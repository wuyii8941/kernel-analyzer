## 3. 阶段 3 的两个问题

**问题 1：AdamW（带历史）的动量来源。** 被测方指出得对：协议要求用同家族干净程序的输出构造 m、v，而哪个程序是干净版本属于盲测信息，这是出题方的协议缺陷。采用被测方的建议：

> m、v 由规格 f 在历史 seed H_s = {20000 + 16s + i, i = 0..15} 的输入上的值构造：先把 f 舍入到 float32（最近舍入）作为该步的梯度，再按 β₁ = 0.9、β₂ = 0.999 做 16 步 EMA，测量步 t = 17 做偏差修正。

同家族所有程序共用同一组 (θ, m, v, t)。这与原设计在统计上等价：干净程序的输出与 RN₃₂(f) 只差末位舍入。封存的更新层预期不受影响。

**问题 2：u 的计算口径。** 接受被测方的口径：optimizer 一步取实数语义，用区间算术对 K（点）与 K_R（区间）各求一步，u = step(K) − step(K_R)，不含 optimizer 自身的 float32 舍入。三种 optimizer 都按此计算：
- SGD：u = −lr·(K − K_R)，精确；
- AdamW（带历史）：m̂、v̂ 的更新与 √v̂ + ε、除法都走区间算术；θ 在 u 中抵消（weight_decay = 0）；
- AdamW（零动量）：m̂ = g，v̂ = g²，更新为 lr·g/(|g| + ε)，同样走区间算术。

参照更新 r = step(K_R) − θ 取区间中点，用于 R2、R3 的方向。
