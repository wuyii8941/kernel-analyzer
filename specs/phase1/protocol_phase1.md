# 第一阶段预先登记协议（v0.4，含 2026-10-07 审阅决定）

## 1 目的与两个要分开回答的问题
本轮回答两个不同的问题，不能混在一起：
1. **独立任务要求能补上 eager 差分的哪些盲区？**（独立规格相对 eager 参照的价值）
2. **在同一份独立规格之上，自动参照 K_R 与数值诊断又额外解决了什么？**（工具相对独立规格的价值）
若 K = K_eager 而 K ≠ f，则 K − K_eager = 0、K − f ≠ 0：这一发现来自独立规格本身，不需要 K_R。所以找到候选与 eager 共有的错误，首先证明的是问题 1；问题 2 要靠 F 组与 FR 组的差别来回答。

## 2 四组方法，同时运行，同输入、同规格、同裁决口径
| 组 | 做什么 | 检验的价值 |
| --- | --- | --- |
| E | K − K_eager | 现成实现之间的比较 |
| F | K − f，不用 K_R | 独立规格本身 |
| P | 性质检查（计数、不变性、规格导数核验） | 不写完整数值答案能解决多少 |
| FR | 同一个 f，加自动 K_R、分解与定位 | 自动参照与诊断的增量 |
每组分别记录：规格书写、接入、运行、归因、验证修改的成本。

## 3 规格的来源与独立性
- 只依据官方文档；URL 与抓取日期在文件开头；没有查看任何实现的源码。
- 歧义按 ambiguities.md：有依据的读法全部评估；一个候选在全部输入上必须符合同一读法；没有依据的变体只作为带标签的错误变体。
- 执行方不得修改规格语义；规格的错误交审计方，改动入库后才生效。v0.2、v0.3 分别按 2026-10-07 的两轮审计修改。
- 规格的支持域（维度、特殊值、数值范围）写在各文件开头；域外输入由规格拒绝或返回未建立，不由执行方代为补答。

## 4 候选
eager CPU float64（用于判断符合哪种读法）；eager CUDA fp32 / bf16；torch.compile（Inductor 生成的 Triton，有 TTIR）；库实现（Liger、Unsloth 的交叉熵等）；锁定版本 2.10 与当前 nightly。

## 5 第一阶段的三个小切片（缩小后的范围）
- **交叉熵**：先做 ignore_index、三种 reduction、以及累加窗口归一化（spec_accumulation.py）；之后再加 class weight 与 label_smoothing 的组合。
- **池化**：先做 avg pool 的尾部窗口、padding 与除数；max pool 的并列、NaN、空采样窗口单独列。
- **index/scatter**：先做 sum、mean、prod 的重复索引、include_self 与零因子；维度与非有限值放后面。
每个条件至少 3 个 seed，输入由 seed 复现。3 个 seed 用于冒烟与复现反例，不用于宣称总体的平均作用。

## 6 裁决口径

**结果分三栏报告，不混入同一个「已确认 bug」计数：**
1. **文档明确条款的违反**：锁定版本文档写明的行为被违反（如 D2 的分母、D4 的 N、−∞ padding、include_self 的参与规则）。
2. **声明解释下的差异**：读法分歧（CE-A1/A2 的 R_B、R_C，POOL-A1 的 R1，NaN 策略，并列路由）。只在主解释下报告差异，不据此宣布上游 bug。
3. **未定义情形的实现约定**：0/0、正数/0、空窗口、过滤后无值等（CE-A3、ACC-A1、POOL-A5 的 NaN 变体）。只记录各实现的约定。
标量口径：主 API 比较使用 kernel 实际接收的标量值；发布值口径作为接口项单列。严格的普通导数评分只在唯一极值处进行；并列处用集合式检查。
1. **区间含零写「未排除相等」**，不写「符合规格」；区间不含零才是该输入上的差异证据。有限样本上无反例不等于函数全域正确。
2. **K − f ≠ 0 不自动等于错误。** 先声明任务允许的数值行为。只有在输入设计成每一步都精确可表示的小规模计数与线性例子上，才要求严格相等；一般浮点执行的 index_add、求和都不是「精确任务」。含初等函数的任务（交叉熵）要把正常舍入排除在外。
3. **τ₆₄ = 10⁻⁹·(1 + |f|) 只是事先声明的筛查门槛**，不是 float64 计算的理论误差上界。float64 候选越过它，先记为「待确认警报」，再凭独立规格与具体反例裁决；低精度候选只记录数值差异，不在本阶段判语义。
4. **F 与 FR 对「实际候选是否违反任务」的最终裁决，使用同一个 K − f 数值契约、同一输入口径与同一异常约定。** FR 额外提供 K_R − f 与 K − K_R 的分解与定位，这些额外目标单独计分，不进入与 F 共用的检出率。有 TTIR 时，K_R 与各读法 f_r 的精确比较（每个读法在该条件的全部元素上区间都含零即「与 r 相容」）属于 FR 的额外目标。
5. **规格本身的「未建立」**：规格求值返回 established=False（中间量超出固定上下文的正规范围）或拒绝输入（SpecInputError）时，该条件计入「规格未建立 / 输入不合法」，不计任何候选的对错。
6. **分类**（每个 算子 × 条件 × 候选）：与规格相容（并记录相容的读法）；偏离规格且与 eager 一致（共有错误）；候选偏离、eager 相容（候选错误）；**候选相容、eager 偏离**（候选修正了 eager，或 eager 的错误只是被关掉的检查遮住了）；两者各偏离各的；读法分歧。
7. **性质检查**：每条性质附前提、变换方式、精确成立的数值条件（v0.3 起写在各 prop_* 的文档字符串里，并在代码中检查形状与前提）。只有在输入设计成每一步都精确可表示时才要求相等；一般浮点执行报告带误差控制的残差。违反精确前提下的性质才记为反例。空窗口、全部忽略这类无定义情形单列。
8. **前后向检查分两种**：J 来自独立规格 f 的导数 → 规格导数核验（有独立判据）；J 来自候选自己声明的计算 → 实现的前后向自一致性（排除不了前后向一起错）。两者分开报告。
9. **计数**：所有结果附分母（算子 × 条件 × 候选）；不支持、报错、超时单列。

## 7 已知问题召回（先做，用于验证流程）
- **B016**：上游 #178871 是 Inductor 融合 scalar broadcast 与 scatter 时丢失原子加法的 mask，复现方式就是比较 eager 与编译结果；eager 正确。因此它是「编译缺陷 + 计数性质」的召回例子，**不是**候选与 eager 共有错误的例子。记录 E、F、P、FR 各自能否发现，不预设 eager 差分必然失败。
- **HF 梯度累加归一化**：问题在累加循环对窗口的归一化（应按有效 token 总数，而不是对各 micro-batch 的均值取平均），不是单个 cross_entropy 算子的错误。用 spec_accumulation.py 作为任务要求；用构造实验先验证三方比较的程序逻辑（两份实现都取均值的均值：token 数 1 与 3、梯度和 −1/2 与 3/2 时，错误实现互相比差为 0，与规格比差为 −1/4），构造实验不冒充旧版本实测；再在旧版本上实测。
- **B014** 的 avg_pool 部分：记录它落在 POOL-A1 的哪种读法上，或属于规格之外的错误。

## 8 零结果的解释
没找到共有错误，只说明所测范围内没有找到。找到共有错误但 F 与 FR 效果相同，说明该例的检出收益来自独立规格，工具的增量要另看自动化或诊断成本。不预先决定哪种结果算成功。
