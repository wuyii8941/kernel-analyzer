# 第二轮：容差研究之前的测量修复（基线 dsl-v2@fb87929，2026-10-12）

本轮任务的中心问题是「常见配置下，容差检查通过时，数值误差是否仍改变了更新、状态或下游结果」（实验在
`1_experiments/tolerance_study/`）。任务书第 6 节要求先保证测量可信、只修直接影响结论的共同机制。本页记录这些修复；
每项先写修复前失败的测试（`2_tool/tests/test_round2_measurement.py`），再修，再在基线工作树上复核失败点
（`evidence/baseline_fb87929_round2_tests.log`），全量测试 1608 通过（`evidence/full_suite.log`）。

| 问题 | 基线上的表现 | 修复 | 组合规则 |
| --- | --- | --- | --- |
| 跨启动沿用绕过已知生产者证据 | 两次启动之间经 `tensor.data` 的原地写入不改变字节和版本号；参照内存照样沿用，范围仍是 call 级 | 生产者追踪按存储记录 ATen 原地写入次数；沿用之后若追踪看到写入，撤回沿用、按外部输入重新求值参照，并报告 `carry_overs_withdrawn_by_trace` | M4 |
| 提高精度时混入不同执行 | 每一级精度都重新执行调用（同一声明下调用次数 57 对 19）；浮点原子、随机或不确定的 K 会混成一条「精度改进曲线」 | 第 1 级保存每个单位的捕获（启动、输出、输入快照、生产者记录、规格、重复启动），更高级只重算参照与统计；捕获超过存储上限时拒绝细化（「预算耗尽」），不重新执行 | P2 |
| 分析默改候选的精度开关 | `check.run` 开头把 `allow_tf32` 设为 False、`float32_matmul_precision` 设为 "highest"：用户按 PyTorch 提示设成 "high" 的候选被「修好」后再测 | 不再设置任何精度开关；报告候选实际运行时的开关（`precision_environment`）与分析自身的干预（`analysis_interventions`） | T2 |
| 额外追踪改变随机流 | 生产者追踪多调用一次被测函数，消耗全局随机数，后续种子的 K 因此改变（调用内随机掩码的例子） | 追踪从被测运行之前的随机状态开始（重现同样的抽取），结束后恢复被测运行留下的随机状态 | T1 |
| 没有数值包围却报告达标 | 只有集合目标、没有完整有限元素的输出，逐级记录里 `resolution_met` 为 True，结局写「每个数值包围都已达标」 | 没有数值包围时 `resolution_met` 为 None；结局写明「没有数值包围，只有集合目标」；数值元素全部达标而另有集合目标时类别为「达标」并注明集合目标宽度 | P2、P3 |

另：测试里用于计数与记录的状态原来放在被 `measure` 以新模块实例加载的调用文件中，测试读到的是另一份对象，调用计数
测试曾在 0 == 0 上空过；改为独立的 `audit_state.py`，并断言计数非零。

这些修复不改变单次启动的求值，也不改变 batch 1 的验收结论（全量测试与 batch 1 的测试全部通过）；`test_batch1_guarantees.py`
中一处期望随「数值元素全部达标且另有集合目标」的类别调整而改为「达标」。
