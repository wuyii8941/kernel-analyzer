这一轮不是单纯增加算子模板：通用合并区域、Gluon、描述符、原子返回集合、部分 NVIDIA/AMD 路径都有实质代码与开发证据。不能继续用旧结构集的“23/28，五个 Welford 未支持”评价当前版本。

## 3. 必须先处理的发现

### F01：64位整数运算的“精确域”实际发生了错误转换

位置：`reference_eval/ttir_eval.py::_cmpi`、`_unsigned`、`_op_atomic_cas`。

`_unsigned(...,64)`返回uint64后，`_cmpi`又转回int64比较。CPU摘录函数测试：

| 运算 | 应得 | 摘录规则所得 | 状态 |
|---|---:|---:|---|
| unsigned `2^63 > 0` | 1 | 0 | ST_OK |
| unsigned `2^64-1 < 1` | 0 | 1 | ST_OK |
| 32位高位unsigned比较对照 | 正确 | 正确 | ST_OK |

CAS还把内存与比较值转换到float64：

- old=`2^53`、compare=`2^53+1`、replacement=7，正确行为是不交换；规则交换成7。
- old=`2^53+1`、compare=0，正确返回old；规则返回`2^53`。
- 小整数匹配/不匹配两个对照正确。

这不是数值容差问题，也不需要竞争才触发。整数比较、索引、路由、锁及集合返回值是数值结果的上游。MLIR unsigned比较明确按最高位的大正数解释，不能按signed int64比较。CAS也必须比较并返回原整数，而非它的float64近似。

修复：整数位模式与解释符号分开；全宽整数比较、除法、逻辑移位、CAS、输出比较不经过有损浮点转换。同步审计 `_int_op` 中divui/remui/ceildivui、shrui、maxui/minui的同类路径，本次未分别执行这些路径。对声明支持宽度做边界参数化测试，不用禁用uint64缩小官方目标。

### F02：scaled dot 丢弃上游区间上端和scale的条件标记

位置：`reference_eval/ttir_eval.py::_scaled_dot`，由`tt.dot_scaled`和`ttng.tc_gen5_mma_scaled`共用。

非FP4输入的`values()`只读取`x.lo`；随后把同一个数组作为idot的上下端。`x.hi`没有传入。scale的`cond`也不参与输出`cond`。

隔离规则探针：1×32输入各元素区间[1,2]，乘32×1全1，scale=1，c=0。合法抽象输入代表的结果包含32与64；当前函数交给dot的是[1,1]而非[1,2]。使用独立精确小例子后端得到[32,32]、ST_OK。另一探针只有scale来自条件边界，输出却不带conditional标记。

这是规则的组合义务反例，不是已重跑设备kernel后发现114,688个历史元素错误。历史输入主要是点值，因而可能完全没有触发这一问题；两层共用同一解码器也可能一同遗漏。

修复：对区间输入作有向缩放与区间收缩，或在确有明确点值前提时机械拒绝非点输入，并将这部分记为待实现；scale的状态、条件、格式与可观察依赖一起传递。不能悄悄取一个端点，再标为完整参照。

### F03：CAS的两个串行化一致，不能升级为所有串行化的保证

位置：`_cas_reverse_order`、`evaluate`、W1的`tt.atomic_cas/*`。

此处报告已经诚实写了“声明前提，不是证明”。但该前提由工具自动加入，前后两次一致的元素仍保留ST_OK且cond=False，而不是获得每个待测程序的顺序无关证书。

精确反例：三个由正确锁保护的临界更新，x初始为0：

- program0：x←x+1；
- program1：x←2x；
- program2：x←x+1。

程序顺序012和逆序210都得到3；六个串行化的结果集合为{2,3,4}。隔离运行生产“比较两序”函数，它保留3为已建立，并仅在reasons中记录assumed。

本次没有运行真实GPU锁kernel，因此不声称已在设备上观测到所有六种顺序。数学反例已经足以否定“两个顺序一样就足够”的一般前提。独立审阅方不能将这个假命题签成真命题。

修复路线：对可证明交换的临界更新提供程序级代数/协议证书；否则构造完整允许结果关系或可靠上包围，或明确选择一个特定顺序目标并限定统计解释。旧的两序测试保留为反例发现探针。对于未证明的前提，报告应另列proof_status，不能混入已认证complete比例。

scan的两个括号结果核对也同理：官方结合性前提可以被明确声明，但有限输入测试不是其一般证明。不要因无法证明结合性便永久缩小官方DSL，可增加可信有序树或集合语义。

### F04：调用级来源完整性判据仍沿用被审计反例否定的方法

位置：`check.py::torch_intermediates`；`measure.py::run_level`。

当前代码仍然把“每个元素位模式曾在某个输入里出现”当成复制，将全零外部缓冲直接视为常量。`measure`通过标签尾部`[copy of inputs]`决定是否升级调用级完整率。

摘录函数 + CPU真实张量 + 模拟捕获记录再次复现：

```
x = float32([1,2,3])
z = (x[:1] + 2^-25).repeat(4)  # 浮点结果全是1，实数目标不是复制
```

来源函数将z标为`[copy of inputs]`，当前measure分类公式把它当调用级。诚实复制与真正改变数值的两个对照也随包提供。

这不是要求本轮马上覆盖整个FX图。短期可继续提供kernel级结果；没有生产者、存储生命周期与元素映射证据时不升级调用级。数值相等不能代替来源证明。

### F05：Gluon解释器进展还没有完整进入统一产品入口

位置：`check.py::run`，`capture.py::_before`相关捕获构造，`measure.py::run_level`。

采集器只保留实际存在的asm键；`check.run`在调用通用求值器前仍直接读取每次launch的`asm["ttir"]`做覆盖、原子检测。只有TTGIR的Gluon记录会在这里KeyError，虽然底层解释器/官方测试插件已经能够解释它。

本次CPU测试只复现了这个查键分支，没有GPU端到端重跑。因此请加一个真实Gluon最小kernel通过`measure.run`的回归，不用插件绕过。

修复：统一的前端/分析层选择对象携带ir_kind、source_profile及语义策略；覆盖检查、原子识别、求值、缓存、报告使用同一选择。不要简单把TTGIR改名成TTIR，掩盖解释范围。

## 4. 对官方范围和所选R06/R07的判断

官方范围仍然是目标，不因为缺硬件或当前数据没出现而删除。

- R06排序/选择要求值、索引和payload分开观察，并执行规定的tie-break；当前有NaN argmax值建立而索引未建立的记录，以及非交换combine的lane选择缺口。这是部分能力，不是整个算子完成。
- R07整数分布/分段已经有histogram越界契约核对、gather逐lane与重复项等进展；但F01说明整数“精确”基本路径还有问题。增量14的返回整数集合会进一步把这些值送进地址、分支和输出，必须保持整数精度和关系依赖。
- NVIDIA的two_ctas/multicast、warp specialization完整产品路径、复杂asm访存仍有欠账。AMD的TDM、部分mbarrier/异步、masked load/store、scaled_downcast、RDNA及AMD Gluon也没有由本轮覆盖。
- 不能用当前观察到的129/129或5,949/5,952推出官方所有类型、属性、区域及内存效应完成。W0应保持官方目标与已验证子签名两张账，不后退到旧profile分母。

## 5. 统计层的实际状态

这轮的有界路线有进展，不应继续引用旧审计说“完全未接入”：

`measure.magnitude_bound → check.run → assess_units/apply_direction_rules → sensitivity_fields → bounded_route`

已经存在。每元素总体界乘方向L1范数的保守上界，进入逐规则Hoeffding结果；默认近似检测与有界结果分开。原来的error_budget接口和`expanded_declaration.bounded_route`文字仍写“仅记录、未使用”，需要同步为真实行为。

仍需说明：

1. M是调用者声明的总体界，不是已自动证明；basis字符串不是证书。无M时不能宣称任意分布保证。
2. 有界结果逐规则用alpha，现有Holm汇总处理的是近似p值；不能把逐规则有界报警自动合成全族5%保证。若宣称族级结果，需要预声明alpha分配或对应有效p值。
3. sensitivity.py的“guaranteed_detectable_effect”包含本次观察的平均区间宽度，不能读成数据取得之前已经确定的功效保证。用事前宽度上界，或改成带条件的灵敏度说明。
4. 底层规则的包围/来源不可靠时，后面的统计再保守也补救不了。
5. 八类校准是开发校准，不是所有分布、所有维度、所有新结构的保证。默认检验只覆盖声明的投影，未确认不排除正交方向。

## 7. 审计C节的处理决定

- κ=conditional：用于明确钉住值/路径或条件边界；不确定分支若做了可靠全包围，仍可complete。未证实的顺序/结合性另列assumption_status。不得把assumed静默升级为verified。
- 编译期常量：差异、来源核验、契约是否允许分别写；没有逐项契约不统一放行，机制推断不等于已重算归因。
- SPEC-ISSUE-1：按目标版本官方SGD伪代码修改规格并保留旧版本记录；maximize先反号，再衰减及动量，最后统一减更新。其他文档歧义只阻塞该条语义裁决，不阻塞模式A。
- 不要求421个独立测试文件。要求每条声称支持的属性/类型/区域/效果前提有真正触发的正例、边界及违反/非适用测试，另补组合相互作用。当前反例说明“三类测试都有”仍不足以签可靠性。
- scan：来源契约要求结合性，不等于工具两次括号核对已经证明；提供可核验证据、有序模型或集合模型。
