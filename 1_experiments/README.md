## 当前首要实验

下一轮不再以扩充 specification 数量为目标，而是闭合一个能说明工具价值的真实案例。两条路线至少完成一条：

| 路线 | 必须建立的事实 |
| --- | --- |
| bias 传递 | 发布实现中自然存在的局部 bias，在固定输入与同一下游路径上传到后续激活、梯度、参数更新或推理输出；对局部原因做实际修正后，下游差异按事前声明的方向或范围改变。 |
| 主流算子真实问题 | 主流框架或常用算子的发布版本，在正常参数范围内与完整任务参照不一致；工具给出对应源码区域和机制，真实修复后差异消失，其他输出和状态保持正确。 |

这里的“传递”用成对干预来建立，不用相关性代替。设局部算子实际输出为 `K_o`、任务参照为 `f_o`、固定的后续计算和其他输入为 `H(·, z)`。
在相同 `z` 上比较 `H(K_o, z)` 与 `H(f_o, z)`，然后用重新编译的局部修复再做一次。只有局部差异和下游差异在事前登记的成对单元上同时成立，且修复会按预期减小两者，
才声称该调用和输入分布上的 bias 传递建立。局部导数或切向传播可以提前预测方向，但不单独构成传递证据。

首选开发案例是 PyTorch Inductor `avg_pool2d(..., ceil_mode=True)` 的反向。已有证据完整建立其公开任务、实际调用绑定和边界窗口的梯度差异；
详见 [Inductor 二维平均池化绑定](../5_specification/evidence/inductor_avg_pool2d_binding.md)。这份旧证据只用于判定定位结果是否命中，不作为定位器的输入。下一轮需要补齐：

1. 冻结 PyTorch 版本、公开调用、形状与参数，保留未修复的基线。
2. 定位器只根据调用、编译产物、输入/输出/状态和参照差异，给出受影响输出、源码区域、错误机制与修复候选。
3. 实际修改源码并重新编译，在同一输入库上比较修复前后的 `K−G`、`G−f` 和 `K−f`；不用“把中间节点设为精确”代替真实修复。
4. 用另一组形状和输入确认修复没有只记住开发用例；完整检查前向、梯度和读写状态。

已有的纯 bf16 AdamW 实验证明了低精度丢弃更新可以改变训练结果，但它没有闭合“陌生 Triton 调用→自动定位→实际修复→下游作用”这条新主线，因此只作为重要性证据，不代替新的旗舰案例。
