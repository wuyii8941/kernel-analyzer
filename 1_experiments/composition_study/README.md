# 组合研究：Triton 操作组合中 bias 的成因

日期：2026-10-13。对象：Triton 3.6.0（`ka_main`），sm_86（RTX A6000）。协议：[protocol.md](protocol.md)。
输入：用户提供的 three_plans_v3 包（`inputs/three_plans_v3_20261013.tar.gz`，sha256 `4e703057…48a0fa`）。

## 结论

> 本节的数字以 `results/` 为准。

1. **「测全」能成立的形式是结构归纳加单程序证书，不是测全所有程序。** 程序有无穷多个；能测全的是生成它们的有限部件：
   原语（每个操作实例在设备上怎么算）、组合规则（每种组合形式怎么由原语拼出来，包括 TTIR 不规定、由下降决定的部分）。
   偏差机制则是一个恒等式：按位点逐个替换的增量之和就是总偏差，每一项的期望只有位点均值、残差与系数的协方差、二阶项、
   离散翻转四种来源，外加声明与任务规格之间的语义差。对任一具体 kernel，这一分解是否完整可以直接核验：
   用原语加组合规则仿真，与设备输出逐位比较；逐位相同就说明没有遗漏，不同或仿真不了的部分就是缺口，必须报告。
2. **原语表测全了。** 包的 705 个操作实例加上前端实际产生的 313 个 libdevice 调用、29 个常量字面量、4 个标量 index_cast，
   共 986 个，每个都有设备结果或明确的不可编译原因。其中 36 个 TTIR 操作名在 3.6.0 的 NVIDIA 后端根本不合法化
   （`math.tanh`、`math.erfc`、`math.powf` 等），前端从不产生它们，真实的数值原语是 libdevice 调用。
   包把 libdevice 整体算作一个名字 `tt.extern_elementwise`，这是 F1 最大的缺口。
3. **组合规则：在全组合扫描中，工具仿真器原有的规则（收缩、近似指令与加法合并、按布局的归约次序、ieee dot）成立；
   扫描找出的缺口已全部在工具里修复，每处都先写修复前失败的测试。**
   - 补上三条此前不可仿真的组合规则：张量核 dot、扫描次序、原子折叠。张量核 dot 和扫描次序在留出数据上逐位复现；
     原子折叠给出的是可能结果的集合，不是确定的位。
   - 其余缺口是仿真器自身的错误或遗漏：FTZ、round-down 下零的符号、f64 的有向舍入、归约溢出、libdevice 乘法的融合、
     reshape 之后的乘加收缩、内存捕获缺 SASS 证据、无声明语义的 libdevice 调用、单操作的归约与扫描区域。
   - 最终扫描：可编译的 769 个原语 × 23 种形式，共 17,687 个单元。
     - 13,665 个逐位相同；
     - 不一致 0 个，覆盖 10,969,457 个仿真元素；
     - 未建立 235 个：其中 208 个是整数除法 / 移位组合，未定义值不仿真；25 个是原子，只有结果集合；2 个是拆分精度或
       fp8 dot；
     - 编译选项的两两覆盖扫描 2,065 个单元，2,039 个逐位相同，1 个含 poison 的转换链未解决。
4. **张量核 dot 的组合规则（sm_86）是全截断的。** 参数在 221,184 个元素上逐位复现，覆盖 tf32 / bf16 / f16、
   K = 256–4864、三组分块。
   - tf32 输入截断到 11 位，不是舍入；bf16 / f16 输入原样使用。
   - 乘积精确。
   - 每 4 个（tf32）或 8 个（bf16 / f16）乘积连同累加器一起，对齐到最大的「操作数指数之和」，保留 1 个额外位后截断，
     再截断到 24 位。

   推论是 dot 有系统性的收缩：
   - tf32 每个被截断的操作数约贡献 −3.5×10⁻⁴；
   - bf16 / f16 来自累加，K = 4864 时约 −6×10⁻⁶。
5. **第二轮 C 组的 Triton TF32 收缩现在有了完整的归因。** 在第二轮捕获的真实 Qwen 激活上，规则逐位复现设备输出
   （48 个单位，5,505,024 个元素全部相同）。逐个位点把截断换成就近：
   - 激活操作数的截断占 79%–99.9%；
   - 权重为 0：权重来自 bf16 检查点，tf32 截断不改变它；
   - 张量核内部累加的截断，K = 896 时约 0.7%，K = 4864 时约 4–5%。

   由激活尾数预测 −3.52×10⁻⁴，实测 −3.52×10⁻⁴ 至 −4.30×10⁻⁴（详见第 5 节）。
6. **偏差机制。** 每类机制都在设备上用最小组合检验过，预测在运行前写定（E2 的循环设计看过第一次结果后改过一次，
   见偏离 D-2）：
   - **B1 位点均值（tf32 截断）**：成立；
   - **B1 的状态条件形式**：同一个 bf16 加法，放在循环里停滞在 256（−92%），放在归约树或扫描里只有 ±0.3%。
     偏差大小由组合形式决定，不由原语决定；
   - **B2 协方差（包的 D1 / D2 构造）**：成立；
   - **B4 阈值翻转**：成立。

   两个预测不成立，记录如实：
   - **只算 B3**：只用二阶项预测量化值的平方均值，fp8 e5m2 下符号反了。原因是就近舍入在每个二进位边界处的舍入区间
     不对称，使残差与系数（2x）负相关，B2 项（−0.60%）压过了 B3 项（+0.28%）。按 B2 + B3 两项预测则完全吻合；
   - **「最大值偏大」**：预测取最大值会挑中残差大的元素，结果反而偏小，原因同上。

   就近舍入并不是「局部无偏」：对光滑分布的数据，粗格式下它对幅度有系统性的收缩。
7. **原语表直接发现了一个错误。** `x % y`（`arith.remf`，f32 / f64 / f16 / bf16）在 sm_86 上被下降为 `x − trunc(x/y)·y`，
   商超过 2²⁴ 时结果完全错误：
   - `1e20 % 3` 得 2.2e12，应为 2；
   - `1e30 % 1e-3` 得 −2.7e22，应为 1.7e-4。

   libdevice 的 `fmodf` 是精确的（只有 FTZ）。这是上游已知的问题（triton issue #11986，修复 PR 未合并），登记为
   [B024](../../4_bugs_cases/bugs/B024_triton_float_mod_large_quotient.md)。原语表独立地重新发现了它。
8. **库里的真实 kernel（Liger-Kernel 0.6.2、FlagGems 5.0.2，共 118 个不同的 kernel）。**
   - 100 个逐位复现；仿真的 70,514,449 个元素中只有 835 个不一致（0.0012%）；
   - 14 个未建立：用原子累加的反向与直方图（6 个）、FlagGems 的 Welford 方差合并（8 个）；
   - 4 个有不一致：
     - Liger sparsemax 反向：同一源代码行上的 div.full 与减法，SASS 证据分不开，默认按收缩处理，而设备没有收缩；
     - FlagGems sort 的 sweep：原因未查明；
   - 没有任何操作落在原语表之外（包的 K1 失败码为 0）。

## 1 体系：可以成立的说法

### 1.1 三层与一个恒等式

| 层 | 内容 | 有限吗 | 在这里怎么测 |
|---|---|---|---|
| 原语 P | 每个操作实例（操作名 × 属性 × 类型）与每个 libdevice 函数 × 签名在设备上的执行 | 是：986 个（Triton 3.6.0） | `catalog.py`：每个实例在 7 种分布与特殊值上对精确值 |
| 组合规则 C | 23 种组合形式（直线、共享、归约、扫描、区域、select、分支、循环、屏蔽、下标、存储、跨启动、原子、dot）各自由原语拼出的方式，含下降决定的部分（收缩、近似指令合并、布局次序、张量核累加、FTZ、编译选项） | 是：形式与下降模式都有限 | `cells.py`：原语 × 形式 × 选项在设备上运行，由组合规则（工具仿真器）逐位预测 |
| 偏差机制 M | 位点残差怎样变成输出偏差 | 恒等式，不需要枚举 | `mechanisms.py`：每类在最小组合里预测并检验 |

偏差恒等式：设 kernel 有舍入位点 s₁ … sₙ，从全部精确开始逐个换成设备行为，各步增量 Δₛ 之和恰为 K − G。一阶近似
Δₛ ≈ cₛρₛ（cₛ 是输出对该位点值的导数，ρₛ 是该位点的局部残差），于是

    E[K − G] = Σ E[cₛ]E[ρₛ]  +  Σ Cov(cₛ, ρₛ)  +  二阶及以上项  +  离散判定翻转的跳变
               (B1 位点均值)     (B2 协方差)      (B3 曲率×方差)     (B4)

加上声明程序 G 与任务规格 f 之间的差（B5：常数舍入、存储类型、算法选择），这是全部来源。它是数学恒等式（泰勒展开加分段），
所以「成因分类测全了」不是经验命题；经验命题在于：P 中每个原语的 ρ 是否测对了，C 中每条组合规则是否对设备成立。

### 1.2 能说什么，不能说什么

能说：
- 对 Triton 3.6.0 / sm_86 / 记录的编译选项，原语表覆盖语言中全部可编译的数值原语（不可编译的逐个给出原因）；
- 组合规则对扫描过的全部「原语 × 形式」单元逐位成立，未覆盖的形式逐个列出；
- 对任一具体 kernel，可以由仿真与设备的逐位比较判断分解是否完整（逐位相同 = 偏差全部由已列出的位点与规则产生，
  并可用逐位点替换做精确归因）；不完整时，工具报告是哪个节点、为什么。

不能说：
- 不能说每个程序在每种数据上的偏差大小已经知道。偏差依赖数据，测的是机制与规则，数据分布只是样本；
- 不能说结论适用于别的 Triton 版本、别的架构。编译选项 `enable_reflect_ftz`、`enable_fp_fusion`、默认 dot 精度
  都会改变原语。本研究在选项扫描中按两两覆盖测了这些因子（3.2 节）；
- 语义层 B5 不能由语言枚举，它依赖任务规格。能枚举的是声明中的舍入点：常量、truncf / fp_to_fp、存储类型；
- 原子折叠的次序不确定：规则只给出可能结果的集合（每个观测都落在其中），给不出确定的位。

## 2 原语表（RQ1，`results/catalog.json`、`results/catalog_summary.json`）

| 来源 | 精确 | 正确舍入 | 正确舍入（特殊值不同） | 忠实（< 1 ulp） | 近似 | dot | 其他 | 不可编译 |
|---|---:|---:|---:|---:|---:|---:|---|---:|
| F1（包的 705 个实例） | 305 | 89 | 23 | 8 | 25 | 7 | 9 个常量由字面量模板覆盖；fp4 dot_scaled 只编译 | 173 |
| libdevice（313） | 71 + 7（仅次正规输入冲零） | 73 | 6 | 8 | 148 | — | — | 0 |
| 字面量（29） | 全部等于十进制值的就近舍入 | | | | | | | |
| index_cast（4） | 4 | | | | | | | |

不可编译的 173 个实例，原因分布：
- 152 个不被 NVIDIA 后端合法化，涉及 36 个操作名；
- 8 个是 fp8 e4m3（nv），需要 sm_89；
- 5 个是 fp8 的 rtz 舍入，后端不支持；
- 6 个 mx 缩放操作无法构造（类型不被 tt 操作接受）；
- 2 个是 f16 / bf16 的 divf，LLVM 位宽不支持。

要点：
- 83 个原语会把次正规数冲成零；
- 近似 / 忠实原语中有 112 个，在光滑分布上的平均有符号误差显著不为零（B1 位点，`results/catalog_summary.json`
  的 `systematic_mean_sites`）。例如 f32 的 `math.sqrt`（`sqrt.approx.ftz`）在四种分布上都偏小约 0.13–0.15 ulp，
  `math.rsqrt` 偏小约 0.07 ulp；
- 另有 57 个正确舍入的原语，平均误差的方向由数据结构决定（例如小整数、近平局），这不是原语本身的偏差。
- 36 个注册了的 TTIR 操作名不被 NVIDIA 后端合法化，6 个 mx 缩放操作无法在合法 kernel 中构造
  （`f8E8M0FNU` / `f4E2M1FN` 不被 tt 操作接受）；fp8 e4m3（nv）需要 sm_89；
- 默认 `enable_reflect_ftz=True` 时，经 libdevice 下降的 f32 运算冲零：floor、ceil、sqrt、rsqrt、exp2，以及全部
  带舍入后缀的 libdevice 运算；
- 近似原语的平均有符号误差在光滑分布上显著不为零（B1 位点），例如 f32 `math.exp`（mul + ex2.approx）在 N(0,1) 上
  为 −0.098 ± 0.012 ulp，在正值上为 +0.097 ± 0.011 ulp；
- 十进制字面量一律按就近舍入成为声明值，例如 0.9999 在 f32 中为 0.99989998，即 B012 的根源；
- `arith.remf` 的错误见结论 7。

## 3 组合规则（RQ2、RQ3）

### 3.1 全量扫描：原语 × 23 种形式（默认选项，`results/cells_summary.json`、`results/cells_default.jsonl.gz`）

可编译的 769 个原语与 23 种形式全部组合，共 17,687 个单元。每个单元：
- 6 个程序，每个程序一种分布；
- 在设备上运行两次检验可重复；
- 由工具的仿真器（全部下降选择冻结）逐元素预测。

| 形式 | 逐位相同 | 不适用 | 未建立 | 编译器拒绝 |
|---|---:|---:|---:|---:|
| C1 直线（深度 1 / 2 / 4） | 2,289 | 18 | | |
| C2 共享（复用 2 / 3） | 1,526 | 12 | | |
| C3 归约 | 350 | 1,084 | 104 | |
| C4 扫描 | 350 | 1,084 | 104 | |
| C5 map_elementwise 区域 | 756 | 6 | | 7 |
| C6 select / C7 scf.if | 763 / 763 | 6 / 6 | | |
| C8 循环（静态 / 数据决定次数） | 1,526 | 12 | | |
| C9 while | 763 | 6 | | |
| C10 屏蔽读写 | 1,523 | 12 | | 3 |
| C11 计算下标 | 1,526 | 12 | | |
| C12 程序内写后读 / C13 跨启动 | 763 / 763 | 6 / 6 | | |
| C14 原子折叠 | 0 | 744 | 25 | |
| C15 dot | 4 | 763 | 2 | |
| 合计 | **13,665** | 3,777 | 235 | 10 |

逐元素看：
- 写出 11,282,094 个，仿真 10,969,457 个，其中 10,846,940 个逐位相同，122,517 个两边都是 NaN；
- **不一致 0 个**；
- 未仿真 312,637 个。

未建立的 235 个单元：
- 208 个是整数除法、取余、移位作为归约或扫描的组合：除零、移位超宽是未定义的，分别编译时 LLVM 可能不同地折叠，
  按规则不仿真；
- 25 个是原子折叠：规则只给出集合，见下；
- 2 个是 dot：tf32x3 与 fp8 e5m2。

编译器拒绝的 10 个：
- 7 个是 fp8 转换在 map_elementwise 区域内，后端不支持标量 fp8 转换；
- 3 个是 fp8 的屏蔽读取，模板中的 fp8 常量无法解析，属模板限制。

不适用是包的规则：归约与扫描的组合必须是同类型的二元操作，原子要求可原子的更新，dot 形式要求 dot 实例。

### 3.2 编译选项（`results/cells_options_summary.json`、`results/cells_options.jsonl.gz`）

扫描的因子是组合形式、原语代表（按原语表的类别 × 族 × 结果类型取 118 个）和四个选项，四个选项各取：
- `enable_fp_fusion` 真 / 假；
- `num_warps` 1 / 4 / 8；
- `enable_reflect_ftz` 真 / 假；
- BLOCK 32 / 128 / 512。

覆盖方式是两两覆盖：任何两个因子的每对取值都至少出现一次，共 2,065 个单元。结果：
- 逐位相同 2,039；编译器拒绝 6（同上的 fp8）；未建立 19（同上的整数组合、原子；另 4 个是非交换组合在单个 warp 内
  lane 结果不一致）。
- 不一致 1 个单元的 66 个元素：f64 → u8 的 fptoui 链，nw 8、BLOCK 512。链中 `sitofp`（有符号）读回无符号结果，
  后一级 `fptoui` 的输入为负，声明值是 poison，LLVM 可以任意折叠。仿真器给出的元素与设备不同，未能解释，记为未解决。

### 3.3 协议假设的结果

| 假设 | 结果 | 依据 |
|---|---|---|
| H2.1：仿真器能仿真的单元全部逐位相同 | 成立（对最终仿真器） | 最终扫描不一致 0 个元素。修复前的扫描找到 3.4 节的缺口，按协议逐个找原因，判据未改 |
| H2.2：不可仿真的只有扫描、原子、张量核 dot | 不成立 | 扫描开始时不可仿真的还包括：无声明语义的 libdevice 调用、一般组合区域、f64 运算等。扩展之后剩下的是：整数除法 / 移位组合、原子、拆分精度与 fp8 dot、反向 / 多维扫描 |
| H2.3：同一输入上逐位可重复，原子浮点折叠除外 | 成立 | 13,135 个做了重复运行的单元中，只有两个原子 fadd 单元（f16、bf16）不可重复 |

### 3.4 新建立的规则

| 形式 | 规则 | 证据 |
|---|---|---|
| C15 张量核 dot | tf32 操作数截断到 11 位；乘积精确；每 G（tf32 4、bf16/f16 8）个乘积与累加器对齐到最大的操作数指数和，保留 1 个额外位截断，和再截断到 24 位；f16 次正规操作数以指数 −14 进入对齐 | `mma_probe.py`（`results/mma_rules.json`）：构造输入上 115 个候选模型中唯一 / 首选者，留出 512 行全部吻合；乘积指数为「操作数指数和」而非乘积自身指数（512 对 480–502）；`dot_check.py`（`results/dot_check.json`）：27 组配置 221,184 个元素逐位相同 |
| C4 扫描 | 线程内顺序；32 个 lane 上 Hillis-Steele；warp 总和经共享内存从左到右折叠 | `scan_rule.py`（`results/scan_rule.json`）：90 组配置（f32/f16/bf16 × add/mul × N 128–4096 × 1–8 warp）131,328 个元素逐位相同；顺序累加只吻合 5.6% |
| C14 原子折叠 | 结果是各次更新按某个次序、在元素类型中逐次就近舍入的折叠结果之一；整数折叠与次序无关 | `atomic_rule.py`（`results/atomic_rule.json`）：f32 / f16 / bf16 各 4 组、每组 400 次重复，4,800 个观测全部落在 720 个次序的结果集合内；i32 100 次全部等于精确和 |

### 3.5 扫描发现、已在工具中修复的仿真器缺口

每处先写修复前失败的测试（`2_tool/tests/test_reference_eval_emulate.py`），完整工具测试 1640 通过：

| 缺口 | 现象 | 修复 |
|---|---|---|
| 归约溢出 | 部分和溢出为 inf（或 inf − inf = NaN）时，仿真器给出超出格式范围的有限值并标为已仿真 | 溢出的部分和标为未决定，不再声称 |
| FTZ | `enable_reflect_ftz=True` 时，libdevice 下降的 floor / ceil 与带舍入后缀的 f32 运算冲零（`cvt.rmi.ftz`、`add.rn.ftz`） | 按编译选项对这些运算的操作数与结果冲零 |
| round-down 的零 | 舍入方向向下时精确零和为 −0（IEEE 754） | 零符号规则按舍入方向 |
| f64 有向舍入 | float64 区间无法判定 binary64 的舍入：就近时未决定，有向时给出错误的邻值 | f64 IEEE 运算用 MPFR（53 位、次正规）精确求值 |
| libdevice 乘法融合 | libdevice 函数（内联 LLVM IR）末尾的乘法被每个使用它的加法融合，不论使用次数；有 NaN 的 lane 曾让整个程序退回普通加法 | 对 libdevice 生产者不要求单次使用；NaN / inf 作为已知值进入设备组合 |
| reshape 后的收缩 | `tl.reshape(x*x, can_reorder=True)` 之后的求和仍被收缩为 fma（Liger group norm） | 穿过同形状的 reshape / 布局转换寻找乘法 |
| 内存捕获缺 SASS | 只有存盘的捕获才读 SASS，内存中的捕获无法判断 ptxas 是否收缩（Liger sparsemax） | 从保留的 cubin 反汇编 |
| 无声明语义的 libdevice | 152 个 libdevice 原语因缺少声明语义而中止 | 仿真不需要声明语义：由设备在仿真的操作数上求值 |
| 单操作的归约 / 扫描区域 | 乘积归约、非结合或整数的扫描区域不可仿真 | 按布局次序（归约）/ 扫描次序，由设备求组合操作 |
| 张量核 dot、扫描 | 不可仿真 | 新规则（上表） |
| f32 有向舍入的零 | 输出区间的外向舍入把精确零变成最小次正规数，FTZ 后为 −0 | 带舍入后缀的 f32 运算也用 MPFR 精确求值 |
| 整数结果 | 不可仿真的整数值写入整数缓冲区时报错；i64 的设备求值经 float64 丢位 | 整数类型的未建立值；设备结果按 int64 取回 |
| 整数到浮点 | 超过 2^53 的整数留下区间，后续 f64 运算取错邻值 | MPFR 一次就近舍入 |
| fptoui | 到 u64 时 [2^63, 2^64) 溢出；到 u8 / u16 / u32 时未按有符号表示保存 | 经 uint64 与按宽度回绕（基础求值器） |
| fp8 e5m2 与 clampf | sm_86 的软件 e5m2 转换平局远离零（声明为就近偶）；clampf 的 min / max 零符号 | 由设备求值 |
| 并行的 oracle 缓存 | 多进程同时写同一个 TTIR 文件，读到不完整的内容 | 先写临时文件再改名 |

## 4 偏差机制（RQ4，`results/mechanisms.json`）

| 实验 | 机制 | 预测 | 实测（95% 区间） | 结果 |
|---|---|---|---|---|
| E1 tf32 dot（K = 256） | B1 位点均值：操作数截断 | E[τ_A] + E[τ_B] = −7.040×10⁻⁴ | −7.055×10⁻⁴（−7.08 至 −7.03） | 成立 |
| E2 bf16 累加，C8 循环 4096 步 | B1 状态条件：[128,256) 上增量全进为 1，[256,512) 上全被吞掉 | 每个 lane 恰好停在 256 | 128/128 个 lane 为 256，相对误差 −91.7% | 成立 |
| E2 同一累加，C3 归约树 / C4 扫描 | 部分和量级相近 | 偏差远小于循环 | +8.4×10⁻⁵ / +8.5×10⁻⁵（±0.3%） | 成立 |
| E3 包的 D1 / D2 | B2 协方差 | ±E\|ρ\| = ±1.37×10⁻⁸ / −1.35×10⁻⁸ | +1.38×10⁻⁸ / −1.35×10⁻⁸ | 成立 |
| E4 量化值的平方均值，bf16 | B3 | 只含 B3：+2.8×10⁻⁶ | −3.4×10⁻⁵（−8.4×10⁻⁵ 至 1.6×10⁻⁵） | 无法判断 |
| E4 同上，fp8 e5m2 | B3（只含 B3） | +0.28% | −0.32%（−0.46% 至 −0.19%） | 不成立：符号反 |
| E4 同上，fp8 e5m2 | B2 + B3（精确残差） | −0.32%：B2 项 −0.60%，B3 项 +0.28% | 同上 | 成立 |
| E5 bf16 舍入后的阈值 x > 1 | B4 翻转 | −Φ(2⁻⁸/0.05) + ½ = −3.11% | −3.07%（−3.19 至 −2.95） | 成立 |
| E5 e5m2 舍入后的组内最大值（两种尺度） | B4 选择效应 | 偏大 | −0.059 / −0.48%（均显著为负） | 不成立 |

E4 与 E5 的不成立有同一个原因：就近舍入在二进位边界的舍入区间不对称。例如 e5m2 中 2 的区间是 [1.875, 2.25)，
下侧 0.125、上侧 0.25，刚过 2 的值被大量舍向 2。所以对光滑分布的数据，残差的条件均值随幅度变化，在边界附近为负。
粗格式下它是一阶项（B2：残差与系数 2x 负相关），量级超过二阶项。见数值分解：
- e5m2：刚过二进位的数（尾数分数 < 1/8）平均残差为 −5.7%；
- bf16：为 −5.4×10⁻⁶。

「就近舍入局部无偏，所以只剩方差项」的直觉在粗格式下是错的。

## 5 陌生 kernel 的归因：第二轮 C 组的 TF32 收缩（RQ5，`results/tf32_attribution.json`）

输入是第二轮捕获的 Qwen2.5-0.5B 真实激活（128 个 token × K）与真实权重，kernel 是第二轮用的 Triton 教程矩阵乘
（BK = 32，默认 tf32）。
- 张量核规则在 48 个单位、5,505,024 个元素上逐位复现设备输出；
- 权重全部是 tf32 精确的（来自 bf16 检查点）。

对齐 ⟨e, r⟩ / ⟨r, r⟩，每层 8 个单位的平均：

| 层 | 设备 | 由激活 τ 预测 | 激活截断 | 权重截断 | 累加截断 | 全部换成就近后剩余 | 激活截断的份额 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2 q_proj（K = 896） | −3.519e-4 | −3.520e-4 | −3.500e-4 | 0 | −2.6e-6 | +6.5e-7 | 99.5% |
| 12 q_proj | −3.588e-4 | −3.517e-4 | −3.567e-4 | 0 | −2.6e-6 | +4.4e-7 | 99.4% |
| 22 q_proj | −3.550e-4 | −3.520e-4 | −3.547e-4 | 0 | −2.4e-6 | +2.1e-6 | 99.9% |
| 2 down_proj（K = 4864） | −4.299e-4 | −3.521e-4 | −3.699e-4 | 0 | −2.1e-5 | −3.9e-5 | 79.1% |
| 12 down_proj | −3.653e-4 | −3.520e-4 | −3.525e-4 | 0 | −1.3e-5 | +1.9e-7 | 96.5% |
| 22 down_proj | −3.657e-4 | −3.520e-4 | −3.512e-4 | 0 | −1.4e-5 | −4.6e-7 | 96.0% |

逐位点的替换是在规则上做的（规则逐位复现设备，所以替换的结果就是「只改这一处的 kernel」的输出）。

读法：
- **激活截断是主体。** 第二轮看到的约 −3.5×10⁻⁴，就是一次截断的期望 −½·2⁻¹⁰·E[2^e/|x|]，激活的尾数接近对数均匀分布。
- **权重为 0。** 权重截断不起作用，因为权重来自 bf16 检查点，在 tf32 中精确。
- **cuBLAS TF32 的收缩小两个数量级。** 这与它对操作数做就近转换一致；cuBLAS 是黑箱，这一点只作推断，未单独核验。
- **K = 4864 时累加截断约占 4–5%。**
- **第 2 层 down_proj 是例外。** 它的激活有大的离群值，全部换成就近后仍有 −3.9×10⁻⁵ 的剩余，来自第 4 节说的
  二进位边界条件偏差。

第二轮只能说「收缩存在」，现在可以说清它从哪里来，以及改哪里会消失：把激活转换改成就近（cvt.rna），
或者在 kernel 里用 tf32x3。

## 6 库里的 kernel（RQ5，`results/corpus.json`）

样本：
- Liger-Kernel 0.6.2 的 13 个操作，f32 与 bf16，前向与反向；
- FlagGems 5.0.2 的 50 个 torch 操作，f32 / f16 / bf16，经 `flag_gems.use_gems`。

每个 kernel 名取前两次启动，按 TTIR 去重，共 118 个不同的 kernel（Liger 44、FlagGems 74）。处理方式：
- 拆成原语与形式；
- 由组合规则逐位仿真，下降选择全部冻结。

| 结果 | Liger | FlagGems | 说明 |
|---|---:|---:|---|
| 逐位相同 | 39 | 61 | |
| 未建立 | 4 | 10 | 原子累加（Liger layer_norm / group_norm 反向；FlagGems nll_loss、sort 直方图）；FlagGems `var` 的 Welford 合并区域（多操作的组合） |
| 有不一致 | 1 | 3 | 见下 |
| 调用失败（不计入） | — | 6 | `floor_divide` 在 FlagGems 内部编译失败；`rms_norm` 是本研究的调用写错了参数 |

不一致：
- Liger sparsemax 反向（f32，67 个元素）：`go - go_sum / cnt` 写在一行源代码里，div.full 与减法在同一行，SASS 的行信息分不开
  两者。仿真器在缺少证据时按「收缩」处理，设备实际没有收缩。用工具的非冻结核对（按输出翻转这一选择）可以复现，
  但那是拟合，不算预测。
- FlagGems sort 的 sweep kernel（3 次启动，各 256 个元素）：原因未查明，记为缺口。

流行度：118 个 kernel 中出现各形式的个数。
- 屏蔽读写（C10）115；
- 归约（C3）62；
- 循环（C8）46；
- select（C6）28；
- 扫描（C4）7；
- 原子（C14）6；
- 分支（C7）4；
- dot（C15）3；
- while（C9）3；
- 程序内写后读（C12）2。

最常见的数值原语：
- f32 的加、乘、减（70、63、52 个 kernel）；
- bf16 的 extf / truncf（各 69，混合精度的读入与写回）；
- i64 的下标运算（extsi、muli、addi）。

没有操作落在原语表之外（K1 = 0）。「操作 × 形式」是否都落在扫描过的单元内（K2）没有逐 kernel 统计；
全量扫描覆盖了全部可编译原语 × 全部形式中适用的组合。

## 7 对 three_plans_v3 的审阅

- **答案机兼当设备。** 包的生成器用 `K_elem = round(G)` 代替设备输出，测不到任何下降带来的偏离：
  - div.full、ex2.approx 的近似；
  - 收缩：f32 / f16 / bf16 的 mul + add 都变成单次舍入的 fma；
  - 归约与扫描的布局次序；
  - 张量核的全截断与 tf32 的输入截断；
  - FTZ；
  - remf 的错误。

  本研究的每个单元都在设备上运行。
- **F1 的分母不是「可以出现在 kernel 里的原语」。**
  - 165 个操作名中有 36 个不合法化，6 个 mx 操作无法构造；
  - 反过来，前端产生的 313 个 libdevice 原语被压成一个名字，它们的行为各不相同：有精确、正确舍入、近似、FTZ 之分。
- **缺少决定下降的因子：** 编译选项（`enable_fp_fusion`、`enable_reflect_ftz`、`num_warps`、默认 dot 精度及 bf16x3 / bf16x6）、
  布局参数、生产者与消费者的相邻关系。收缩与近似指令合并只发生在相邻的两个原语之间，包的两两覆盖不覆盖原语 × 原语。
- **两两覆盖与完备性。** 覆盖设计保证每对因子值至少出现一次，这对「故障」有意义；对数值组合，能支撑完备性的是结构归纳
  加单程序逐位证书（第 1 节）。两者可以并用：覆盖设计决定测哪些单元，逐位证书决定单元是否成立。
- **归类只给出「操作 × 包围形式」的袋子，不给出数据流。** 偏差取决于数据流上的系数（导数）与相关性。本研究的归类
  直接用工具的 TTIR 解析器，再由仿真器做逐位证书，用逐位点替换做精确归因。
- **D 模式与分布。** 包的 D1 / D2、D3 / D4 构造在设备上同样成立（E3）。包缺少的是：
  - 状态条件的位点均值（停滞，E2）；
  - 二进位边界的条件偏差（E4、E5）；
  - 形式对同一原语偏差大小的决定作用（E2）。

## 8 局限

- 只有一个 Triton 版本、一个架构；`enable_reflect_ftz=False` 等选项只在选项扫描的两两覆盖中出现。
- 原语表每个分布 2048 个样本，近似原语的最大误差是样本上的最大值，不是证明的上界；16 位一元函数未做穷举。
- 张量核规则覆盖 tf32 / bf16 / f16 与 fp32 累加器；tf32x3、bf16x3 / bf16x6、fp16 累加器仍不可仿真。
- 扫描规则只覆盖一维、正向、无复制的块布局；反向、多操作数、多维扫描仍不可仿真。
- 原子折叠只能给出结果集合；分布与次序的选择未建模。
- 机制实验每类一到两个最小组合；它们检验机制与传播公式，不估计真实工作负载中的流行度（第 6 节只统计结构出现的频率）。

## 10 偏离

- **D-1 仿真器在研究中被修改。** 协议的 RQ2 把工具仿真器当作被测系统。扫描找到缺口后，按「先写失败测试、再修」的规则
  在研究中修复（3.5 节），并把新规则写进工具。报告的扫描是全部修复之后的完整重跑（17,687 个单元，以及 2,065 个选项单元），
  只有两组单元在最后一处修复后单独重跑并替换：fp8 转换 161 个、fptoui 368 + 136 个。修复前的两轮扫描混用了不同版本的代码，
  只作发现缺口用，不报告其数字（留在 `.cache/composition_study`）。
- **D-2 E2 在看到第一次结果后改了设计。** 原设计的 C8 循环每个 lane 只累加 32 步，预测「不停滞」，结果成立，但说明不了机制。
  改为 4096 步并预测「停在 256」后重跑，表中报告的是改后的结果。
- **D-3 E4 / E5 的「B2 + B3」解释是事后的。** 运行前写定的只有「只含 B3」和「最大值偏大」两个预测，两者都不成立，如实列出。
  B2 + B3 分解是看到结果后的解释，其中的「预测」与设备逐位相同，因为设备转换就是就近舍入，所以它只解释、不检验。
- **D-4 张量核模型在第一次矩阵乘核对失败后加了一个阶段。** 第一版模型只用 B = 全 1 的输入拟合，无法分辨乘积的对齐指数。
  加入随机 B 的第二阶段、确定「操作数指数和」之后，再在留出的 27 组矩阵乘上核对逐位相同。
- **D-5 选项扫描只覆盖代表原语。** 按原语表类别 × 族 × 结果类型取 118 个原语代表做两两覆盖，没有覆盖全部原语。
- **D-6 库的捕获需要两处变通。**
  - FlagGems 的复制、填充、随机数操作留在 ATen：否则记录器复制操作数时会进入 FlagGems 的不可重入锁；
  - 工具捕获加入了 StridedBuffer。
- **D-7 TF32 的逐位点替换在规则上做。** 规则对设备逐位相同，但替换后的「反事实 kernel」没有在设备上单独运行。
- **D-8 原语表重跑过。** 三处问题修正后重跑了全表，报告的是最后一次：
  - 参照：无符号输入的整数转浮点；
  - 选择与位转换：比较 NaN 时只比较类别；
  - 模板：clampf 的三个操作数。
