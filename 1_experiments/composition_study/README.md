# 组合研究：Triton 操作组合中 bias 的成因与预测

日期：2026-10-13。对象：Triton 3.6.0（`ka_main`），sm_86（RTX A6000）。协议：[protocol.md](protocol.md)。
输入：用户提供的 three_plans_v3 包（`inputs/three_plans_v3_20261013.tar.gz`，sha256 `4e703057…48a0fa`）。

## 结论

> 数字由 `report_numbers.py` 从结果文件生成（`results/numbers.json`）。本节按两份审阅修订：改正评估错误，撤回过头的说法，
> 加上预测层（第 10 节）。第一版的结论在 git 历史中（提交 e1e9823）。

1. **组合测试能否预测 bias：预测原型已有证据，理论化标准尚未建立（第 10 节）。** 冻结的预测器不运行 kernel，只用组合测试得到的局部关系
   （每个舍入点的契约）与组合规则，事先给出输出的 bias，再在设备上检验：
   - 两个独立的留出集，各 60 个随机程序（逐元素、归约、扫描、循环累加、dot）：成立 51 / 44，不成立 2 / 2，其余按声明的
     失效条件放弃（7 / 14）；
   - 有可测 bias 的程序（「RN 无偏」的零预测被否定）共 45 个：预测器说中 33 个、不成立 3 个、放弃 9 个；
   - 一个真实修改——round-2 的 TF32 kernel 把激活在 `tl.dot` 前就近取到 tf32——在 6 个 Qwen 层上事先预测收缩减少
     3.05–3.54×10⁻⁴，设备实测 2.88–3.58×10⁻⁴；随机 fp32 权重时收缩翻倍到约 −7×10⁻⁴，也事先说中。
   - 不成立全部是 f32 近似函数链（sigmoid、sin、log、erf……）的亚 ulp 偏差（10⁻⁹–10⁻⁸）。v1 的留出结果还揭出预测器噪声
     估计的一个错误，按冻结规则报告 v1、修正后用新的留出种子做了 v2。
2. **原语表测全了。** 包的 705 个操作实例加上前端实际产生的 313 个 libdevice 调用、29 个常量字面量、4 个标量 index_cast，
   共 986 个，每个都有设备结果或明确的不可编译原因（第 2 节）。真实的数值原语是 libdevice 调用，包把它们压成一个名字。
3. **组合规则：仿真器在扫描过的单元上与设备一致，但「逐位相同」只是对测过的输入的证据。** 769 个可编译原语 × 23 种形式，
   17,687 个单元：逐位相同 12,074、部分 1,591（有写出的元素没有仿真值：1,747 个单元——含选项扫描——的这些通道声明值未
   定义，38 个是归约 / 扫描部分和溢出、仿真器未建模）、未建立 235、仿真的元素不一致 0（第 3 节）。第一版把「部分」算作
   逐位相同、并说「逐位相同就说明没有遗漏」，两者都已撤回。单元每个只含一个原语，两个不同原语之间的相互作用不在其中：
   改正后的库语料暴露了三处这类缺口（Liger rope / jsd、FlagGems group_norm），已在工具中先写失败测试再修（3.5 节）。
4. **张量核 dot（sm_86）是一个实验模型：全截断。** 在构造输入上拟合、在留出输入上核对，27 组配置 221,184 个元素逐位相同
   （tf32 / bf16 / f16，K = 256–4864）：tf32 输入截断到 11 位；乘积精确；每 4 / 8 个乘积连同累加器对齐到最大的操作数指数
   和、保留 1 个额外位截断，再截断到 24 位。它推出 dot 的系统性收缩，预测层的 dot 契约由它导出（对逐位模型的偏差
   0.1–2.3%）。
5. **第二轮 TF32 收缩：激活截断是主体，改成就近确实消除它。** 规则在第二轮的真实 Qwen 激活上逐位复现设备（48 个单位）。
   逐个位点把截断换成就近是规则上的反事实（单点切换，彼此不可相加，不是份额）；其中「激活就近」这一处已作为真实修改
   在设备上检验（结论 1）。第 2 层 down_proj（激活有离群值）有约 −4×10⁻⁵ 不被单次截断解释，预测器在这一层同样少预测。
6. **偏差机制。** B1（位点均值）、B1 的状态条件形式（同一个 bf16 加法在循环里停滞在 256，在归约 / 扫描里只有 ±0.3%）、
   B2（包的 D1 / D2）、B4（阈值翻转）各在最小组合里事先预测并成立。就近舍入在每个 2 的幂处的舍入区间不对称，使残差与
   值负相关（B2）：e5m2 下它压过二阶项，「只算 B3」的预测符号反了（E4）。第一版由此推出「就近舍入对光滑数据系统性
   收缩」，这说过了头：整体是收缩还是放大取决于数据在 binade 内的分布与下游系数（E4 的「B2 + B3」吻合用的是精确残差，
   只解释不检验，D-3）。预测层直接在数据的工作点上取舍入函数本身，这一项随之进入预测（e5m2 的单元测试在抽样误差内）。
7. **原语表直接发现了一个错误。** `x % y`（`arith.remf`）在 sm_86 上被下降为 `x − trunc(x/y)·y`，商超过 2²⁴ 时结果完全
   错误（`1e20 % 3` 得 2.2e12）；上游已知（triton #11986），登记为
   [B024](../../4_bugs_cases/bugs/B024_triton_float_mod_large_quotient.md)。预测器对它不给契约（误差超过 2²⁰ ulp，不是有界的
   局部关系），遇到即放弃。
8. **库里的真实 kernel（第 6 节）。** 改正采集错误后共 231 个不同的 kernel（Liger 46、FlagGems 185）：逐位相同 213、
   未建立 11（原子、Welford 合并区域）、有不一致 7（Liger sparsemax 反向的已知 SASS 证据问题、FlagGems sort sweep 原因未
   查明；不一致元素 1,616 个，占仿真元素的 0.0022%）。按完整签名的 K1：152 个 kernel 含 i1 布尔运算，包的原语表没有 i1
   实例；K2：2,504 个（原语, 形式）对中 2,244 个的单元全部逐位相同。

## 1 体系：可以成立的说法

### 1.1 三层与一个恒等式

| 层 | 内容 | 有限吗 | 在这里怎么测 |
|---|---|---|---|
| 原语 P | 每个操作实例（操作名 × 属性 × 类型）与每个 libdevice 函数 × 签名在设备上的执行 | 是：986 个（Triton 3.6.0） | `catalog.py`：每个实例在 7 种分布与特殊值上对精确值 |
| 组合规则 C | 23 种组合形式（直线、共享、归约、扫描、区域、select、分支、循环、屏蔽、下标、存储、跨启动、原子、dot）各自由原语拼出的方式，含下降决定的部分（收缩、近似指令合并、布局次序、张量核累加、FTZ、编译选项） | 是：形式与下降模式都有限 | `cells.py`：原语 × 形式 × 选项在设备上运行，由组合规则（工具仿真器）逐位预测 |
| 偏差机制 M | 位点残差怎样变成输出偏差 | 恒等式，不需要枚举 | `mechanisms.py`：每类在最小组合里预测并检验 |

偏差恒等式：设 kernel 有舍入位点 s₁ … sₙ，从全部精确开始逐个换成设备行为，各步增量 Δₛ 之和恰为 K − G。一阶近似
Δₛ ≈ cₛρₛ（cₛ 是输出对该位点值的导数，ρₛ 是该位点的局部残差），于是

    E[K − G] = Σ E[cₛ]E[ρₛ]  +  Σ Cov(cₛ, ρₛ)  +  二阶及以上项  +  离散判定翻转的跳变
               (B1 位点均值)     (B2 协方差)      (B3 曲率×方差)     (B4)

加上声明程序 G 与任务规格 f 之间的差（B5：常数舍入、存储类型、算法选择），这是全部来源。它是数学恒等式（泰勒展开加分段），
所以「成因分类测全了」不是经验命题；经验命题在于：P 中每个原语的 ρ 是否测对了，C 中每条组合规则是否对设备成立。

### 1.2 能说什么，不能说什么

能说：
- 对 Triton 3.6.0 / sm_86 / 记录的编译选项，原语表覆盖语言中全部可编译的数值原语（不可编译的逐个给出原因）；
- 组合规则对扫描过的全部「原语 × 形式」单元逐位成立，未覆盖的形式逐个列出；
- 对任一具体 kernel 和一组具体输入，可以由仿真与设备的逐位比较检查已列出的位点与规则是否复现了这次执行：逐位相同说明
  在这些输入上规则与设备一致，可以在规则上做逐位点替换的归因；不一致或仿真不了的部分就是缺口，工具报告是哪个节点、
  为什么。逐位相同是对这些输入的证据，不是对其他输入、更不是对其他程序的证书（第一版的「逐位相同就说明没有遗漏」
  说过了头，审阅指出）；
- 能否不运行 kernel 就事先说出 bias，是另一个问题，由第 10 节的预测层回答。

不能说：
- 不能说每个程序在每种数据上的偏差大小已经知道。偏差依赖数据，测的是机制与规则，数据分布只是样本；
- 不能说结论适用于别的 Triton 版本、别的架构。编译选项 `enable_reflect_ftz`、`enable_fp_fusion`、默认 dot 精度
  都会改变原语。本研究在选项扫描中按两两覆盖测了这些因子（3.2 节）；
- 语义层 B5 不能由语言枚举，它依赖任务规格。能枚举的是声明中的舍入点：常量、truncf / fp_to_fp、存储类型；
- 原子折叠的次序不确定：规则只给出可能结果的集合（每个观测都落在其中），给不出确定的位。

## 2 原语表（RQ1，`results/catalog.json`、`results/catalog_summary.json`）

| 来源 | 精确 | 正确舍入 | 正确舍入（特殊值不同） | 忠实（< 1 ulp） | 近似 | dot | 其他 | 不可编译 |
|---|---:|---:|---:|---:|---:|---:|---|---:|
| F1（包的 705 个实例） | 305 | 89 | 23 | 8 | 25 | 7 | 9 个常量由字面量模板覆盖；fp4 dot_scaled 只编译 | 173 |
| libdevice（313） | 71 + 7（仅次正规输入冲零） | 73 | 6 | 8 | 148 | — | — | 0 |
| 字面量（29） | 全部等于十进制值的就近舍入 | | | | | | | |
| index_cast（4） | 4 | | | | | | | |

不可编译的 173 个实例，原因分布：
- 152 个不被 NVIDIA 后端合法化，涉及 36 个操作名；
- 8 个是 fp8 e4m3（nv），需要 sm_89；
- 5 个是 fp8 的 rtz 舍入，后端不支持；
- 6 个 mx 缩放操作无法构造（类型不被 tt 操作接受）；
- 2 个是 f16 / bf16 的 divf，LLVM 位宽不支持。

要点：
- 83 个原语会把次正规数冲成零；
- 近似 / 忠实原语中有 112 个，在光滑分布上的平均有符号误差显著不为零（B1 位点，`results/catalog_summary.json`
  的 `systematic_mean_sites`）。例如 f32 的 `math.sqrt`（`sqrt.approx.ftz`）在四种分布上都偏小约 0.13–0.15 ulp，
  `math.rsqrt` 偏小约 0.07 ulp；
- 另有 57 个正确舍入的原语，平均误差的方向由数据结构决定（例如小整数、近平局），这不是原语本身的偏差。
- 36 个注册了的 TTIR 操作名不被 NVIDIA 后端合法化，6 个 mx 缩放操作无法在合法 kernel 中构造
  （`f8E8M0FNU` / `f4E2M1FN` 不被 tt 操作接受）；fp8 e4m3（nv）需要 sm_89；
- 默认 `enable_reflect_ftz=True` 时，经 libdevice 下降的 f32 运算冲零：floor、ceil、sqrt、rsqrt、exp2，以及全部
  带舍入后缀的 libdevice 运算；
- 近似原语的平均有符号误差在光滑分布上显著不为零（B1 位点），例如 f32 `math.exp`（mul + ex2.approx）在 N(0,1) 上
  为 −0.098 ± 0.012 ulp，在正值上为 +0.097 ± 0.011 ulp；
- 十进制字面量一律按就近舍入成为声明值，例如 0.9999 在 f32 中为 0.99989998，即 B012 的根源；
- `arith.remf` 的错误见结论 7。

## 3 组合规则（RQ2、RQ3）

### 3.1 全量扫描：原语 × 23 种形式（默认选项，`results/cells_summary.json`、`results/cells_default.jsonl.gz`）

可编译的 769 个原语与 23 种形式全部组合，共 17,687 个单元。每个单元：
- 6 个程序，每个程序一种分布；
- 在设备上运行两次检验可重复；
- 由工具的仿真器（全部下降选择冻结）逐元素预测。

状态按严格规则判定（`cells.rescore`，由存储的元素计数重算；数字由 `report_numbers.py` 生成）：**逐位相同**要求每个写出的
元素都被仿真且与设备逐位相同、没有程序中止；仿真的元素全部一致、但有写出的元素没有仿真值的，记为**部分**。第一版把
「部分」也算作逐位相同（1,591 个单元，审阅指出），已改正。

| C2 共享（复用 2 / 3） | 1,360 | 166 | 12 | | |

| C4 扫描 | 334 | 16 | 1,084 | 104 | |

| C6 select / C7 scf.if | 680 / 681 | 83 / 82 | 6 / 6 | | |
| C8 循环（静态 / 数据决定次数） | 1,360 | 166 | 12 | | |

逐元素看：
- 写出 11,282,094 个，仿真 10,969,390 个，其中 10,846,873 个逐位相同，122,517 个两边都是 NaN；
- **不一致 0 个**；
- 未仿真 312,704 个。

「部分」单元里没有仿真值的元素是什么（`results/cells_partial_recheck.jsonl.gz`：把默认与选项扫描中的 1,785 个部分单元
和 1 个不一致单元按记录原因的新版比较函数重跑，状态与元素数不变）：
- 1,747 个单元：声明值未定义的通道。按原因计的单元数（一个单元可有几种）：浮点转整数越界 797、移位不小于位宽 442、
  整数除零或 INT_MIN / −1 493、浮点除法定义域 16。这些通道语义上没有值，不仿真是规则，不是缺口；
- 38 个单元：归约 / 扫描的部分和溢出为 inf，仿真器把这些通道标为模型之外（未记录原因）。设备上是确定的 inf，这是仿真器
  未建模的情形，属缺口。

未建立的 235 个单元：
- 208 个是整数除法、取余、移位作为归约或扫描的组合：除零、移位超宽是未定义的，分别编译时 LLVM 可能不同地折叠，
  按规则不仿真；
- 25 个是原子折叠：规则只给出集合，见下；
- 2 个是 dot：tf32x3 与 fp8 e5m2。

编译器拒绝的 10 个：
- 7 个是 fp8 转换在 map_elementwise 区域内，后端不支持标量 fp8 转换；
- 3 个是 fp8 的屏蔽读取，模板中的 fp8 常量无法解析，属模板限制。

不适用是包的规则：归约与扫描的组合必须是同类型的二元操作，原子要求可原子的更新，dot 形式要求 dot 实例。

覆盖的边界：每个单元只含**一个**原语（重复多次），两个不同原语之间的相互作用（例如乘法与加法收缩成 fma、两个乘积相加
时收缩哪一个）不在单元里。这类缺口要由真实 kernel 暴露：第 6 节的库语料里，Liger rope 与 jsd、FlagGems group_norm 的
三处缺口都属此类（3.5 节）。

### 3.2 编译选项（`results/cells_options_summary.json`、`results/cells_options.jsonl.gz`）

扫描的因子是组合形式、原语代表（按原语表的类别 × 族 × 结果类型取 118 个）和四个选项，四个选项各取：
- `enable_fp_fusion` 真 / 假；
- `num_warps` 1 / 4 / 8；
- `enable_reflect_ftz` 真 / 假；
- BLOCK 32 / 128 / 512。

覆盖方式是两两覆盖：任何两个因子的每对取值都至少出现一次，共 2,065 个单元。结果（严格规则）：
- 逐位相同 1,845；部分 194（同上：未定义值的通道）；编译器拒绝 6（同上的 fp8）；未建立 19（同上的整数组合、原子；
  另 4 个是非交换组合在单个 warp 内 lane 结果不一致）。
- 不一致 1 个单元的 66 个元素：f64 → u8 的 fptoui 链，nw 8、BLOCK 512。链中 `sitofp`（有符号）读回无符号结果，
  后一级 `fptoui` 的输入为负，声明值是 poison，LLVM 可以任意折叠。仿真器给出的元素与设备不同，未能解释，记为未解决。

### 3.3 协议假设的结果

| 假设 | 结果 | 依据 |
|---|---|---|
| H2.1：仿真器能仿真的单元全部逐位相同 | 成立（对最终仿真器，限仿真了的元素） | 最终扫描不一致 0 个元素；1,591 个单元只是部分仿真（3.1 节）。修复前的扫描找到 3.4 节的缺口，按协议逐个找原因，判据未改 |
| H2.2：不可仿真的只有扫描、原子、张量核 dot | 不成立 | 扫描开始时不可仿真的还包括：无声明语义的 libdevice 调用、一般组合区域、f64 运算等。扩展之后剩下的是：整数除法 / 移位组合、原子、拆分精度与 fp8 dot、反向 / 多维扫描 |
| H2.3：同一输入上逐位可重复，原子浮点折叠除外 | 成立 | 13,135 个做了重复运行的单元中，只有两个原子 fadd 单元（f16、bf16）不可重复 |

### 3.4 新建立的规则

| 形式 | 规则 | 证据 |
|---|---|---|

### 3.5 扫描发现、已在工具中修复的仿真器缺口

每处先写修复前失败的测试（`2_tool/tests/test_reference_eval_emulate.py`）。前 16 行在第一版中修复；后 4 行由改正后的
库语料（第 6 节）与审阅发现，在本次修订中修复：

| 缺口 | 现象 | 修复 |
|---|---|---|
| 归约溢出 | 部分和溢出为 inf（或 inf − inf = NaN）时，仿真器给出超出格式范围的有限值并标为已仿真 | 溢出的部分和标为未决定，不再声称 |
| FTZ | `enable_reflect_ftz=True` 时，libdevice 下降的 floor / ceil 与带舍入后缀的 f32 运算冲零（`cvt.rmi.ftz`、`add.rn.ftz`） | 按编译选项对这些运算的操作数与结果冲零 |
| round-down 的零 | 舍入方向向下时精确零和为 −0（IEEE 754） | 零符号规则按舍入方向 |
| f64 有向舍入 | float64 区间无法判定 binary64 的舍入：就近时未决定，有向时给出错误的邻值 | f64 IEEE 运算用 MPFR（53 位、次正规）精确求值 |
| libdevice 乘法融合 | libdevice 函数（内联 LLVM IR）末尾的乘法被每个使用它的加法融合，不论使用次数；有 NaN 的 lane 曾让整个程序退回普通加法 | 对 libdevice 生产者不要求单次使用；NaN / inf 作为已知值进入设备组合 |
| reshape 后的收缩 | `tl.reshape(x*x, can_reorder=True)` 之后的求和仍被收缩为 fma（Liger group norm） | 穿过同形状的 reshape / 布局转换寻找乘法 |
| 内存捕获缺 SASS | 只有存盘的捕获才读 SASS，内存中的捕获无法判断 ptxas 是否收缩（Liger sparsemax） | 从保留的 cubin 反汇编 |
| 无声明语义的 libdevice | 152 个 libdevice 原语因缺少声明语义而中止 | 仿真不需要声明语义：由设备在仿真的操作数上求值 |
| 单操作的归约 / 扫描区域 | 乘积归约、非结合或整数的扫描区域不可仿真 | 按布局次序（归约）/ 扫描次序，由设备求组合操作 |
| 张量核 dot、扫描 | 不可仿真 | 新规则（上表） |
| f32 有向舍入的零 | 输出区间的外向舍入把精确零变成最小次正规数，FTZ 后为 −0 | 带舍入后缀的 f32 运算也用 MPFR 精确求值 |
| 整数结果 | 不可仿真的整数值写入整数缓冲区时报错；i64 的设备求值经 float64 丢位 | 整数类型的未建立值；设备结果按 int64 取回 |
| 整数到浮点 | 超过 2^53 的整数留下区间，后续 f64 运算取错邻值 | MPFR 一次就近舍入 |
| fptoui | 到 u64 时 [2^63, 2^64) 溢出；到 u8 / u16 / u32 时未按有符号表示保存 | 经 uint64 与按宽度回绕（基础求值器） |
| fp8 e5m2 与 clampf | sm_86 的软件 e5m2 转换平局远离零（声明为就近偶）；clampf 的 min / max 零符号 | 由设备求值 |
| 并行的 oracle 缓存 | 多进程同时写同一个 TTIR 文件，读到不完整的内容 | 先写临时文件再改名 |
| 核对的状态 | `verify` 在有写出的元素未仿真或有程序中止时仍报 `bit_identical` | 新增 `partial`：仿真的元素全部一致但不完整 |
| 两个乘积相加时收缩哪一个 | 两个乘积在同一行时，留下的乘法在 PTX 里带第一个乘积的列号，按位置判断会选错（f32 `a*b - c*d`）；bf16 的单独乘积在 sm_86 上是 `fma.rn.bf16 x, y, -0`，原来认不出 | 先用 PTX 数据流证据：单独乘法的两个乘数来自哪个乘积的操作数（经 mov / cvt 追到定义它们的指令的源位置）；没有结论时再用位置证据 |
| 展平 reshape 后的归约次序 | `tl.reshape(x2d, (n,), can_reorder=True)` 后求和，仿真器用一维布局的次序，设备用源二维布局的寄存器次序 | 由源布局算出每个值所在的 warp、lane、寄存器，按寄存器次序排列后走同一棵树 |
| 展平 reshape 后的乘加收缩 | 乘积穿过改变形状的 reshape 进入求和时，未并进第一个组合 | 穿过展平的 reshape 寻找乘法 |

E4 与 E5 的不成立有同一个原因：就近舍入在二进位边界的舍入区间不对称。例如 e5m2 中 2 的区间是 [1.875, 2.25)，
下侧 0.125、上侧 0.25，刚过 2 的值被大量舍向 2。所以对光滑分布的数据，残差的条件均值随幅度变化，在边界附近为负。

- e5m2：刚过二进位的数（尾数分数 < 1/8）平均残差为 −5.7%；
- bf16：为 −5.4×10⁻⁶。

「就近舍入局部无偏，所以只剩方差项」的直觉在粗格式下是错的。

## 5 陌生 kernel 的归因：第二轮 C 组的 TF32 收缩（RQ5，`results/tf32_attribution.json`）

输入是第二轮捕获的 Qwen2.5-0.5B 真实激活（128 个 token × K）与真实权重，kernel 是第二轮用的 Triton 教程矩阵乘
（BK = 32，默认 tf32）。
- 张量核规则在 48 个单位、5,505,024 个元素上逐位复现设备输出；
- 权重全部是 tf32 精确的（来自 bf16 检查点）。

对齐 ⟨e, r⟩ / ⟨r, r⟩，每层 8 个单位的平均：

| 层 | 设备 | 由激活 τ 预测 | 激活截断 | 权重截断 | 累加截断 | 全部换成就近后剩余 | 激活截断 / 规则对齐 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2 q_proj（K = 896） | −3.519e-4 | −3.520e-4 | −3.500e-4 | 0 | −2.6e-6 | +6.5e-7 | 99.5% |
| 12 q_proj | −3.588e-4 | −3.517e-4 | −3.567e-4 | 0 | −2.6e-6 | +4.4e-7 | 99.4% |
| 22 q_proj | −3.550e-4 | −3.520e-4 | −3.547e-4 | 0 | −2.4e-6 | +2.1e-6 | 99.9% |
| 2 down_proj（K = 4864） | −4.299e-4 | −3.521e-4 | −3.699e-4 | 0 | −2.1e-5 | −3.9e-5 | 79.1% |
| 12 down_proj | −3.653e-4 | −3.520e-4 | −3.525e-4 | 0 | −1.3e-5 | +1.9e-7 | 96.5% |
| 22 down_proj | −3.657e-4 | −3.520e-4 | −3.512e-4 | 0 | −1.4e-5 | −4.6e-7 | 96.0% |

逐位点的替换是在规则上做的：规则对原 kernel 逐位复现设备，但替换后的「只改这一处」的反事实没有在设备上单独运行（D-7）。
「激活截断」等三列各是一次单点切换（其余位点保持截断）带来的对齐变化，它们不可相加，也不是总量的份额：三列之和加上
「全部换成就近后剩余」不等于设备对齐（位点之间有相互作用，例如激活就近后累加截断面对的项也变了）。最后一列只是比值。
其中一处——激活转换改成就近——在第 10 节作为真实修改，先冻结预测、再在设备上运行检验。

读法：
- **激活截断是主体。** 第二轮看到的约 −3.5×10⁻⁴，与一次截断的期望 −½·2⁻¹⁰·E[2^e/|x|]（激活的尾数接近对数均匀分布）
  相符；第 2 层 down_proj 设备为 −4.30×10⁻⁴，激活 τ 的预测 −3.52×10⁻⁴ 只解释了它的约 82%（见下面的例外）。
- **权重为 0。** 权重截断不起作用，因为权重来自 bf16 检查点，在 tf32 中精确。
- **cuBLAS TF32 的收缩小两个数量级。** 这与它对操作数做就近转换一致；cuBLAS 是黑箱，这一点只作推断，未单独核验。
- **K = 4864 时累加截断约占 4–5%。**
- **第 2 层 down_proj 是例外。** 它的激活有大的离群值，全部换成就近后仍有 −3.9×10⁻⁵ 的剩余，来自第 4 节说的
  二进位边界条件偏差。

第二轮只能说「收缩存在」，现在可以说清它从哪里来。「把激活转换改成就近（cvt.rna）收缩就会消失」在本节只是规则上的
反事实；它在设备上是否成立见第 10 节。tf32x3 的下降不在模型内，没有检验。

## 6 库里的 kernel（RQ5，`results/corpus.json`）

样本：
- Liger-Kernel 0.6.2 的 13 个操作，f32 与 bf16，前向与反向；
- FlagGems 5.0.2 的 50 个 torch 操作，f32 / f16 / bf16，经 `flag_gems.use_gems`。

每次调用中每个 kernel 名取前两次启动，按 TTIR 去重，共 231 个不同的 kernel（Liger 46、FlagGems 185）。处理方式：
- 拆成原语与形式；
- 由组合规则逐位仿真，下降选择全部冻结。

第一版的语料有两处采集错误（审阅指出，已改正后重跑）：FlagGems 的调用在 dtype 循环里定义，lambda 在调用时才查找
`x_` 与 `dt`，三个 dtype 实际都跑了 bf16（56 个 kernel 受影响）；捕获上限按 kernel 名跨调用计数，同一 kernel 在第二个
dtype 上不再捕获（例如 Liger rope 的 bf16 从未比较过）。第一版的 118 个 kernel 因此少了 f32 / f16 的 FlagGems 与部分
bf16 的 Liger。

| 结果 | Liger | FlagGems | 说明 |
|---|---:|---:|---|
| 逐位相同 | 41 | 172 | |
| 未建立 | 4 | 7 | 原子累加（Liger layer_norm / group_norm 反向；FlagGems nll_loss、sort 直方图）；FlagGems `var` 的 Welford 合并区域（多操作的组合） |
| 有不一致 | 1 | 6 | 见下 |
| 调用失败（不计入） | — | 2 | `floor_divide` 的 f16 / bf16 在 FlagGems 内部编译失败 |

逐元素：写出 73,245,927 个，仿真 73,114,855 个，其中不一致 1,616 个（0.0022%），均在下面两处。

不一致：
- Liger sparsemax 反向（f32，80 个元素）：`go - go_sum / cnt` 写在一行源代码里，div.full 与减法在同一行，SASS 的行信息
  分不开两者。仿真器在缺少证据时按「收缩」处理，设备实际没有收缩。按输出翻转这一选择可以复现，但那是拟合，不算预测。
- FlagGems sort 的 sweep kernel（每个 dtype 2 次启动，各 256 个元素）：原因未查明，记为缺口。

改正后的语料暴露了第一版没有看到的三处仿真器缺口，都是两个不同原语之间的相互作用（单元扫描每个单元只含一个原语，
覆盖不到），已按「先写失败测试、再修」在工具中修复（3.5 节）：
- Liger rope（f32 与 bf16）：`a*b - c*d` 两个乘积在同一行，LLVM 收缩其中一个，留下的那个乘法在 PTX 里带的是第一个乘积的
  列号，不论留下哪个；bf16 的单独乘积在 sm_86 上是 `fma.rn.bf16 x, y, -0`，原来的证据读取认不出它；
- Liger jsd（bf16）：修上一条时一度把「同一行」的位置证据整个关掉，回归；现在先用数据流证据，没有结论时再用位置证据；

  组合次序是源布局的；乘积穿过展平的 reshape 也会并进第一个组合。bf16 输入时 f32 部分和几乎是精确的，次序不影响结果，

## 7 对 three_plans_v3 的审阅

- **答案机兼当设备。** 包的生成器用 `K_elem = round(G)` 代替设备输出，测不到任何下降带来的偏离：
  - div.full、ex2.approx 的近似；
  - 收缩：f32 / f16 / bf16 的 mul + add 都变成单次舍入的 fma；
  - 归约与扫描的布局次序；
  - 张量核的全截断与 tf32 的输入截断；
  - FTZ；
  - remf 的错误。

  本研究的每个单元都在设备上运行。
- **F1 的分母不是「可以出现在 kernel 里的原语」。**
  - 165 个操作名中有 36 个不合法化，6 个 mx 操作无法构造；
  - 反过来，前端产生的 313 个 libdevice 原语被压成一个名字，它们的行为各不相同：有精确、正确舍入、近似、FTZ 之分。
- **缺少决定下降的因子：** 编译选项（`enable_fp_fusion`、`enable_reflect_ftz`、`num_warps`、默认 dot 精度及 bf16x3 / bf16x6）、
  布局参数、生产者与消费者的相邻关系。收缩与近似指令合并只发生在相邻的两个原语之间，包的两两覆盖不覆盖原语 × 原语。
- **两两覆盖与完备性。** 覆盖设计保证每对因子值至少出现一次，这对「故障」有意义；对数值组合，更有用的是按原语与组合
  形式逐个核对下降规则，并在真实程序上逐位核对（第 1 节）。两者可以并用：覆盖设计决定测哪些单元，逐位核对决定单元在
  测过的输入上是否成立。
- **归类只给出「操作 × 包围形式」的袋子，不给出数据流。** 偏差取决于数据流上的系数（导数）与相关性。本研究的归类
  直接用工具的 TTIR 解析器；预测层（第 10 节）沿数据流传播每个舍入点的局部契约。
- **D 模式与分布。** 包的 D1 / D2、D3 / D4 构造在设备上同样成立（E3）。包缺少的是：
  - 状态条件的位点均值（停滞，E2）；
  - 二进位边界的条件偏差（E4、E5）；
  - 形式对同一原语偏差大小的决定作用（E2）。

## 8 局限

- 只有一个 Triton 版本、一个架构；`enable_reflect_ftz=False` 等选项只在选项扫描的两两覆盖中出现。
- 原语表每个分布 2048 个样本，近似原语的最大误差是样本上的最大值，不是证明的上界；16 位一元函数未做穷举。
- 张量核规则覆盖 tf32 / bf16 / f16 与 fp32 累加器；tf32x3、bf16x3 / bf16x6、fp16 累加器仍不可仿真。
- 扫描规则只覆盖一维、正向、无复制的块布局；反向、多操作数、多维扫描仍不可仿真。
- 原子折叠只能给出结果集合；分布与次序的选择未建模。
- 机制实验每类一到两个最小组合；它们检验机制与传播公式，不估计真实工作负载中的流行度（第 6 节只统计结构出现的频率）。
- 预测层的局限见 10.4 节：近似函数链的亚 ulp 偏差、离散工作点、一阶范围之外、判定规则二阶项的加权、留出程序只来自一个
  语法。

## 10 组合测试能否预测 bias（预测层，`2_tool/.../reference_eval/bias_predict.py`）

第一版做到的是**仿真**：给定输入，规则逐位复现设备。审阅指出这不是「通过组合测试预测 bias」：预测要在 kernel 运行之前，
只用组合测试得到的局部关系与组合规则说出 bias，再用冻结的预测在留出程序上检验。本节是这一层。

### 10.1 预测器

不运行 kernel（`TritonLaunchRecorder(execute=False)` 只记录启动），按精确值把启动求一遍；在每个舍入点注入该点的
**契约**——给定精确操作数的特征时残差的条件均值、半宽、方差——并沿求值器的前向切向规则传播到输出：

    E[K − G] ≈ Σ_s J_s · μ_s

每个输出元素得到预测均值误差 δ、一阶最坏半径 R、预测总误差（δ 加一次噪声抽样）；对每个输出给对齐 ⟨δ, G⟩ / ⟨G, G⟩。

契约（条件 → 局部偏差关系），每条都来自本研究的组合测试：

| 舍入点 | 局部关系 | 依据 |
|---|---|---|
| 正确舍入的 RN 点（IEEE 运算、转换、整数转浮点） | 舍入函数本身 r(t) = RN(t) − t，在设备值估计（精确值加已预测的均值误差，落到各自格式的网格）上取值；吸收、进位、跨 binade、平局、短结果、二进位边界的不对称（B2）都在其中 | 原语表：这些原语在设备上正确舍入 |
| 近似原语（div.full、ex2.approx 系、非正确舍入的 libdevice） | 每格（一元：输入的符号、binade、8 个有效位桶；二元：输出的符号、binade、4 个桶）、每个操作数有效位类别的平均有符号误差 | `contracts.py`：在设备上单测原语，对 MPFR 精确值 |
| 软件 e5m2 转换 | 其函数（先截到 f16，再 3 位最近远离）在估计值上取值 | 组合研究；对设备逐位相同 |
| 张量核 dot | tf32 操作数截断的均值；每组截断丢弃位的均值（各项粒度：乘积的最低置位、沿链跟踪的累加器粒度） | `tensor_core.py` 的规则；对逐位模型的偏差 0.1–2.3% |
| 求和归约 / 扫描 / ieee dot | 设备组合顺序上逐次的 RN 关系 | C3 / C4 / C15 单元的下降规则 |

组合时保留的信息：精确值；切向区间 [δ − R, δ + R]；每个操作数在设备上能携带的有效位数；加法吸收时操作数的设备值估计。

失效条件（任一成立则「无法判断」）：没有契约的运算；R 内可能翻转的不连续阈值（select 两支相差大于 R、浮点转整数、
floor 等）；预测总误差超过 |G| 的 2⁻⁴ 的元素超过 1%；次正规 / 非有限值超过 0.1%；浮点原子；近似原语超过 1% 落在未刻画
的格外，或只在少于 64 个不同的操作数值上求值。

### 10.2 检验设计（[predictor_protocol.md](predictor_protocol.md)，v2：[predictor_protocol_v2.md](predictor_protocol_v2.md)）

- 留出程序：`programs.py` 的语法随机生成，覆盖逐元素链、归约、扫描、循环累加、dot（tf32 / ieee / bf16 / f16、就近预
  取整）、近似函数、转换（含 e5m2）、连续与不连续的 select；种子由冻结的预测器、契约表、生成器的 SHA-256 决定；
- 预测在 6 个输入种子上做，捕获时核不运行；预测文件在任何测量之前入库（v1：提交 8bc0407，SHA-256 eef82b40…）；
- 测量在另外 6 个输入种子上做，G 由参照求值器给出；
- 判定：|α − α̂| ≤ 3·√(SE_pred² + SE_meas²) + 0.1·|α̂| + 2·r²（抽样、一阶契约的相对精度、二阶项）；
- 对照：零预测（「RN 无偏」，α̂ = 0）按同一规则判定。只有零预测被否定的程序，预测器的非零预测才是组合测试带来的信息。

### 10.3 结果

**留出集 A（v1，60 个程序）**：成立 51、不成立 2、无法判断 7。

| | 预测器成立 | 预测器不成立 | 预测器无法判断 |
|---|---:|---:|---:|
| 零预测被否定（有可测的 bias）：24 | 19 | 2 | 3 |
| 零预测成立：36 | 32 | 0 | 4 |

- 按形式：dot 17 / 1 / 0，逐元素 12 / 1 / 3，扫描 10 / 0 / 1，归约 6 / 0 / 0，循环 6 / 0 / 3（成立 / 不成立 / 无法判断）；
- 两个不成立：p027（tf32 dot 后接 sigmoid，预测 −2.4×10⁻⁹、实测 −4.4×10⁻⁹：近似函数链的亚 ulp 偏差，冻结前已知的局限）；
  p006（e5m2 转换后接 tanh / sqrt / cos，预测 4.1×10⁻⁴、实测 6.3×10⁻⁴）。p006 揭出预测器的一个错误：噪声遍不携带半径
  通道，下游点都被当作精确操作数而不注入方差；所报告的 RMS 也漏掉了每个元素的确定性均值误差。r 因此被低估（留出集上
  预测 / 实测中位数 0.43），二阶项 2·r² 偏小，「相对误差过大」的失效条件几乎不起作用。均值预测不受影响。按协议，v1 的
  结论照冻结时报告；修正放进 v2，用新的留出种子重做；
- 七个无法判断：两个是离散输入的近似函数（p025、p046），若照样计分两个都会不成立——放弃有理由；两个次正规（p004、
  p056）、两个相对误差过大（p032、p034）、一个 floor 可能翻转（p022），若照样计分这五个都在容差内。

**留出集 A2（v2，60 个新程序，预测文件提交 1fb5efc，SHA-256 8c95b1f4…）**：成立 44、不成立 2、无法判断 14。

| | 预测器成立 | 预测器不成立 | 预测器无法判断 |
|---|---:|---:|---:|
| 零预测被否定：21 | 14 | 1 | 6 |
| 零预测成立：39 | 30 | 1 | 8 |

- 两个不成立都是 f32 近似函数链在 bf16 值输入上的亚 ulp 偏差：p012（sigmoid、log，预测 −9.6×10⁻⁹、实测 +2.1×10⁻⁸）、
  p049（div.full、sin、log，预测 1.2×10⁻⁸、实测 1.9×10⁻⁹——零预测成立而预测器不成立，一个假阳性）；
- 无法判断从 7 个升到 14 个：修正后「相对误差过大」的失效条件真正起作用（7 个）。照样计分的话 14 个中 11 个在容差内，
  三个会不成立（两个离散输入、一个可能翻转）——这三次放弃有理由，其余是保守的。

**判定规则的一个缺陷（事后发现，不改冻结的判定）**：二阶项 2·r² 里的 r 是相对误差的不加权 RMS，接近零的输出（例如矩阵乘
的抵消）让它变得很大，个别容差因此宽到没有意义（TF32 的某些层到 0.3 甚至 1.6）。α 按 G² 加权，二阶项也应按 G² 加权。
事后用不含二阶项的严格容差（3·SE + 0.1·|α̂|）重查：A 的 51 个、A2 的 44 个成立全部仍成立，下面 TF32 的 24 个也全部
仍成立——没有一个成立靠这个缺陷（`results/numbers.json` 的 `post_hoc_strict_tolerance`）。

**真实修改（TF32，第 5 节的 kernel；预测提交 aae04e7，SHA-256 faca27ab…，用 v1 预测器）**：24 个（变体, 层×矩阵）全部

### 10.4 能说什么

外部审阅（`c415b62`）之后的评估：下面的结果说明预测原型有事前预测的能力，但还不是理论化标准——契约里混有确定的舍入函数、
经验格均值和一阶近似，半宽不是界，判定是经验容差（不确定性越大越容易通过），组合定理与余项界没有写出，组合测试检验的是仿真
而不是「部件契约能否推出整体」；冻结后又发现两处模型内错误（噪声遍、fma 链的状态传播，后者已在工具中修正）。下文的「成立」
都应按这一点读。

在声明的范围内**事前预测与设备相符**：Triton 3.6.0 / sm_86，由已编目原语按本研究的组合形式构成的程序（生成器的语法：逐元素链、归约、
扫描、循环累加、dot，IEEE 运算、近似函数、转换、select），输入为声明的分布。只用组合测试得到的局部关系和组合规则，冻结的
预测器事先给出输出的 bias，并在设备上被证实：
- 两个独立的留出集（每个 60 个程序）：成立 51 与 44，不成立各 2，其余按声明的失效条件放弃；
- 有可测 bias 的程序（零预测被否定，24 与 21 个）：预测器成立 19 与 14、不成立 2 与 1、放弃 3 与 6——「RN 无偏」在这些
  程序上全部失败，预测器的非零预测是组合测试带来的信息；
- 一个真实修改（tf32 激活就近）的效果在 6 个真实层上事先说中，并在设备上运行证实；随机权重的翻倍同样说中。

**不成立 / 无法判断的部分**：
- f32 近似函数链的亚 ulp 偏差（10⁻⁹–10⁻⁸）：格均值契约在一个格里平均掉了误差随有效位的细节，四个留出不成立都在这里
  （开发集也一样）；
- 少数固定工作点上的近似函数（离散输入）、可能翻转的不连续阈值、一阶范围之外的大误差、次正规、浮点原子、未编目的运算：
  预测器放弃，不给数；
- 判定规则的二阶项按不加权的相对误差计，接近零的输出让容差偏宽（事后严格重查不改变任何结论，但规则本身应改为按 G² 加权）；
- 留出程序来自一个语法；真实库 kernel 只检验了 TF32 一例，第 6 节的库语料没有做预测；只有一个 Triton 版本、一个架构。

## 11 偏离

- **D-1 仿真器在研究中被修改。** 协议的 RQ2 把工具仿真器当作被测系统。扫描找到缺口后，按「先写失败测试、再修」的规则
  在研究中修复（3.5 节），并把新规则写进工具。报告的扫描是全部修复之后的完整重跑（17,687 个单元，以及 2,065 个选项单元），
  只有两组单元在最后一处修复后单独重跑并替换：fp8 转换 161 个、fptoui 368 + 136 个。修复前的两轮扫描混用了不同版本的代码，
  只作发现缺口用，不报告其数字（留在 `.cache/composition_study`）。
- **D-2 E2 在看到第一次结果后改了设计。** 原设计的 C8 循环每个 lane 只累加 32 步，预测「不停滞」，结果成立，但说明不了机制。
  改为 4096 步并预测「停在 256」后重跑，表中报告的是改后的结果。
- **D-3 E4 / E5 的「B2 + B3」解释是事后的。** 运行前写定的只有「只含 B3」和「最大值偏大」两个预测，两者都不成立，如实列出。
  B2 + B3 分解是看到结果后的解释，其中的「预测」与设备逐位相同，因为设备转换就是就近舍入，所以它只解释、不检验。
- **D-4 张量核模型在第一次矩阵乘核对失败后加了一个阶段。** 第一版模型只用 B = 全 1 的输入拟合，无法分辨乘积的对齐指数。
  加入随机 B 的第二阶段、确定「操作数指数和」之后，再在留出的 27 组矩阵乘上核对逐位相同。
- **D-5 选项扫描只覆盖代表原语。** 按原语表类别 × 族 × 结果类型取 118 个原语代表做两两覆盖，没有覆盖全部原语。
- **D-6 库的捕获需要两处变通。**
  - FlagGems 的复制、填充、随机数操作留在 ATen：否则记录器复制操作数时会进入 FlagGems 的不可重入锁；
  - 工具捕获加入了 StridedBuffer。
- **D-7 TF32 的逐位点替换在规则上做。** 规则对设备逐位相同，但替换后的「反事实 kernel」没有在设备上单独运行。
- **D-8 原语表重跑过。** 三处问题修正后重跑了全表，报告的是最后一次：
  - 参照：无符号输入的整数转浮点；
  - 选择与位转换：比较 NaN 时只比较类别；
  - 模板：clampf 的三个操作数。
- **D-9 第一版的评估错误（审阅指出，本次修订改正）。** 部分仿真的单元与启动被算作逐位相同（1,591 个默认单元）；
  FlagGems 调用的 lambda 晚绑定，三个 dtype 都跑了 bf16（56 个 kernel）；捕获上限跨调用计数；K1 只按操作名比较、K2 没有
  实现。状态改为严格规则并由存储的元素数重算（原始单元记录不变），语料重新采集，K1 / K2 按完整签名实现。第一版

  照冻结时报告；修正后另立 v2 协议，用新的留出种子生成新的 60 个程序重做。
