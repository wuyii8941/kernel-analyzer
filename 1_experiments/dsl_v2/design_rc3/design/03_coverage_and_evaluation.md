# 03 官方覆盖与评价：先定外部全集，再核对实现

## 1. 覆盖分母来自官方，不来自仓库

官方目标面U由固定的Triton提交、相应LLVM提交、前端及后端profile定义。经典语言和Gluon都在目标中；NVIDIA/AMD设备缺席只影响验证进度，不删除语言目标。[S01–S05]

`legacy_229_route.json`只是旧仓库快照。原来的165项TTIR子集可以保留为一个历史运行配置，不能当作DSL的总分母。
`official_surface_matrix.json`的61项是本次整理出的需求族；`official_public_exports_snapshot.json`的148项只是一个模块的`__all__`。它们均不等于所有指令、方法、属性和外部符号的全集。

## 2. 官方清单四条来源链

### 2.1 公共接口

枚举classic/Gluon的模块导出、tensor及descriptor方法、类型与布局对象、NVIDIA/AMD子模块、随机数、排序、调试和编译提示。
区分别名、复合包装、原语和编译期对象。别名可共享实现，不得漏掉不同默认参数或约束。

### 2.2 源码定义

从官方TableGen定义、生成器及接口声明提取操作、类型、属性枚举、region/successor结构、traits、memory effects和verifier。
处理模板实例化、include和条件编译。对源码文件作正则扫描只能发现候选，不能声称完成了所有TableGen实例枚举。
同时登记所用MLIR版本与builtin/arith/math/scf/cf/ub及导入路径实际依赖的后端方言。

### 2.3 构建与目标

从构建后加载的方言注册表、实际后端target支持和运行时签名取得有效配置。
“源码存在但此构建未启用”“后端支持但当前设备不具备”“experimental但官方导出”均单列。
不能凭一台sm_86设备没有生成TMA/MFMA，就说这些构造不在DSL内。

### 2.4 实际编译与执行

按官方教程、单元/集成测试与独立现实语料收集实际签名和路径。记录autotune选择、fallback、布局和实际库符号。
代码中缺少日志不证明对应官方构造不存在；反过来，实际出现而清单没有的项必须触发覆盖警报。

四条来源链的差集要求逐项有依据；不是简单要求各集合相等。源码可包含本profile不启用的项，实际日志必是有限样本。

## 3. 规则覆盖单位

    signature = (source_profile, operation, type_pattern, attrs_guard,
                 region_interface, effect_contract, semantic_policy)

每条规则要声明匹配的整个子域，并检查重叠冲突、遗漏及未知属性。数值输入、形状和combine长度无穷多，不靠列举覆盖；使用符号条件和参数化证明。

同一操作可对应多种路线：数值模式下的精确函数、格式模式的舍入函数、官方许可的结果集合、环境参数化关系。不能用一列`exact`覆盖所有模式和输入。

全覆盖至少分五个指标：
1. 官方需求已登记比例；
2. 签名规则及义务实现比例；
3. 接纳后按承诺得到参照的比例；
4. 达到请求分辨率/统计条件的比例；
5. 现实调用中实际可用的比例。
第一项不替代后四项。未实现和未测硬件不从分母删除。

## 4. 必测的结构及交互

| 结构轴 | 适用时必须出现的边界与组合 |
|---|---|
| 数值/格式 | exact/初等函数、全部声明浮点格式、打包FP4/FP8、scale轴、特殊值、有符号零、FTZ、抵消和舍入边界 |
| 张量 | shape 0/1或源API允许的最小值、广播、不同stride/offset、allow_reorder/can_reorder、重复布局副本 |
| 区域 | 多值reduce、scan、map、带分支combine、嵌套循环、调用、早退和数据相关循环终止 |
| 内存 | aliases、mask/other、间接地址、in-place、跨启动、缓冲复用、无效地址、同线程顺序与跨线程冲突 |
| 并发 | CAS/RMW返回值使用、轮询与进展、合法非交换顺序、mbarrier phase/bytes、不同作用域、异步提前复用 |
| 后端 | tensor memory、warpgroup/warp specialization、cluster/CLC、AMD buffer/LDS/TDM/MFMA及packed操作 |
| 插件/环境 | inline asm pack/约束/副作用、extern、RNG与seed/counter、时钟、插桩和编译假设 |
| 观察 | 多输出、辅助下标、状态写入、输出/梯度/实际更新、固定方向/对齐/整向量 |

不要求全笛卡尔积；按语义合法性分区采用两两组合，加有理由的高风险三项及更深嵌套。有限覆盖数组不能替代组合证明。[P5]
真实算子（注意力、MoE、状态空间、归一化、优化器、卷积等）只是这些结构的载体，不是DSL白名单。

## 5. 生成测试与独立答案

生成器按官方合法签名/契约生成，不按求值器已经实现的规则筛掉困难项。语义oracle与被测导入器不共用判定实现。
有理核心用独立精确计算；初等函数用独立严格包围或可证明解析关系；高精度点值仅作为交叉检查。
并发程序区分三个集合：已知有效、已知违反、有效性尚未证实。不可交换原子、CAS和轮询不自动放入非法集合。

注入先核查是否激活；倍乘2的幂、恒真mask、编译后等价变换不能硬当阳性。
确定性改名对可检查逐位一致；合法非确定性程序按执行分布/集合比较，一致性对不是相对G的零均值标签。
有意制造真实竞争的运行使用权限允许的隔离流程，未经许可的项标未执行；不绕过权限，也不计正确拒绝。

## 6. 现实语料与验收分离

官方教程/测试、编译器生成和独立库实现三个来源层先登记，再看工具是否支持。记录编译失败、捕获失败与所有fallback。
开发/保留按实现谱系、结构和作者来源切分，不能只换seed。开发语料用于排序欠账；保留集只在冻结后用于验收。

每个未完成输出记录全部阻塞。优先级按解除联合阻塞后的覆盖收益、实现/证明成本和目标分辨率，而不按单项出现次数贪心。
同时报告去重任务覆盖与调用频次加权覆盖；重复调用不冒充独立实现。

## 7. E / F / P / FR 对照不变

E比较eager；F直接比较独立规格；P执行前提明确的性质；FR加入G与分解。
F与FR使用同一K−f契约裁决任务违反，FR的G−f与K−G另行评分。
普通参考实现加相同统计既是产品降级路径，也是外部基线。没有G时不能硬分解；有严格f时也不能称其未认证。
FP64匹配不证明G精确，性质通过不证明任务正确，数值均值非零不证明训练损害。

现有两轮盲测、独立复算、已知问题、现实语料以及失效校准保留版本对应，不自动认证rc3设计的新功能。
原答案缺失或标签事后修改时，另列事后独立裁决，不倒填成预先封存。

## 8. 覆盖计分与停止

- 接纳前规则/前提不足：记能力欠账或证明未找到，不声称程序错误。
- 预先承诺的片段内缺规则、漏包或静默读取实际值：记实现缺陷，不临时改语言移出分母。
- 集合语义宽度：不是漏包；是否足以支持稳健均值由区间判断，不能默认成功或失败。
- 预算耗尽：记服务失败及范围，不能伪装完整。
- 新签名/后端：扩目标账本，历史实验分母不变。
- 每项结果提供source、target_id、范围、参照质量、效应及统计状态。

最终不能只发布一个“官方覆盖率”。目标登记、实现承诺、数值质量、检测能力和现实可用性是五件事。
