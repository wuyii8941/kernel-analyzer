## 1. 验收对象

第一批交付（`3_audits/batch1_semantic_core/README.md`）：

1. 来源 / 内存效果：跨输入摘要误配、原地算术后字节未变、重叠 view 部分写入当成整块常数三类问题的修复（组合规则 M1–M5），以及
   生产者追踪不干扰被测运行（T1）。
2. 精度控制器：不再用"达标比例没变"推断"继续加精度无效"；停止类别为达标 / 预算耗尽 / 后端限制 / 固有集合宽度 / 无数值包围 /
   本级失败（P1–P3）。
3. 安装包：已安装的 wheel 运行时不依赖仓库路径，入口可用（K1）。
4. bias 查询：比较目标、输入分布、观察量与抽样单位在数据之前固定；严格有界路线带声明族（每个规则类内 Holm）保证；非零与等价两个
   判定轴分开，只在请求等价时要求预先声明 δ（Q1–Q3）。

## 3. 独立答案

- 来源：每项的真值（`truth`：读到的字节是否等于调用自身的值——声明输入、精确常数或其精确拷贝）由程序语义直接推出，写在
  `items.json` 里；工具的预期范围（`expected.reference_scope`）也事先写定。真值为"干净"而工具规则给 kernel 级的项（H-P1b、H-P7、
  H-P12）事先标为保守（能力缺口，不是可靠性问题）。任何"真值不干净却给 call 级"都是可靠性违反，单独标出。
- 精度：H-R1 / H-R2 的级别由 `predict_levels.py` 预测——不调用工具的区间代码，在 60 位精度下按公开的 SumK / Sum2 / γ 界在同一批单位
  输入上计算宽度与 float32 binade 的 1/8 ulp 之比（`predictions.json`，运行前已生成：两项都在第 2 级达标）；H-R3 / H-R4 / H-R5 的类别由
  结构推出（无精度相关规则 / float64 端点 / 集合目标）。
- bias：H-Q1 的符号由舍入方向推出（向零舍入把正值拉向零：坐标均值为负，R1、R2 为正），有界路线的 M 由推导给出（写在声明的 basis
  里，不来自样本）；H-Q2 只承诺等价轴（|K − G| ≤ 0.0157 对 δ ≈ 0.056），非零轴不做承诺。
- 回归：与 reg20261009T2319 的逐程序行比较（预计命中、观察、K−G / K_R−f 汇总、执行状态、v3.1 比较字段）。

## 4. 判定

每项只记三种状态：成立 / 不成立 / 无法判断。

- 来源：工具的范围等于预先写定的范围记成立，否则不成立；运行错误或输出未评估记无法判断。
- 精度：类别与预测一致、达标级别等于预测级别（预测标为 uncertain 时允许相差一级）、需要时结果前缀一致，记成立。
- bias：预先承诺的每一项都一致记成立；有不一致记不成立；不一致的项全是"无法判断 / 未建立"时记无法判断。
- 安装：日志出现 `CLEAN_WHEEL_ACCEPTANCE_OK` 记成立。
- 回归：逐行比较全部一致记成立；有差异逐项列出并记不成立。

全部失败、未知、条件性结论和人工介入都保留在结果里，不重跑覆盖。
