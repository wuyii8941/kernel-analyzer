# 纸面数值估计、高精度重算与本工具：三方对照（2026-10-16）

数值分析给出偏差的规律，但规律要有前提：每个运算落到哪条指令、归约按什么次序、哪些乘加被融合、张量核怎样转换与累加、
次正规数是否冲零。这些前提只存在于实际编译出来的 kernel 里。本实验在 23 个真实模型的 2120 个真实 Triton kernel 上
比较三种做法：

- A：按教科书前提作数值估计；
- B：用高精度重算测出总偏差；
- C：本工具。

协议在运行之前登记（[protocol.md](protocol.md)，提交 287b868），偏离 D1–D7 都在运行中先记录、后继续。

## 结论

1. **只换前提，估计就错。** 在真值有显著系统偏差的 644 个输出上：
   - A 在同一份数据上精确执行（纸面估计能达到的上限），符号对的只有 19%，符号与大小都对的只有 4%；
   - 零均值的概率模型（A0）一个也说不中；
   - 本工具按 kernel 的真实前提精确执行，符号与大小 100% 正确；
   - 本工具的事前预测器不运行 kernel，符号对 95%。
2. **A 的错误几乎都能归到某一个前提上。** A 的 673 处错误中，662 处（98%）只换一个前提就能复现：
   - 张量核：539 处，tf32 是截断不是就近；
   - 归约次序：92 处，教科书按顺序求和，实际是树形；
   - 近似指令：53 处；
   - 乘加融合：19 处。
3. **高精度重算测得准总量，但只能测总量。** 植入集上：
   - 对任务参照重算（B-f）只给出总偏差，分不出数值与语义；
   - 对 kernel 程序重算（B-G）完全看不到语义错误；
   - 两者都不能定位、不能预测改法效果、不能在运行前预测。
4. **本工具能拆分、定位并预测改法。**
   - 7 个语义植入全部判不一致，2 个数学上等价的阴性对照判一致；
   - 数值植入的归因首位 4/4 是植入行；
   - 236 处真实改法在设备上改写并重放：改掉 C 归因的首位后偏差减半的占 84%，C 事先预测的改后偏差与实测一致的占 94%。
5. **局限要说清。**
   - 显著偏差的 84% 来自 tf32 矩阵乘；不算矩阵乘，A 对 38%，事前预测器对 62%，精确执行仍是 100%。
     事前预测器在归约类 kernel 上明显弱于矩阵乘。
   - 事前预测器在真值无显著偏差的输出上误报 13.7%，超过登记的上限 10%（H2 不成立），集中在 mamba 的扫描 kernel
     与 LayerNorm 类统计量上：预测器会高估一部分小偏差。
   - 数值与语义的拆分按登记的严格口径不成立（H4）：有两个语义植入同时改变了数值路径，数值偏差的变化超过 3 个标准误，
     但仍在 10⁻⁸ 量级。

## 三种方法

| | 做什么 | 本实验里的实现 |
|---|---|---|
| A 纸面数值估计 | 按教科书前提估计 kernel 的系统偏差 | A0：舍入误差均值为零的概率模型，预测恒为 0；A-exec：同一个 kernel、同一份输入，在仿真器里把五个前提全部换成教科书前提后精确执行；另有五个「只换一个前提」的消融 |
| B 高精度重算 | 用 fp64 或精确算术把同一个计算再算一遍，与设备输出相减 | B-G：kernel 声明的程序本身的高精度值，对 B 最有利，要有能执行 kernel 程序的解释器；B-f：任务参照的高精度值，即常见做法，在植入集上有定义 |
| C 本工具 | 读出编译产物里的前提，再套用数值分析 | C-exec：真实前提下的精确执行（仿真器）；C-model：事前预测器，不运行该 kernel；归因到源码行；改法的反事实；与任务参照的语义比较 |

五个教科书前提与它们在编译产物里的真实对应：

| 教科书前提 | 编译产物里的事实 |
|---|---|
| 近似指令按 IEEE 正确舍入 | `div.full`、`ex2.approx`、`rsqrt.approx`、`sqrt.approx`、`sin.approx` 等有系统误差 |
| 不做乘加融合 | LLVM 把乘法与加法收缩成 `fma`，包括消去 `0 + x·x` 后把未舍入的平方融进求和 |
| 求和从左到右 | 归约按布局：线程内顺序、warp 内蝶形、warp 间经共享内存 |
| 张量核就近舍入 | tf32 操作数向零截断到 11 位，分组累加也截断 |
| 次正规数不冲零 | libdevice 与近似指令的 FTZ 路径 |

A-exec 与 C-exec 都是精确执行，差别只在前提，所以两者之差完全来自前提。

## 局限

- 每个模型只保留前 2 层（gemma-4 除外），一次训练步，128 个 token 的 wikitext 输入，两种精度配置。别的输入分布、
  序列长度和 batch 下，偏差的大小与符号可能不同。
- kernel 全部来自 Inductor 生成的代码：逐元素、归约、持久归约与矩阵乘模板。手写的库 kernel（Liger、FlagGems、
  flash attention 等）只在已有案例里出现。
- 只覆盖 Triton 3.6.0 / sm_86。别的版本与架构下，前提可能不同，这恰好是本实验要说明的问题，但这里没有测。
- 真值是统计意义上的系统偏差（对齐量加 3 倍标准误）。很多偏差远小于输出格式的单位舍入，只说明方向与大小，
  不说明是否值得修。
- A-exec 只替换了五个前提。纸面分析可能还会作出别的假设（例如误差独立、只看最坏界）；这里用的是对 A 最有利的
  实现：在真实数据上精确执行。
- 改法验证只覆盖登记的机制（tf32、近似除法、rsqrt、sqrt、exp）。归约次序、sin/cos 近似等首位位点没有一行能改的
  写法或不在登记清单里，只记录不改。

的 LayerNorm 类 fp32 统计量上：预测器预测 −5×10⁻⁹ 到 −9×10⁻⁹ 的偏差，真值约为 0，C-exec 与真值一致。去掉 mamba，
误报率仍是 10.4%。预测器会高估一部分小偏差。

几个典型：

- **tf32 矩阵乘**（540 个显著输出）：
  - 设备输出系统性偏小，例如 gpt-neo 注意力里的一个批量矩阵乘为 −7.5×10⁻⁴，反向的权重梯度矩阵乘为 −7.1×10⁻⁴；
  - A 把 tf32 当成就近舍入，预测偏差在 10⁻⁵ 量级；
  - 从 bf16 检查点加载的权重在 tf32 中是精确的，所以截断只作用在激活上，A 看不到这一点。
- **RMSNorm 的 rstd**（fp32 统计量）：
  - 设备上的平方和按树形归约，偏差约 +2×10⁻⁸；
  - A 按顺序求和，预测 −6×10⁻⁷，方向相反、大 25 倍。
- **LayerNorm**：
  - 均值与方差的除法是 `div.full`，rstd 是 `rsqrt.approx`，偏差约 −3×10⁻⁸；
  - A 把它们当成 IEEE 运算：做了改法验证的 77 个这类输出中，真值 75 个为负，A 有 51 个预测的符号相反。

  个标准误以内」。改 eps 或除数也改变了数值路径，数值偏差从 −2.5×10⁻⁸ 变为 −1.5×10⁻⁸、从 −1.8×10⁻¹⁰ 变为 −4.1×10⁻⁸。
  两者仍远小于各自的语义偏差（5×10⁻⁴、2×10⁻³）。这条判据定得过严，照登记报告。

## 结果三：定位与改法

236 处在设备上真改并重放（另有 66 处首位位点没有登记的改法，3 处出错）。

| 机制 | 个数 | 改掉首位位点后偏差减半 | C 的改后预测一致 | 改法效果（改前 − 改后）：C 预测在 10% 内 | 同上：A 预测 |
|---|---|---|---|---|---|
| tf32 矩阵乘 → `input_precision="ieee"` | 159 | 159 | 159 | 159 | 1 |
| 近似除法 → `div_rn` | 43 | 20 | 39 | 40 | 18 |
| rsqrt.approx → `div_rn(1, sqrt_rn(x))` | 34 | 20 | 24 | 27 | 16 |
| 合计 | 236 | 199（84%） | 222（94%） | 226（96%） | 35（15%） |

- 「改法效果」一栏未登记，是看到 tf32 的结果后补的描述量。原因是登记的「改后值一致」对 A 不公平地有利：
  - 改完后偏差本来就接近 0，A 一直认为偏差接近 0，所以 A 的改后值有 172/236（73%）「一致」；
  - 但 A 认为这处改动几乎没有效果。tf32 上 A 估计改前偏差在 10⁻⁵ 量级，实际是 −3×10⁻⁴ 到 −7×10⁻⁴。
- 近似除法与 rsqrt 的改法中，约一半偏差没有减半：除法改掉后，偏差还有别的来源。C 的改后预测在这些情形下仍然
  多数一致（39/43、24/34），即 C 事先知道「只改这一处不够」。
- 没有登记改法的首位位点：
  - 归约次序 20 处；
  - 普通 fp32 加法、乘法、减法共 21 处；
  - cos 与 sin 的近似指令 20 处；
  - libdevice 函数 5 处。
- 出错 3 处：两处是改法脚本对首位行的索引错误，一处读取捕获文件时报文件损坏。
- 改法验证不限于逐位相同的单元。近似除法的 43 个里，原单元有 37 个本来就没通过逐位核对：LayerNorm 类 kernel 里
  还有仿真器没有覆盖的下降方式，原因未查。改后启动的核对状态与原单元基本一致。真值 K − G 与 K′ − G′ 不依赖仿真器，
  不受影响；C 的归因与改后预测用的是仿真器，在这些单元上仍有 39/43 一致。
- 按偏离 D6，tf32 的改法每组「模型 × 配置」最多 4 个；mamba 扫描 kernel 中 10 个输出的改法验证在报告写成时未完成。

## 偏离

协议执行中先记录、后继续的偏离（详见 [protocol.md](protocol.md) 末节）：

| | 内容 |
|---|---|
| D1 | 仿真器的缺口：消去 `0 + x·x` 后、或把行掩码 select 挪到线程内部分和之后，LLVM 把未舍入的平方融进求和。已修复（先写失败的测试，提交 9ed6b13）；全部单元用修复后的代码重跑，修复前混合版本的部分结果作废。逐位核对未通过的单元另作补充分析 |
| D2 | 交叉熵的阴性对照换成两个数学上等价的单行改写（原计划在多 kernel 拆分后不等价） |
| D3 | 单元素输出（标量损失）不分类，单独列出 |
| D4 | program 抽样加输入工作量上限（2²³ 个输入元素），受影响的单元重跑 |
| D5 | 9 个模型的权重从 Hugging Face 下载；gemma-4 与 Ministral-3 用 transformers 5 环境；gemma-4 保留全部层 |
| D6 | tf32 矩阵乘的改法验证每组「模型 × 配置」最多 4 个（已完成的 103 个全部一致之后定下） |
| D7 | 列单元目录的模式漏掉了序号 ≥ 100 的 234 个单元（granite fp32、mamba bf16），用同一份代码补做 |
