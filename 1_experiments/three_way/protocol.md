# 纸面数值估计、高精度重算与本工具：三方对照（协议，2026-10-16，运行之前登记）

## 1 要回答的问题

数值分析给出偏差的规律，但规律要有前提：每个运算落到哪条指令、归约按什么次序、哪些乘加被融合、张量核怎样转换与累加、
次正规数是否冲零。这些前提只存在于实际编译出来的 kernel 里。本实验在许多真实模型的真实 kernel 上检验三件事：

1. 只换前提、其余完全相同时，按教科书前提算出的偏差是否会错，错多少，错在哪个前提上；
2. 高精度重算能测准总偏差，但做不到哪些事；
3. 本工具能否给出：偏差的符号与大小、数值与语义的拆分、源码行、改法效果的预测、运行之前的预测。

## 2 三种方法

**A 纸面数值估计**：按教科书前提估计 kernel 的系统偏差。两种实现：
- **A0 概率模型**：舍入误差均值为零、彼此独立（Higham–Mary 的概率误差分析），预测的系统偏差恒为 0。
- **A-exec 教科书前提的精确执行**：同一个 kernel、同一份输入，在工具的仿真器里把五个前提全部换成教科书前提后精确执行
  （`2_tool/src/kernel_analyzer/reference_eval/premises.py`）：
  - 近似指令按 IEEE 正确舍入；
  - 不做乘加融合；
  - 求和与前缀和从左到右；
  - 张量核把 tf32 操作数就近舍入，乘积精确，fp32 从左到右就近累加；
  - 次正规数不冲零。

  它保留声明的程序、类型与就近舍入，只是不读编译产物。在同样的前提下，纸面推导不会比在真实数据上精确执行更准，
  所以 A-exec 是纸面估计能达到的上限。
- **A 的逐前提消融**：五个前提每次只换一个（A-functions、A-fusion、A-order、A-tensor_core、A-subnormals）。

**B 高精度重算**：用 fp64 或精确算术把同一个计算再算一遍，与设备输出相减。两种：
- **B-G**：kernel 声明的程序本身的高精度值。它需要一个能执行 kernel 程序的解释器，这个解释器本身属于本工具，
  所以 B-G 是对 B 最有利的设定。fp64 与精确值的差在这里可忽略，B-G 的数值记为 K − G；
- **B-f**：任务参照（kernel 应当计算的函数）的高精度值，即常见做法。只在第 6 节的植入集上有定义。

B 只测量，不预测、不定位，也不给改法。

**C 本工具**：
- **C-exec**：读出的真实前提下的精确执行，即仿真器本身；
- **C-model**：事前预测器（`bias_predict`），不运行该 kernel；
- 归因：每个舍入位点逐个设为精确时的贡献，对到源码行与机制；
- 改法的反事实：该位点换成正确舍入的实现之后的偏差（仿真器 `substitution="rn"`）；
- 语义比较：G 与任务参照 f 的差（第 6 节）。

## 3 kernel 总体

- **模型**：`/data1/tzh/models` 下全部有权重、能在 liger 环境（torch 2.10、Triton 3.6.0、transformers 4.57）里按 CausalLM、
  MaskedLM 或 Seq2SeqLM 加载的模型。加载或编译失败的如实记录，不替换。只保留前 2 个 Transformer 层（真实权重），
  以及嵌入层和输出头。
- **输入**：wikitext-103 验证集文本（`.cache/three_way/data/wikitext103_validation.txt`，SHA-256 前缀 8ef749789ca06934）
  的前 128 个 token，用各模型自己的分词器。
- **配置**：
  - bf16：权重 bf16，不用 autocast；
  - fp32tf32：权重 fp32，允许 TF32，Inductor 用 Triton 模板生成矩阵乘（`max-autotune-no-cudagraphs`，
    `max_autotune_gemm_backends="TRITON"`）。
- **单元**：一次编译过的训练步（前向加反向）里，每个不同 kernel 的第一次启动。张量拷贝超过 512 MB 的启动不保存，记为
  「因大小跳过」。
- **program**：均匀抽取，含首尾两个，累计到约 32768 个已求值元素或 256 个 program 为止（先到者）；不足时全部 program。
  每个 program 写多少元素，按最大的输出张量元素数除以 program 数估计（Inductor 的块大小写在源码里，不是参数）。

排除（计数报告，不替换）：逐位核对不是 bit_identical 的单元，不进入真值比较；只有整数输出的单元；共同元素集合为空的输出。

## 4 真值与分类

- **真值**：设备输出 K 与声明程序精确值 G 的对齐 a = ⟨K − G, G⟩ / ⟨G, G⟩，标准误 se 由逐元素乘积计算。所有方法都在同一个
  共同元素集合上比较：已写入、G 有定义、K 有限、全部 7 次仿真都已建立。
- **类别**：a > 3·se 为正，a < −3·se 为负，其余为无显著偏差。每个仿真按自己的 a 与 se 用同一规则分类；
  C-model 用预测器自己的噪声标准误；A0 恒为无显著偏差。
- **分层**：输出类型（f32 与 bf16 / f16）、配置、kernel 类型（逐元素、归约、持久归约、矩阵乘模板），以及 |a| 是否超过
  输出格式的单位舍入。

## 5 指标

1. **符号**：预测类别与真值类别相同的比例。
2. **大小**（真值有显著偏差时）：|预测 − a| ≤ 3·√(se_a² + se_p²) + 0.1·|a| 的比例（与审查入口的「预测一致」相同）。
3. **数值与语义能否分开**：第 6 节植入集。
4. **能否定位到行**：第 6、7 节。
5. **改法效果的预测**：第 7 节。

另报：A-exec 每一处错误由哪个前提造成（只换该前提就复现同向的错误）。

## 6 植入集（语义与定位）

在 fp32tf32 配置下的真实 kernel 源码上逐行植入，用捕获的输入重放：
- **语义植入**（f 取原 kernel 的精确值 G）：
  - RMSNorm 的 eps 常数改为原值的 10 倍；
  - 均值的除数 N 改为 N − 1；
  - RoPE 中 rotate_half 去掉取负；
  - SiLU 门控去掉 sigmoid 因子；
  - 交叉熵里减去的行最大值改为减去 0（数学上等价，作为阴性对照，应判一致）。
- **数值植入**（定位的已知答案）：在 3 个 kernel 的一个 fp32 中间量上插入 bf16 往返转换，记下行号。

对每个植入：
- C：报告 G′ − f（语义）与 K′ − G′（数值），以及归因的首位源码行；
- B-f：报告 K′ − f；
- B-G：报告 K′ − G′；
- A：报告教科书前提下的归因首位。

## 7 改法验证（定位与改法预测）

- **范围**：真值有显著偏差的 fp32 输出，其 C 归因的首位位点属于下列机制之一：
  - tf32 dot：改为 `input_precision="ieee"`；
  - 近似除法：改为 `div_rn`；
  - rsqrt.approx：改为 `div_rn(1, sqrt_rn(x))`；
  - sqrt.approx：改为 `sqrt_rn`；
  - ex2.approx（exp 与 exp2）：改为 libdevice 的 `exp` / `exp2`。

  归约次序没有一行就能改的写法，不做改法验证。
- **做法**：改写 kernel 源码，用捕获的输入在设备上重放，测改后的 a′。
- **比较**：C 在改之前给出的预测（该位点换成正确舍入）与 a′ 比；A 的预测（教科书前提下同样的反事实）与 a′ 比。
- **一致**：|预测 − a′| ≤ max(3·se, 0.1·|a|)。
- **定位**：改掉首位位点后，|a′| ≤ 0.5·|a|，算定位正确。

## 偏离

- **D1（2026-10-16，正式分析之前）**：逐位核对未通过的单元，加一个补充分析。
  - 原因：Qwen3 的 fp32 试跑中，Inductor 的 RMSNorm kernel 在 16 行里有 1 行差 1 个 ulp。机制是仿真器的缺口：
    归约循环只执行一次、累加器初值为 0 时，LLVM 消去 `0 + x·x`，把未舍入的平方直接融合进线程内求和
    （PTX 中的 `fma.rn.f32` 链），仿真器则先把平方舍入再求和。
  - 做法：真值 K − G 不依赖仿真器，所以这些单元仍有真值。它们进入补充分析，比较 A-exec、A 的逐前提消融与 C-model；
    C-exec 不参与。主分析与 H1–H6 的判定照登记，只用逐位相同的单元。
  - 这个缺口另作工具修复（先写修复前失败的测试）。修复后是否重跑受影响的单元，在汇总前决定，并在此记录。
  - **修复与决定（同日，汇总之前）**：
    - 缺口有两种形态，都已在仿真器中修复，测试见 `2_tool/tests/test_emulate_single_trip_reduce.py`，3 项测试修复前失败、修复后通过：
      - 累加器为 +0 时，LLVM 消去 `0 + x·x`，未舍入的平方被下一次加法或归约融合；
      - `sum(where(c, x·x, 0))` 中 c 沿归约轴不变时，LLVM 把 select 移到线程内部分和之后。
    - 回归测试：仿真器、组合规则、教科书前提、审查入口共 63 项通过。Qwen3 的三个 RMSNorm 单元由不一致变为逐位相同。
    - 修复时，第一次正式分析与植入正在运行，各单元的进程会读到改动前或改动后的代码。为保持一致，全部单元与植入用修复后的
      代码重跑；修复前已写出的 72 个单元与 12 个植入结果作废，不进入结果（存于 `.cache/three_way/results_pre_fix/`）。
- **D2（2026-10-16，植入运行之前）**：交叉熵阴性对照换成两个数学上等价的单行改写。
  - 原因：Inductor 把交叉熵拆成几个 kernel，NLL kernel 读的是前一个 kernel 算好的行最大值 m 与 log-sum l。
    只在这一个 kernel 里把 m 改成 0，数学上不等价，登记的「减去 0」做不成单 kernel 的等价改写。
  - 改为：
    - 交叉熵 NLL kernel 中 `x − m − l` 改为 `x − (m + l)`；
    - RMSNorm 均值 `s / N` 改为 `s · (1 / N)`（N = 3072，不是 2 的幂，数值上不同）。
  - 两者都应判一致。
- **D3（2026-10-16，汇总之前）**：只有 1 个元素的输出不参与符号与大小的分类，单独列出。
  - 原因：这类输出主要是整个训练步的标量损失。n = 1 时按公式标准误为 0，任何非零误差都会被判为「显著偏差」，
    但一次舍入谈不上系统偏差。第 4 节的分类在这里没有意义。

    - 其余未显著：预测器在这里报出显著偏差，只称为「未显著输出上的报出率」，不称为误报；
  - 预测器弃权（状态为「无法判断」）的输出照实计数，另报把弃权算作错误时的比例。
  - 补记（看过上面两部分的计数之后、做下面这个划分之前）：「其余未显著」上的报出再分两部分：预测的 |a| 超过真值的 3·se
