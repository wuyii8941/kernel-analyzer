# 超越 Tolerance：怎样判断一个训练算子的数值误差会不会形成 bias，并影响 loss

# 第一部分：问题是什么

---

## Slide 1｜问题

模型训练测试中通常比的是：两个结果差多少？差得小就通过。output, 权重，gradient，loss等组成

但在训练里还要问另一件事：**这些差异的正负最终会互相抵消，还是会形成有方向的偏差？**

一个比较大但方向来回变的误差，可能只是多一点噪声。一个小得多但反复朝同一边的误差，可能被训练不断写入参数。

今天不是要否定 tolerance。它很适合抓明显的数值错误。我们要补的是它没回答的那一半：

> **正负误差经过真实训练路径后还能不能抵消？如果不能，这个 bias 会不会进一步造成 loss 分叉？**

所以后面的证据分成两层：

- **第一层（Bias formation）**：抵消是否被破坏
- **第二层（Bias consequence）**：在配对长程实验中，candidate 和 repair 是否出现 loss 分叉

## Slide 2｜起点：FlashAttention 的教训

这个问题来自一个真实的训练崩溃。

FlashAttention 和标准 attention 在数学上完全等价，但改变了分块和累加顺序。在 BF16（一种 16 位浮点格式，精度低但速度快）下，某些累加模式让舍入误差**反复偏向同一侧**——不是有正有负，是单边的。

这个偏差经过反向传播，每一步给参数推一点点。多步之后，参数明显偏离，训练崩了。

**修复方式**：只改掉触发单侧舍入的那个局部条件，训练就重新稳定了。说明找到的是原因，不只是相关。

这篇工作（Qiu & Yao, ICLR 2026）最重要的启示是：

> **误差小不代表安全，数学等价不代表训练行为等价。我们关注的是bias，而非噪声或者方差导致的偏差。**

Golden et al. (2024) 也做过类似的 matched implementation 对比，追踪了 FlashAttention 的权重发散。但他们自己写明只测了单次前向、只测了 attention。**这两条限制正好是我们要补的**——我们要覆盖真实反向、覆盖优化器、覆盖一个训练步里的所有算子。

## Slide 3｜训练是一个有状态的循环

不熟悉训练的听众只需知道四步：

- **前向**：模型读输入，经过矩阵乘法、归一化、激活函数等算子，得到预测
- **算 loss**：预测和正确答案差多远
- **反向**：从 loss 倒着算，得到每个参数应该怎么调（梯度）
- **优化器**：结合当前梯度和历史状态，决定真正写入参数的更新量

一个局部差异要影响参数，必须穿过整条链：

```
算子误差 forward → backward → gradient → optimizer → parameter update → 下一步状态改变
```

两条轨迹一旦分开，下一步的状态也不同，后续还会产生反馈。

**训练不是一次函数调用，是一个有状态、带反馈的循环。**

【图 · Slide 2 · 重要】画一个训练循环的完整示意图：五个方框（forward → loss → backward → optimizer → parameter update）形成一个环，最后一步用箭头回指 forward 表示"进入下一步"。在"算子误差"处标一个红点，然后用虚线追踪这个红点穿过每一步，直到写入参数。**这张图贯穿全篇，后面每讲到链条的某一段都可以回指它。**

# 第二部分：核心定义

---

## Slide 4｜Cancellation Preservation：平均方向来自两项

理想情况下，+ε 和 −ε 出现得一样多，经过训练路径后对参数的影响互为相反。

**安全不要求误差为零。安全要求正负误差经过真实训练路径后还能互相抵消。**

我们把这个叫 **Cancellation Preservation**（抵消保持）。

在我们预先选定的误差边界上，最终平均 update 可以精确拆成两项：

**第一项：正负误差事件或配对不平衡**

理想是 +ε 和 −ε 出现得一样多，碰到相似的训练状态。实际可能出现：

- 固定累加顺序让舍入偏向一侧
- 量化网格、截断、饱和、underflow 或 scaling 让一侧更常出现
- 正负误差分别碰上不同的反向状态
- forward 保存值和 backward 使用值之间的合同差异

代表案例：**Liger**（BF16 分块累加造成单侧方向）、**Phi**（误差和反向状态的固定配对造成梯度方向）

**第二项：正负响应不对称**

即使人为构造了严格相反的 +ε / −ε，经过反向或优化器后，参数更新也可能不再互为相反数。

代表案例：**saved-P** 和 **SiLU**（对严格相反的梯度残差重放，观察到优化器的非对称响应）

| 形成项 | 工程上的表现 |
|---|---|
| 正负事件或配对不平衡 | 累加顺序、量化/截断/饱和、舍入事件分布、backward 配对、forward/backward 状态合同差异 |
| 正负响应不对称 | 非线性 backward、optimizer 的非奇对称响应 |

这两项是所选误差边界上的精确分解，不是所有底层浮点成因的穷尽清单。同一种实现机制也可能同时影响两项。

## Slide 5｜两项形成路径怎样落在训练链上

回到 Slide 2 那张训练循环图。把两项形成路径标在链条上：

```
实现与数据 → 局部误差事件 (ε, state)
                    │
                    ├─ 第一项在这里：+ε / −ε 的事件数量或配对不公平
                    ↓
          backward / optimizer response
                    │
                    ├─ 第二项在这里：R(+ε) + R(−ε) ≠ 0
                    ↓
          parameter update difference
                    │
                    ├─ 低秩：只描述"偏差长什么样"
                    ↓
           后续训练反馈：放大、保留或压制
```

当我们发现一个训练产生Bias，我们需要回答的三个问题是:

1. **Formation**：平均方向主要从哪一项形成？
2. **短程证据**：16/32 步里能否测到方向，用于机制定位和实验排序
3. **长程复核与后果**：4096 步后半程 bias 本身是否仍有方向，并且配对实验中是否出现参数和 loss 分叉

## Slide 8｜怎样测短程方向

在同一个训练状态下，只替换一个声明的实现边界，记录第 t 步真正写入参数的更新差异 u_t。

定义方向分数：

$$A_T = \frac{\|\sum_{t=1}^{T} u_t\|}{\sqrt{\sum_{t=1}^{T} \|u_t\|^2}}$$

每一步，我们记录 candidate 和 repair 对目标参数造成的更新差。然后用一个离线随机对照：保持每一步差异的大小和形状不变，只随机把整步差异看作正向或反向。重复很多次，就得到“如果这些误差只是随机抵消，累计方向应该有多大”的基线。真实结果明显超过这个范围，就说明这些更新差不是随机游走，而是在反复朝相似方向推动参数。

每个案例都和**自己的随机基线**比（把每步更新方向随机翻转），不用一个固定阈值。

| 扰动 | 方向分数 | 一句话 |
|---|---:|---|
| 每步注入同等大小的随机干扰（5 种子） | 0.87–1.04 | "纯随机"在这把尺子下的样子 |
| 换数据顺序 | 0.007 | 同一组 batch 用完后几乎抵消 |
| **单个算子实现差异** | **4.701** | 远超随机 |


---

## Slide 9｜第一项 的例子：Liger 的正负事件从源头就不平衡

我们往 Liger 的输入里加了数学上完全无效的零行——loss 不变、有效梯度不变，但物理上的 chunk 分组变了。

| 累加精度 | 结果 |
|---|---|
| BF16 累加器 | 24 个状态里 **24 个同向**，sign-test p = 5.96×10⁻⁸ |
| FP32 累加器 | 13 比 11，方向不再一致 |

> 数学没变。**低精度累加和固定分块的组合**造成了正负事件的不平衡。

这是第一项 最直接的例子。

---

## Slide 10｜第一项 的例子：Phi 的问题是误差和反向状态的固定配对

Phi `lm_head dX` 的局部误差本身方向不强（A ≈ 2.07），但经过反向传播后，梯度方向分数跳到了 4.70。

**关键干预**：保留所有误差的大小和所有反向状态，**只打乱"哪个误差碰到哪个反向状态"**。结果方向消失了。

> 不是误差自己有方向，是**误差和反向状态的固定配对**制造了方向。这说明 formation 的关键不在单看局部误差大小。

---

## Slide 11｜第二项 的例子：严格相反的误差也可能得到不相反的更新

为了直接检测响应是否保持对称，我们固定相同的权重、优化器状态、输入和随机种子，分别重放 +δg 和严格的 −δg。

如果响应对称，应有 F(+δg) = −F(−δg)。

我们拆出偶部 [F(+δg) + F(−δg)] / 2。对称响应下应该为零。

| 案例 | 观察 |
|---|---|
| **saved-P** | even response 非零，约为自然 response 的 0.677 倍 |
| **SiLU** | even response 非零，约为自然 response 的 0.693 倍；SGD 下为线性 null（如预期） |

> 输入严格正负对称，但优化器输出不是。这就是第二项。

---

## Slide 12｜为什么优化器必须进入测试

优化器不是第三个形成项，但**真正写进参数的是优化器的输出**。优化器是映射的一部分，正好处在第二项 的检查位置。

Qwen 的短程结果最直观：

| 看哪一步 | 方向分数 |
|---|---:|
| 参数梯度 | 1.343 |
| AdamW 实际更新 | 0.961 |

如果只看梯度，会说"有方向"。看真正写进参数的更新，这个窗口里**方向没了**。

三个案例的对比：

| 案例 | 梯度方向分数 | AdamW 更新方向分数 | 结论 |
|---|---:|---:|---|
| Liger | 2.838 | **1.681** | 减弱但仍持续 |
| Phi | 4.683 | **1.030** | 大幅削弱，剩一点 |
| Qwen | 1.343 | **0.961** | 消掉了 |

> 优化器可以保留方向、削弱方向、也可以消掉方向。**所以检查必须做到实际参数更新，不能在梯度处停下。**

---

## Slide 13｜只改 numerical source，bias 就消失了

前面我们已经看到：数值误差经过真实训练路径后，可能形成有方向的参数更新。

但这里还有一个更关键的问题：

这个方向真的是 numerical implementation 本身造成的吗？

我们在 Phi lm_head dX 上做了一个最小干预。

保持完全相同的：

32 个训练状态
参数
backward 路径
AdamW 配置

唯一改变 BF16 的舍入方式。

原实现使用确定性舍入：相同的数值条件会按照固定规则选择相邻的 BF16 值。

我们把它换成 stochastic rounding：数值误差仍然存在，但不再总由同一条确定性规则决定误差落在哪一侧。

实现	是否超过自己的随机基线	误差是否仍然存在
原始确定性 BF16	是	是
空操作对照	是	是
stochastic rounding，4 个 seeds	0 / 4	是

四个 stochastic-rounding 重复全部回到了各自的随机抵消范围。

更重要的是，前三个重复的误差能量与原实现基本相当，其中部分甚至更高。也就是说，方向消失不能简单解释成“误差变小了”。当前讲稿里的原始六臂结果正支持这一点。

我们没有消除 numerical error。我们只改变了误差产生的方式，原来的方向就消失了。

这给出了一个因果闭环：

确定性的 numerical behavior
            ↓
     参数更新形成方向
            ↓
只改变 rounding rule
            ↓
      方向消失

这也和开头 FlashAttention 的思路呼应：FlashAttention 的关键不是把所有浮点误差降到零，而是定位到会反复产生单侧偏差的数值条件，并通过局部修改消除它。

# 第四部分：Oracle 与训练后果

---

## Slide 14｜Oracle idea：先检查根因，再检查后果

目前不存在一个已验证的通用 Oracle，所以这里讲的是一个 idea，不是成品。

**Probe A — 配对公平性**：保留误差和训练状态的边际量，只打乱配对。自然配对有方向 + 打乱后消失 → 支持第一项。（Phi 的干预是现有实例。）

**Probe B — 响应对称性**：固定 state/weights/moments，重放严格 +δ / −δ。F(+δ) + F(−δ) ≠ 0 → 支持第二项。（saved-P 和 SiLU 是现有实例。）

**Probe C — 短程排序**：用 A16/A32 决定先深测谁。

**Reduction 专用候选量 — orbit mean**：只对 reduction / summation / reassociation，冻结多种数学等价的 chunk/reduction schedules，检查它们相对高精度结果的平均 residual。它需要多次 schedule replay，不是一次 forward 的静态 Oracle，也不能覆盖 backward 或 optimizer。Liger 上将预先预测：BF16 orbit mean 与 local-stage 平均方向对齐，换 FP32 accumulator 后二者同步下降。

```
Probe A / B（定位形成项）
        ↓
A16 / A32 短程排序（决定优先级）
        ↓
配对长程实验（检查训练后果）
        ↓
bias only / bias + loss 分叉 / 未决
```

> Oracle 的创新不在造一个更复杂的分数，在于把问题分成两层：先定位抵消为何失效，再检查 bias 是否进入 loss。

---

## Slide 15｜长程后果对照：有 loss 分叉，但 bias 组件没有持续

案例地图回答了"哪里形成了 bias"。这一页回答另一件事：

> **有些配对实验确实出现了参数和 loss 分叉，但 4096 步后半程没有持续的 bias 组件。它们是后果对照，不是持久性 bias 案例。**

| 案例 | 早期形成证据 | 4096 步 bias 组件 | 配对后果 |
|---|---|---|---|
| Qwen seq64 v_proj | 条件源不对称 | A=0.993，未稳健保持 | 参数距离 0.220；后 512 步平均 loss gap +0.00410 |
| Qwen v_proj | 局部算术/配对 bias | A=0.981，未稳健保持 | 参数距离 0.302；后 512 步平均 loss gap −0.000615 |
| Qwen saved-P | 响应/状态合同不对称 | A=1.195，p=0.084，未过持久门 | 参数距离 0.123；后 512 步平均 loss gap −0.000150 |

这里的"loss 分叉"指：在声明的 4096 步受控配对实验中实际记录到 loss gap；它不等于证明两条完整训练轨迹会收敛到不同最优点，也不能替代 bias 本身的持久性证据。

Liger 和 lm_head dX 家族同时有 bias 和 loss 分叉，但它们已属于更强的 direct 子集，不在此重复。

---

## Slide 16｜反馈决定差异怎样长大，但不是根因

两条轨迹一旦分开，后续 weights、gradient、optimizer state 都不同。即使目标算子某一步几乎抵消，反馈也可能维持轨迹距离。

类比一个持续的小内存泄漏：每次只泄漏几字节，泄漏是真的。但最终 OOM 的大部分内存不是那行代码直接分配的——是系统状态的级联。**泄漏是触发器，级联是放大器。**

用 Liger 来说：**它的直接作用只占最终参数分离的 0.46%，但它是唯一持续的那部分。**不拆开看就会把 99.5% 的反馈也归给这个 kernel。

我们从 32 个可达记录中盲抽了 12 个跑完整轨迹——**11 个的权重最后都变了**。原因就是反馈放大，和算子是谁没关系。

> **"最后权重变了"不能反推目标算子持续朝同一边推。**形成和放大必须分开归因。

## Slide 16｜同一个实现差异，换参数位置结果就不同

同一个 Phi `lm_head dX` 的误差传到 12 个参数位置（1 个已知 anchor + 11 个结果盲选）：

| 参数位置 | 方向分数 |
|---|---:|
| final norm | **4.488** |
| layer 31 post-attention norm | **2.321** |
| layer 25 input norm | **2.226** |
| layer 8 post-attention norm | 1.192 |
| layer 16 post-attention norm | 1.033 |
| layer 12 input norm | 0.940 |
| layer 6 input norm | 0.578 |

> 测试对象不能只是"某个 kernel"。它得绑定：具体模型 + 具体调用 + 真实 backward + 参数位置 + 优化器。

（单参数受控实验，不是全参数训练。）

## Slide 17｜怎样用于真实开发流程

编译器 / kernel library / GPU backend 更新时：

```
找出实现变化的 forward + backward 路径
        ↓
过滤差异为零或到不了参数的
        ↓
构造最小修复和空操作对照
        ↓
第一层：bias formation
  检查事件/配对公平性 + 响应对称性
        ↓
用 A16/A32 排序后续实验优先级
        ↓
第二层：配对长程实验
  记录参数距离和 loss gap
        ↓
输出：bias only / bias + loss 分叉 / 反馈主导 / 未决
```

两个工程价值：
- **发现传统方法漏掉的**：误差很小，但正负组织不公平
- **避免错误拒绝高性能实现**：误差较大，但参数更新仍能抵消

> 交付的不是坏算子名单，而是**"先确认 bias，再检查是否进入 loss"的两层评估流程**。

## Slide 18｜结论

**第一**：Tolerance 只回答误差有多大。我们的第一层回答：误差是否形成 bias。

**第二**：formation 归结为两项形成路径——正负事件或配对不平衡，以及正负响应不对称。低秩是几何形态，反馈是后续过程，都不是第三个形成项。

**第三**：最强的 window-confirmed bias 标签要求 bias 组件在 4096 步后半程仍持续；只有整段统计、只有反馈或只有 loss 分叉的记录都分别报告，不能混成同一强度。

**第四**：工程流程是——确认 bias 怎样形成 → 短程决定先深测谁 → 配对长程检查是否进入 loss。

> 当两个实现都通过 tolerance 时，我们先问它们是否引入 bias，再问这个 bias 是否改变了训练的 loss。
