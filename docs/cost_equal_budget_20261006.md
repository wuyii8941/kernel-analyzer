## 2. 同等预算（`scripts/equal_budget.py` → `results/external/gpuemu/equal_budget.json`）

**口径：这是指定预算与参数下的观察。** 预算取本工具在第二层的实测墙钟时间；三条基线在同一条 Python 流水线上运行（作者的
`run()`、作者的 fp64 参考、torch fp32 实现，逐种子串行）。下文的 56–775 倍是这条共享流水线下两者能处理的输入数之比，
不是两类方法固有的成本比（基线的实现若并行化，比值会更大；工具的参照求值若加速，比值会更小）。基线的参数取默认值与第一层
扫描选出的工作点，不在新预算下重新标定。

规则（运行前写在脚本说明里）：每个第二层条件的预算 = 本工具在该条件上的实测墙钟时间；三条输出层基线在同样的时间内用
新种子（96 起）运行 kernel、作者的 fp64 参考与（B3）torch fp32 实现，条件的告警 = 任一种子告警；参数取默认值与第一层
扫描选出的工作点。

| | 种子数（本工具 96） | B1 默认 / 扫描 | B2 默认 / 扫描 | B3 默认 / 扫描 |
|---|---|---|---|---|
| 植入且触发（8 个） | 7,102–59,186 | 8 / 8 | 8 / 8 | 8 / 6 |
| 控制组与未触发（14 个） | 5,395–74,428 | 0 / **1**（matmul） | **3** / **1** | **2** / 0 |
| 本工具确认平均作用而容差通过的 9 个 | 6,459–14,890 | 0 / 0 | 0 / 0 | 0 / 0 |

- 在这一预算与流水线下，基线能看 56–775 倍的输入。植入错误本来就大，多看输入不改变结论（B3 扫描后对两族注意力不告警，是
  工作点规则的结果，见外部评价结果文档）。
- **多看输入不会让幅度判定看见容差以下的平均作用**：9 个条件在 6,459–14,890 个种子上仍然全部通过。这类信息只能来自
  均值检验，与预算无关。
- **工作点在更多输入下会漂移**：B1 的扫描工作点（0.01 × tol，在第一层少量开发种子上选出）在 matmul 64×64×64 的 74,428
  个种子上产生误报；B2 的默认配置在 attention、flash_attention 与 matmul 的控制组上告警，B3 默认在两族注意力上告警。
  基线的阈值要随预算重新标定；本工具均值检验的误报率由检验水平控制，不随单位数增加（单位越多，只是对更小的作用有功效）。
- 本工具的代价：每个单位（种子）的成本是输出层基线的 56–775 倍（本工具每个种子 0.03–0.6 s，基线约 0.5–1.3 ms）。只需要发现大错误时，直接
  差分或作者的容差判定更划算；需要知道差异的来源、或需要容差以下的系统作用时，这部分代价换来的是基线在任何预算下都
  给不出的信息。
