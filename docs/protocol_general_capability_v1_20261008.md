## 0 纪律（任务书第 0 节原样执行）
「未建立」计入覆盖缺口；「未检出」不写成「没有 bias」；不扩算子名单、不逐个手写 reference、不按 kernel 名字特判；旧冻结成绩不改；
新增统计策略用独立确认数据；改变参照语义、默认统计或裁决规则时升版本并回归。

## 1 统一入口：一次声明
模块 `kernel_analyzer.measure`，命令 `scripts/measure.py --declaration D.json`。用户只写四样：

| 字段 | 内容 | 缺项时 |
| --- | --- | --- |
| `call` | 合法调用绑定：`module:function`（或文件路径 + 函数名），函数接收输入字典、返回 {输出名: 张量} | 报缺项 |
| `inputs` | 每个输入的来源：`{"sampler": 分布, "shape": [...], "dtype": ...}`，或 `{"state": "module:function"}`（由前序调用产生的状态），或 `{"const": 值}` | 每个缺 shape / dtype / 分布或来源的输入逐条列出，**不猜** |
| `compare` | 模式 A（`G` 为 kernel 自身语义）或 B（另给 `spec: module:function`）；测量点 `measure: [输出名]` | 报缺项 |
| `budget` | CPU / GPU 秒数上限、单例超时、样本上限 | 报缺项 |

自动展开（写入报告的 `expanded_declaration`，确认阶段不改）：
- **方向规则，两类分开报告、各自做 Holm**：固定均值类 R1（坐标均值，w = −1/√n）、R5（开发集学到的方向，保存后冻结）；对齐类 R2（朝零，
  w = −sign(G)/√n）、R3（缩放，w = −G/|G|）。
- **开发 / 确认切分**：开发 32 个单位、确认 64 个单位（与校准一致，`docs/statistics_calibration_20261006.md`），种子不相交；声明可减少确认
  单位，少于 n_min = 16 时判「无法判断（样本）」。
- **版本与因素**：记录 torch、Triton、GPU、工具版本、输入声明的哈希；声明中的每个因素水平（dtype、shape）单独成一个比较，不合并。
- **参照类别允许集合**：只有 `complete_composed` 进入统计；conditional / not_established 剔除并报告比例。
- **混合来源**：读到非 Triton 中间值的输出只做数值差异（e_num），不出语义结论（检测器 2.3 的上游检测）。

## 2 语义与依赖（规则注册表）
注册表 `results/general/rule_registry.json`，键为（操作、属性、类型、子区域形状），每条记：包含性论证、反例测试、负对照、状态（支持 /
声明前提下支持 / 拒绝）。本轮新增：
- **多值归约的 Welford 合并**（结构匹配：delta、权重和、select 保护的 w_b/W、均值与 M2 的更新）。实数语义取封闭形式
  W = Σwᵢ、μ = Σwᵢmᵢ/W、M2 = Σsᵢ + Σwᵢ(mᵢ − μ)²；前提 wᵢ ≥ 0（由区间判定）且 W > 0；W = 0 的行均值取决于合并顺序 → 未建立，M2 = Σsᵢ。
  在前提下封闭形式与合并树无关——这是包含性论证。区间用中心化形式计算（以浮点均值 c 为中心，Σwd² − (Σwd)²/W）。
- **通用折叠的 scan**（已有）：依据是 Triton 对 scan 合并函数可结合的要求，代码不检查结合性——在注册表中标「声明前提」，交审阅方。
- **未登记的归约合并函数**：拒绝（语义缺失），不折叠、不猜。
- 嵌套循环与分支、保存 / 读取与别名、跨启动状态、原子、位级、外部指令：以注册表现有条目为准，每条补齐论证与测试；缺测试的列为缺口。
- 按 kernel 名字特判的代码为零：由测试扫描源码中以 kernel 名做分支的语句。

## 3 参照的精度与成本
- **精确累加**：求和与点积改用误差无关变换的 K 重累加（SumK / DotK，K = 3），给出严格界 |s − ŝ| ≤ u|ŝ| + γ²ₙ₋₁... 级别的项，累加
  引入的宽度降到浮点末位；原 γₙΣ|x| 界保留为对照。
- **相关性**：同一 SSA 值在乘、减中重复出现时按单变量处理（x·x 平方、x − x = 0）。
- **缓存**：TTIR 解析按文本哈希缓存。
- **自适应工作精度**：输出元素宽度超过分辨目标时，可用精确有理 / MPFR 求值器重算（受预算约束）；本轮先报告触发比例。
- **每个家族报四个数**：完整参照率；相对宽度（宽度 / (|G| 的 ulp)）的分布（中位数、90%、最大）；达到分辨目标的比例——分辨目标默认
  为输出 dtype 在 |G| 处的 ulp 的 1/8（能分辨 1/8 ulp 的平均作用）；分段耗时（捕获 / 参照 / 统计）。

## 4 默认检测与校准
- 固定均值类与对齐类分开报告；R5 的方向只在开发集学习，确认集冻结。
- **有界路线**：输出是输入的求和或点积时，每个单位的幅度界 M = γₙ Σ|xᵢ|（n 为累加长度，u 为输出累加 dtype 的单位舍入）加输出舍入半个
  ulp；有 M 时同时报告有界检验（经验 Bernstein，单侧，α/2）；没有误差预算的片段只走近似路线（端点保守 t），结果注明「近似路线」。
- 退化（零方差）、样本不足（n < 16）、分布前提（|偏度| > 2 且 n ≤ 64，bootstrap-t 只在 n = 64 时用）→「无法判断」。
- **校准**：五类合成分布——稀疏大值、稠密小值、组内正负抵消、状态相关、稀有大尾部（每坐标 0.999 概率为 0、0.001 概率为大值）；每类
  报零效应下的误报率、注入效应下的功效、未建立（无法判断）比例，固定均值类与对齐类分开，每格 1000 次重复，确认 64 个单位，坐标 256 维。
  注入效应的大小在运行前写定：稀疏 / 稠密 / 尾部按坐标均值 0.25 个噪声标准差，抵消类为组内 ± 相同幅度（坐标均值为零，R1 不应检出，
  R2 / R3 视对齐而定），状态相关类为 −0.25·sign(G) 的朝零作用。不把几条投影「未确认」写成「向量无 bias」。

## 5 冻结与未见结构验收
第 1–4 项完成后打标签 `general-v3.0`，记录源码树哈希（`git rev-parse HEAD:src`）与依赖版本。审阅方交付的绑定与抽样器、封存的答案哈希

## 6 失败分类
每个未建立或失败归入：语义缺失（拒绝的操作 / 合并函数 / 未登记外部指令）→ 第 2 项；绑定问题（配对不可证、输出不由 Triton 写出、
混合来源）→ 第 1 项；包围太宽（宽度超过分辨目标）→ 第 3 项；超预算（超时、样本上限）→ 第 3 项；统计不足（无法判断的三类）→ 第 4 项。
分类由 `kernel_analyzer.measure.classify_failure` 按工具给出的原因字符串决定，映射表写在代码里并随报告输出。
