# 当前主线计划审计

这份审计只检查一条主线：**算子实现产生的数值差异，怎样进入梯度和参数更新，以及怎样用较便宜的指标筛选出会持续的差异。**它不再寻找一个对所有算子都成立的万能标签。

文档中的术语尽量按 LLM 训练来读：

- “参数载体”就是实际观察的一块权重，例如最后一层归一化权重；
- “同向程度”就是每一步的参数差异是否互相加强，而不是像随机噪声一样抵消；
- “matched repair”就是只替换被审计的算子实现，其余模型、输入、优化器状态和训练步完全相同；
- “闭环后果”就是把 candidate 和 repair 各自真实训练后，比较两条权重轨迹的分离。

## 已经真正完成的实验

### 1. 把一处差异拆成三段

对 Liger、Phi 和 Qwen，各用同一条有顺序的 32 步参考轨迹，分别量：

1. 算子输出的差异；
2. 反向传播后的参数梯度差异；
3. 优化器写入参数的更新差异。

结果（32 步的“同向程度”，数值越大越像持续往一个方向走）：

| 案例 | 算子输出 | 参数梯度 | 参数更新 | 读法 |
|---|---:|---:|---:|---|
| Liger fused CE | 2.984 | 2.931 | 2.931 | 差异在算子输出阶段已经有方向 |
| Phi lm_head dX | 2.074 | 4.701 | 4.701 | 反向传播把原本较弱的方向放大 |
| Qwen lm_head dX | 1.008 | 1.698 | 1.698 | 输出阶段近似扩散，方向在反向传播后出现 |

这三段是同一把尺子，避免把“算子误差”与“反向传播/优化器造成的误差”混为一谈。详细原始结果见 [`three_stage_summary.json`](../results/property/joint_bias_formation_v1/three_stage_summary.json)。

### 2. 检查 Phi 的不同参数位置

预先固定 12 个参数位置：1 个已知位置和 11 个不看结果挑选的位置。32 步结果的同向程度范围是 0.578–4.488，中位数 1.073；7/12 高于 1，3/12 高于 2。这个结果说明方向性不是只在一个位置出现，但也不是所有参数都一样。

### 3. 四臂对照

同一初始状态、同一数据流、32 步：

| 对照 | 同向程度 |
|---|---:|
| 只改算子实现 | 4.488 |
| 换数据顺序 | 0.0067 |
| BF16 与 FP32 训练 | 1.857 |
| 换随机种子 | 0（该 Phi 配置没有 dropout，因此这一臂不适用） |

算子差异的绝对参数距离小于精度差异，但它更有方向性。重复注入、每步打乱方向的随机对照在 5 个种子上的同向程度为 0.870–1.037，提供了扩散的经验刻度。

### 4. 未见数据上的 loss

用同一批未参与训练的数据、同一个 FP32 前向路径比较四臂最终参数。参考 loss 为 3.018674。算子臂的 candidate–repair loss 差为 `3.74e-6`，精度臂为 `1.26e-5`，数据顺序臂为 `5.59e-8`，随机种子臂为 0。这里的 loss 只是下游结果，不用来重新定义“是否有 bias”。

### 5. Oracle 与简单指标的比较

在冻结的 12 个“有真实差异且参数可达”的案例上，16 步的方向性筛选 AUROC 为 0.909；局部更新 RMS 为 0，dtype 为 0.5，归约长度为 0.182。规则 `A16 > 1` 标记 3/12，找到了唯一一个已标记的 32 步局部持续案例，召回率 100%，假阳性率 18.2%。

这是回溯性、小阳性样本的工程结果，不是通用准确率。GPU 小时节省没有记录完整，因此不声称具体节省倍数。

把筛选数字单独保存为 [`timed_efficiency_partial_v1.json`](../results/property/joint_bias_formation_v1/timed_efficiency_partial_v1.json)：当前实际有 11/12 行的完整 32 步 wall-time 记录，共 4.927 GPU-hours（按一 GPU/每 case 计）。Mamba 行在宿主机 GPU 上又按四种真实配置尝试，仍未产生有效 timing row；详见 [`mamba_timing_blocked_v3.json`](../results/property/joint_bias_formation_v1/mamba_timing_blocked_v3.json)。这里只报告已测子集，不把它写成完整 GPU 节省或完整 recall 结论。

## 仍然明确保留的边界

- 旧案例中没有保存完整的 `epsilon`、`+epsilon`、`-epsilon` 重放输入时，不补造反对称响应；结论写 `UNRESOLVED`。
- held-out 已确认新的 source-negative，但完整的三因子预测器仍未确认。
- 这些实验使用声明的参数载体或单个参数，不等同于完整模型全参数训练。
- Liger、Phi、Qwen 不是三个完全独立的物理机制：Liger 是一个累加实现例子，Phi 与 Qwen 是同一 lm_head 矩阵乘反向家族在两个模型上的例子。
- 因此当前最稳妥的主张是：**误差大小本身不能决定危险性；必须分别检查它在算子输出、参数梯度和参数更新三层是否变得有方向，并用短轨迹方向性做筛选。**不声称所有算子共享一个万能 property。

机器可读的逐项审计见 [`plan_audit_v2.json`](../results/property/joint_bias_formation_v1/plan_audit_v2.json)。

## 对刚刚补充实验的覆盖核对

下面是本轮计划的验收表。它把“已经真的跑过”和“解释性加固”分开，避免把额外想法混进 bias + 算子 + Oracle 主线。

| 实验 | 是否属于主线 | 当前证据 | 口径 |
|---|---|---|---|
| 算子输出误差 → 参数梯度误差 → 参数更新误差 | 是 | 三个案例各 32 个有顺序状态，结构校验已通过 | 三段使用同一条 repair-reference 轨迹；不把后验轨迹标签倒灌成 formation 标签 |
| Phi 的 1 个已知位置 + 11 个结果盲位置 | 是 | 12 个独立 32 步结果，selection digest 与 manifest 一致 | 只能说明 12 个声明载体，不代表全模型所有参数 |
| 四臂同尺（算子、随机种子、数据顺序、精度） | 是 | 32 步最终权重已保存并做 digest 校验 | Phi 配置没有 dropout，因此随机种子臂记为不适用，不伪造差异 |
| 重复注入的随机残差刻度 | 是 | 5 个固定种子，A=0.870–1.037 | 它是扩散基线，不是新的算子 case |
| 四臂最终权重的共同 FP32 未见数据 loss | 是 | 4 行、32 步最终权重，统一评估路径 | 只作为下游后果，不重新定义 bias |
| RMS / dtype / 归约长度基线 | 是 | 冻结的 12 行回溯比较 | 只支持“当前样本中 RMS 不是有效筛选器”，不声称通用准确率 |
| 12 个有真实差异且参数可达的负例 consequence | 是 | 12/12 完成，16 步到 32 步回测已生成 | 反馈漂移与局部 source persistence 分开报告 |
| 分诊效率的真实 GPU 时间 | 是 | [`timed_efficiency_partial_v1.json`](../results/property/joint_bias_formation_v1/timed_efficiency_partial_v1.json)：11/12 screen-negative rows 有真实 32 步 wall time，共 4.927 GPU-hours（按一 GPU/每 case 计）；缺失的 Mamba 行在宿主机上又做了四次真实配置尝试，仍无有效 timing row，见 `mamba_timing_blocked_v3.json` | 只报告这 11 行的原始 wall time；不声称完整 12 行或完整 Oracle cohort 的 GPU 节省 |
| held-out 联合 predictor | 是，但属于收口验证 | 目前只有有界 source-negative 确认 | 未完成前不称为通用 predictor |
| 全量 raw epsilon 的 (+ε/-ε) 重放 | 否，属于加固 | 只有部分可重放案例 | 缺少保存输入的案例保持 UNRESOLVED，不补造数据 |
| SR、全参数训练、继续盲搜新正例 | 否 | 不作为本轮停止条件 | 它们不能替代三段 A、matched repair 和 Oracle 基线 |

因此，刚刚讨论的两项补充——三段 A 和统一 FP32 loss——已经纳入主线并有真实结果；其余缺口集中在计时和 held-out 验证，不是计划遗漏了 bias 或算子实验。
