# 工具修订（2026-10-03）：参照可信一直保持到报警可信

两位审阅方在 blind_test_v1 之后给出的修改意见，第一组（必须修的缺陷）全部落在代码里，并补了第二位审阅方要求的统一
入口与可复算记录。冻结的盲测结果保持原样（`results/reference_eval/blind_test_v1/phase1_report*.md`、`phase2/`），
修复版把这批程序当回归集另列（`results/reference_eval/blind_test_v1/regression_v2/`）。这批程序在修复过程中已被
看过，新的泛化成绩要来自另一批未参与修改的组合。

## 1 默认检测器接受区间样本（第 2 版，`reference_eval/detect.py`）

**问题**：参照是区间，第 1 版检测器把中点当成精确观测。阶段 2 中 prog_07、11、12、21、26 与 prog_25 rstd 的 e_sem
区间 100% 含零（K_R 与 f 在区间宽度内一致），两次区间计算的中点差稳定地与 K_R 相关，对齐检验于是报警。

**修改**：每个出口都按区间做端点保守检验，中点只用于在开发单位上定义方向和尾部诊断，不能单独产生检出。

- 投影类（total、learned、rows/cols、aligned、relative）：每个单位的投影取严格向外的 [l, h]（有向乘法、精确求和），
  再用与 R1–R5 相同的端点保守 t 推断。
- 方向无关的总检验（U 统计量）：盒内统计量的下界与每个符号翻转样本的上界比较
  （T_min = (Σ_c max(0, |U_c| − R_c)² − Σ(|m| + r)²)/(n(n−1))，T_max(s) = ((√(sᵀGs) + ‖R‖)² − Σ max(0, |m| − r)²)/(n(n−1))），
  报告的 p 值不小于盒内任一残差的符号翻转 p 值；宽度为零时与原检验完全相同（有测试核对）。
- 盒全部含零时，总检验 p = 1，投影类 p = 1：这类数据不可能产生检出，不需要程序名单或「低于 1e-12 忽略」的阈值。
- 返回实际使用的方向（`return_directions`），结果分「固定方向均值」与「参照相关对齐」两个问题。

**证据**：`tests/test_reference_eval_detect.py`（零残差、偏心含零区间、真实小偏差带符号检出、宽参照区间保守、零宽度
等价）；`tests/test_reference_eval_regression_rows.py`（阶段 2 六项的真实 e_sem 区间，按「区间全含零且第 1 版报警」
从冻结报告里选出）。校准 `results/reference_eval/detector_calibration_v2.json`（每 1000 次）：

| 情形 | 第 1 版 | 第 2 版 |
|---|---|---|
| 点残差、均值为零，向量均值族误报 | 3.3–6.0% | 3.0–5.4% |
| 点残差、均值为零，对齐族误报 | 1.7–3.4% | 3.0–4.2% |
| 区间残差、真值为零、中点带与 K 相关的稳定偏移 | （第 1 版在此报警） | 0/1000（95% 上界 0.4%） |
| 区间残差、噪声 + 中点偏移 0.2σ、半径 0.1σ | — | 0/1000 |
| 点残差的检出率（密集、抵消、稀疏、单行、随机符号、缩放） | — | 与第 1 版在抽样误差内相同 |
| 每坐标盒半径与每坐标作用同量级（密集 0.06σ/坐标、半径 0.1σ） | — | 0：参照不确定性足以解释该偏移，正确地不判 |

最后一行是端点保守的代价：盒宽度跨坐标按最坏情形线性累加。实际 kernel 的参照宽度通常比残差离散度小 4–5 个数量级，
只有在参照不确定性确实与作用相当时才会失去检出。

## 2 端点保守的 p 值与投影

- **p 值**（`analysis._summarize`）：μ 只知道落在 [E[l], E[h]]，改为 2·min(p(E[l] > 0), p(E[h] < 0))，与区间判定完全一致
  （p ≤ α 当且仅当保守区间不含零，有测试）。旧式取两个双侧 p 的较大者，在跨零的盒上（E[l] < 0 < E[h] 都显著）会变得
  很小，Holm 因而把这类检验算作拒绝、放宽其余检验的阈值。冻结结果中阶段 1 没有这种格子；阶段 2 发布标量下 90 个、
  float32 标量下 111 个。按修正后的 p 重做 Holm，阶段 2 的 29 / 19 个最终检出一个不少、一个不多（检出格的 p 最大
  1.9e-22，最严阈值 3.1e-4）。
- **投影**（`intervals.fsum_bounds`、`intervals.project_bounds`）：有向乘法，每个端点数组精确求和（fsum，正确舍入）后
  向外一个 ulp；分组规则的组内求和与除以 √size 也改为有向。`analysis._project`、盲测运行器、默认检测器都用它。
  `run_detection.py` 的次要残差定义 K − RN(K_R) 原来是普通减法，改为有向。

## 3 统一的判定层（`analysis.assess_units`）

方向规则、有效坐标策略、端点处理、默认检测器与多重校正只有一份实现：

- 规则表 `analysis.RULES`：`negative_ones`（R1）、`toward_zero`（R2）、`scale_down`（R3）、`aligned_reference_update`、
  `declared_vector`（R4）、`fixed_direction`（R5）、`cross_fit`、`grouped_<rule>`。每条规则写明它回答的问题（固定方向均值
  或参照相关对齐）和 μ 正负对原始残差意味着什么——R1 的方向是 −1/√n，**正的 μ 表示残差均值为负**，报告逐条自动写出。
- `assess_units`：坐标集在开发单位上固定；确认单位按声明的策略处理；规则用严格投影与端点保守推断；默认检测器在同一
  坐标上运行。记录包含离线复算所需的一切：开发/确认单位编号、每条规则每个确认单位的投影上下界、实际方向（常数、按单位
  的归一化标量，或保存的向量名）、原始 p、排除原因；向量（坐标集、R4、R5、检测器的学习与分组方向）另存。
- `apply_holm`：Holm 校正后的 p 值（`holm_adjusted_p`）、拒绝与最终判定及其含义。
- 使用者：`statistics_stage`（`scripts/run_reference_analysis.py`，另存 `statistics_arrays.npz`）、`run_blind_test_v1.py`
  （只剩输入与规格绑定）、`run_detection.py`（陌生算子默认入口，可选 `--rules`）。

## 4 比较对象与接口精度（`reference_eval/interface.py`、`scripts/blind_test_v1_regression.py`）

- **运行时标量**：记录传入的 Python 值、kernel 参数类型、kernel 实际收到的值与相对舍入（如 F4 的 t = 1/√2 → float32，
  −1.7e-8；F1/F3 的 eps）。
- **编译期常数**：列出 TTIR 中每个浮点常数的精确值；若它是某个简单有理数或常见无理数的正确舍入而又不等于它，列出候选值
  与相对舍入（prog_05、08、27 的 8 个分块合并系数 1/7、3072/7、1/3…）。候选值是从存储值读出的推测，IR 里没有原意。
  分母上限随数值的 ulp 变化，Q(x) = √(2·10⁻³ / ulp(x))，随机值被误读的概率约 10⁻³ 以下（实测 2 万个随机 float32 中
  0–11 个）。
- **五个量**：同一次运行分别评估 K − K_R（实现）、K_R − f_interface（语义，标量按收到的值）、K_R − f_published（语义，
  标量按发布值）、f_interface − f_published（接口项：启动时的标量舍入，作为有指定生产者的上游节点）与 K − f_published
  （总差异）。K − f_published = 实现 + 语义（发布口径），语义（发布口径）= 语义（接口口径）+ 接口项。

## 5 舍入核验模式的格式与模式

- 新增 f8E4M3FN（最大有限值 448）、f8E4M3FNUZ、f8E5M2FNUZ、f8E4M3B11FNUZ、f4E2M1FN；最大有限值单列。没有无穷的格式
  溢出时，饱和还是 NaN 由实现决定，元素记为参照未建立（不猜）。
- 精确有理数路径（`numbers.round_rational`）支持 rtne、rtz、rd、ru 与上述格式；通用求值器读取 `rounding` 属性。
- 逐位模拟器去掉两处静默退回：未知格式按 f32 舍入、未知格式一律视为可表示。
- 证据：`tests/test_reference_eval_formats.py` 对每种格式的全部位模式枚举比较四种模式（含无穷/饱和/实现定义溢出的边界）。

## 6 回归结果（blind_test_v1，修复版重跑，冻结结果不动）

37 个程序重新运行（seed 0–95），五个量各自走统一判定层，Holm 范围与协议相同（每个量内全部「程序 × 输出 × 规则」）。
与冻结结果逐格比较（`regression_summary.json`）：

| 量 | 协议规则判定变化 | 默认检测器判定变化 |
|---|---|---|
| 实现 K − K_R（阶段 1） | 0 / 170 | 0 |
| 语义，发布口径 K_R − f_published（阶段 2 主表） | 0 | 7 个族判定，全部为检出 → 未确认：prog_07、11、12、21、26 的对齐族，prog_25 rstd 的两族 |
| 语义，接口口径 K_R − f_interface（阶段 2 附表） | 0 | 同上 7 个 |

即修复只去掉了六项误报，没有改变任何协议判定，也没有丢掉默认检测器的任何真实检出。新拆出的两个量：

- **接口项 f_interface − f_published**：F4 的 t 舍入（prog_16、28、30、35、36、37 的 R2+、R3+，输出被缩小），F1 的 eps
  舍入（prog_07、11、12、18、21、26 的 R2−、R3−，输出被放大），F3 的 eps 舍入（rstd 列）。F1 与 F3 的这一项在
  K_R − f 里被 K_R 的区间宽度（约 1e-12）盖住，单列之后才分辨得出。
- **语义，接口口径**：检出的正是冻结解读中「两种标量取法都检出」的那组——prog_18、33、35、10、prog_27 rstd，以及
  prog_05、08 rstd（编译期合并常数，接口清单列出这三个程序的 8 个舍入常数）。

真实数据的回归样例：`tests/data/blind_v1_zero_semantic_residual_rows.npz`（六项输出，96 个 seed，前 128 个坐标），
`tests/test_reference_eval_regression_rows.py` 要求第 2 版对每一项两族都未确认、每个检验 p ≥ 0.05。

完整表格（按问题分开：数值不一致的符号比例、固定方向均值、参照相关对齐，每个检出附含义）、接口与常数清单见
`results/reference_eval/blind_test_v1/regression_v2/regression_report.md`；离线复算记录（每个确认 seed 的投影上下界、
方向与归一化标量、开发/确认划分、原始与校正后 p）见 `regression_records.json`，向量另存
`.cache/blind_v1_regression_v2/`。
