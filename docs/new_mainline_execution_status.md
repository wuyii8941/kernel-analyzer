## 2026-09-07 四目标校准：不是新一套结果标签

原计划继续执行，验收按[当前主线](current_mainline.md)明确四项共同目标：

| 目标 | 当前状态 | 还不能用什么替代 |
|---|---|---|
| 机制与工具共同组成框架 | 自动采集/复算和代表机制已有，跨家族复用继续补齐 | 更多调用位置不等于更多机制；只测量不能代替可检验修改预测 |
| 真实包含 Triton | 多个源码核对家族已进入训练测量 | 静态覆盖不是动态支持；混合计算不等于误差发生在 Triton 内 |
| 统计学理论完备 | 固定集合分析可用，总体保证未完成 | 校准失败后停用总体输出是正确限制，不是目标已完成 |
| 强训练后果 | AdamW8bit 在八条冻结数据流上得到超过预声明 0.01 门槛的评估 loss 差；未见崩溃，修改改善未确认 | 一项固定 checkpoint 结果不能代替跨模型、跨 checkpoint 验证 |

自动化验收采用明确的人机边界：发现、绑定、采集、统计判断、失败记录和报告复算属于
自动流程；诊断后选择修改、决定训练候选和设置训练实验允许人工安排。人工安排必须形成
可追溯协议和结果揭示前的预测，之后由统一程序执行和复算。因而“程序不能自行提出并
选择修改”不再视为阻塞项；未记录依据、临时更换指标或手工抄写结果仍不合格。

这一边界已在 optimizer-update 新家族上实际走通：研究者审核候选、参考、参数与固定
gradient 集合；冻结后程序自动执行 transition、重复性检查、原坐标统计、统一判断和
报告复算。首轮因普通 Tensor 的 `dequantize` 调用形式错误而失败，真实 gradient 与
失败原因均保留；v2 按摘要复用相同 gradient 完成。它不表示程序能够自行提出 optimizer
修改或选择长训练。

后续已经按这条边界完成一次闭环：研究者冻结 block-size 机制预测，程序在固定真实
gradient 上确认该预测；再冻结八条非重叠数据流、1024 步、主要评估点和 0.01 loss
门槛，自动运行三种 optimizer 并独立复算。默认 AdamW8bit 的配对 loss 差均值为
`+0.02718`，95% 区间 `[+0.01217,+0.04220]`，达到该次预声明的实际幅度标准；
64-block 修改的训练改善未确认。这个结果关闭一条机制到训练后果链，不关闭全部
kernel 覆盖或一般总体推断。

component 结果之后提出的 FP32-first-moment 修改已用另外 8 条新数据流完成冻结训练
确认。主要比较 `default−modified` 的均值为 `−0.01070`，95% 区间
`[−0.02708,+0.00567]`，所以修改改善仍为 `NOT_CONFIRMED`；修改版相对 FP32
AdamW 的次要差异为 `+0.03513`，区间 `[+0.01040,+0.05987]`。这次阴性结果说明
固定 gradient 上较小的参数写入 RMS 不能代替训练收益，诊断指导的实现改善仍是
未完成项，不再用同一批输入临时选择第三个 optimizer 变体。

具体统计失败与生产范围见[方法](method.md)，文献定位见
[创新边界](novelty_positioning.md)。后续状态更新必须分别记录“执行完成”“预测成立”
和“四目标达到”；不修改旧 JSON 的原成功标准，不把缺口改名成完成。

恢复实验前，先固定待解决的统计条件和可信参考，再以有限清单补不同家族/新状态，
优先跟进普通 warm 训练中有可靠作用、能给出机制预测的修改。确认前声明最小有
意义的训练变化、主要指标与预算，不据已见的 Liger 小差异调整标准。
本次文档校准不启动或恢复 GPU 队列。
