# 普通行归约参考：待运行接入

`row_sum_reference.py` 识别 FP32 连续行求和、BF16 输出的完整生成计算体，包括地址、掩码、归约维度和存储类型。数学对象是 `sum_j x[row,j]`，不是行平方和，也不能由包含 RoPE 的生成名称推断为完整 RoPE 实现。

该参考在 DeepSeek seq128 已保存 backward 源码中匹配了一个 128×8 定义。九项测试覆盖非二次幂掩码、参考结果、错误寻址、错误归约、类型变化、非有限输入及未证实的内存别名。

当前状态是**源码参考已实现、seq64 自动绑定 36 个训练位置、设备声明重试的首批四个位置已核验通过，其余位置仍在队列中**。新增的 `run_declared_reference_family.py` 在进程内接入预先声明的新家族；新清单记录该入口及参考的摘要，运行前必须匹配，不能替换已有注册家族。它调用原有扫描、绑定和采集程序，不复制统计代码，也不改动仍在运行的 softplus 队列的共享注册表。

启动记录位于 `results/property/numerical_coverage_v1/deepseek64_row_sum_batch000_launch_v1/`。记录存在不代表实际路径验证成功；后续需核验具体 Triton 源码身份、原坐标统计和实际参数写入。36 个位置不是 36 个机制，且首批未完成前不报告偏差结论。

该次首批在测量前被身份检查阻止。`deepseek64_row_sum_actual_source_v1.json` 保存实际执行模块：计算体、类型和其他编译字段与原定义一致，唯一差异是逻辑 CUDA 设备编号由 0 改为 3。`declare_source_device.py` 显式生成新的预期设备版本，不修改原源码，也不作为实际执行证据。新声明的完整函数 AST 已与诊断记录匹配，重试记录为 `deepseek64_row_sum_device3_batch000_launch_v1`；实际采集仍保留原完整 AST 检查。重试未验收前不计入有效测量。

重试现已由 `deepseek64_row_sum_device3_batch000_v1/completion_verification.json` 核验：四个位置均有 32 个状态和三阶段原坐标统计，固定确认集合的参数写入 RMS 差异均为零。不能将其概括为全部 32 个状态逐位相同：第一个位置在 calibration 中有一个状态的一处非零差异，其他三个位置的已记录 32 个状态均未出现非零坐标。该结果不支持新增显著偏差或训练损害主张。

`verified_baselines/` 由现有共同数据比较脚本生成四个位置的 12 行三阶段表及图；剩余位置使用相同声明入口自动运行，任何身份或有效性失败仍停止后续队列。

后续接入复用现有家族绑定、训练重放与统一统计代码；不能为这一归约另设统计阈值。源码语义正确不证明数值偏差存在，单元测试不替代实际执行身份和参数可达性检查。
