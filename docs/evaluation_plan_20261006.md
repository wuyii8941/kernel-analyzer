# 评价设计与工作计划

2026年10月6日。本文按同类论文评价章节的形式组织：研究问题、评价对象、基线与指标、各问题的实验设计、有效性威胁。
每个问题都标出已有证据与还缺的部分，工作计划由「还缺」一栏推出。本文取代 [plan_20261006.md](plan_20261006.md) 中
尚未完成的部分；已完成的工作包作为下文的「现状」。现状只用三种状态：**已完成且有报告；已运行，待核验或待入库；
尚未运行**，逐条核账见 [status_ledger_20261006.md](status_ledger_20261006.md)。

## 1 研究问题

- **RQ1 参照的可靠性与成本。** 对声明支持范围内的陌生组合，自动参照的建立率、包含性、区间宽度与成本如何？建立率的
  分母包含不支持、超时与未建立。
- **RQ2 规格差异检查。** 在规格与前提已声明时，工具能否在所测输入上可靠地找出声明语义与规格的差异，并与实际输出的
  总差区分开？语义目标不使用经验容差：区间不含 0 是该输入上的差异证据；区间含 0 只表示未能排除相等，不证明相等。
- **RQ3 系统性作用检测。** 对目标量已独立确定的任务，固定方向均值与对齐作用的检出、误报与灵敏度如何？与幅度检查相比，
  提供了哪些不同的信息？
- **RQ4 更新传播。** 同一个实现差异经过下游映射后，效应量如何变化？哪些变化只有测量实际写入才能看见？
- **RQ5 实用性。** 未参与开发的使用者能否接入新组合？工具是否帮助发现问题、确定修改位置、确认修改只修了哪一部分？
  代价多大？

**标签怎样定。** 每条标签绑定一个五元组：程序、输入分布、比较对象、测量点、规则。固定方向均值与对齐作用分开列表。

| 标签依据 | 用途 |
|---|---|
| 独立证明或可靠确定在该规则下 μ = 0 | 评价该规则的误报率 |
| 独立确定 μ ≠ 0，或确定其落在事先声明的效应区间 | 评价检出率、符号与效应量 |
| 没有注入，但 μ 未独立确定（包括干净版本与成熟库实现） | 发现型数据，不算阴性 |
| 已知规格反例 | 评价规格差异检查，不自动成为平均作用的阳性 |

**语料怎样选。** 语料按标签来源分三类：自己出题并封存答案的、他人构造并给出标签的、没有标签的真实代码。第一类标签
最完整，第二类排除出题方的偏差，第三类检验实用性。首轮只做一个外部受控集合加一个陌生组合子集，把提取率、规格成本、
运行预算与独立答案核准后，再决定是否接入第三个外部集合。TritonBench 有两个不同的同名项目（thunlp 的代码生成基准与
meta-pytorch 的性能套件），选用前写明；KernelBench-Verified 以 CUDA 为主，只能走黑箱，且四种输入由同一基础输入变换
而来、不是独立单位，首轮暂缓。黑箱结果只建立 f 与 K − f，不计入 e_num 与 e_sem 分解的成绩。

## 3 基线与指标

**基线怎样选。** 本方法与现有做法在三个维度上不同：参照从哪里来、怎样判定、在哪一层判定。每一维取现有工作中实际使用
的代表作为外部基线，再做消融——把本方法的这一维换成现有做法，其余不变。

| 维度 | 现有做法（代表） | 对照方式 | 可行性（运行前写定） |
|---|---|---|---|
| 参照来源 | 更高精度重跑（KernelBench 一类）；可信的参考实现（TTrace）；随机扰动的多次运行（随机算术） | 消融：K_R 换成更高精度重跑 | 很多 Triton kernel 在内部固定 fp32 / bf16（`tl.dot` 累加精度、常数类型），不能直接以 fp64 重跑：能真正 fp64 重跑的子集单列；其余以 fp64 eager 的 f 代替，作为另一种比较单独成表，不合并 |
| 判定规则 | 逐元素容差（allclose）；按扰动标定的范数阈值（TTrace）；有效位数或变异性（随机算术） | 外部基线：每类取一个代表；消融：均值检验换成幅度判定 | Verificarlo / CADNA 一类不能在 Triton GPU kernel 上运行：用本工具的逐位模拟器实现随机舍入，命名为「随机算术式」；TTrace 原代码能在这些 kernel 上运行才称 TTrace，否则称「TTrace 式阈值」 |
| 判定层 | 算子输出 | 消融：判定层从更新换成输出 | — |

**参数与公平口径。** 每条基线报告两组结果：原论文或原项目的默认配置；事先登记的参数扫描——扫描范围、预算与选点规则
在运行前固定，工作点在开发数据上选定，在保留数据上报告。比较有两种公平口径：同程序、同输入、同样本数，回答检测信息
本身的差别；同等时间或算力预算，回答实际使用中哪个方案更划算。计时统一计入编译、捕获、参照与统计。两类判定的分歧
称为「幅度与平均作用提供的不同信息」，不直接称为基线的漏报或误报。

**指标。**

| 性质 | 指标 |
|---|---|
| 参照可靠 | 独立复算下的包含性违反数；参照类别分布（分母含不支持、超时与未建立）；区间宽度分布 |
| 检出 | 已独立确定 μ ≠ 0 的单元上的检出率与符号正确率；规格反例的检出率 |
| 不误报 | 已独立确定 μ = 0 的单元上的误报率及其区间；规格一致的 kernel 被判差异的比例 |
| 灵敏度 | 事先声明的效应结构与噪声模型下的敏感性曲线 |
| 信息差异 | 通过容差但平均作用非零的单元数；误差大但平均作用未确认的单元数 |
| 训练相关性 | 不同下游映射之间的效应量变化；如做独立 run，loss 差及区间 |
| 复用 | 外部接入的耗时、求助次数、核心改动、自动完成率与失败原因 |
| 诊断收益 | 是否更准确地确定修改位置，是否能确认补丁修了哪一部分 |
| 成本 | 运行时间按编译、捕获、参照、统计分段；同等预算下的结果 |

## 4 各研究问题的实验设计

**RQ1 参照的可靠性与成本。** 设计：各类语料上都不写专属 reference，统计参照类别分布、区间宽度与成本；参照用两种
互相独立的方式复算：不使用工具代码的独立实现；代表性纯片段导出为 FPCore 后由第三方求值器交叉复算（写明导出对象、
求值器的精度与舍入、覆盖范围），无法导出的片段仍计入分母。
- 已完成且有报告：盲测全部程序建立完整参照；两轮独立复算合计 16,908,160 个输出元素、974 个投影值，0 处违反（v2 每个
  元素核对 K_R、f 与三种优化器下的 u 五项）；一次真实训练捕获中全部 launch 建立完整参照；真实修改的反事实与设备输出
  逐位一致；锁定版本的全部注册指令均映射或显式拒绝。
- 尚未运行：外部受控集合与陌生组合子集上的建立率；FPCore 交叉复算；成本统计。

**RQ2 规格差异检查。** 设计：在带规格差异标签的语料上，与第 3 节各类判定规则对照；同时报告 e_sem 与 e_total。结论分
三种：在某输入上可靠地不一致、未能排除相等、未建立。
- 已完成且有报告：两轮盲测 14 个语义变体全部给出 K_R ≠ f 的区间证据，事先登记符号的 6 个全部正确（v1 3/3、v2 3/3）；
  OpInfo 直接差分基线——已登记的错误用完整用例的直接差分也能发现，工具的增量在差的拆分与诊断，代价更高。
- 尚未运行：外部受控集合上的对照。

**RQ3 系统性作用检测。** 设计：在 μ 已独立确定的单元上评价检出、符号与误报；在全部语料上统计两类信息差异。外部语料按
事先声明的输入分布分别报告，同一基础输入的变换不作独立单位。新发现经独立复算确认残差，总体均值仍以统计判定为准。
- 已完成且有报告：合成数据上误报率与族错误率符合名义水平；盲测已知阳性 16/17 检出且符号正确，未检出的 1 个（v2
  prog_08）是在打开任何结果之前就声明测不出的灵敏度探针，去掉探针为 16/16；由被测方冻结的判定矩阵复算一致
  （`results/reference_eval/blind_test_records/recount.json`）。
- 尚未运行：外部基线与三项消融在同一单元上的结果；外部语料上的信息差异计数；等价性检验的两项校准——区间覆盖率，以及
  |μ| ≥ δ 时错误宣布等价的概率（在 μ = ±δ 附近检查）。

**RQ4 更新传播。** 设计：同一组数值差经过不同的下游映射分别估计效应量。主表列效应量与区间、参照类别、口径（理想优化器
响应或实际写入），判定只作最后一列；不以「这一层显著、下一层不显著」推断抑制。
- 已完成且有报告：AdamW8bit 覆盖了状态经过量化的优化器；盲测 v2 覆盖一种线性优化器（SGD）与两种自适应优化器状态
  （AdamW 带历史、零动量），理想响应口径下 SGD 8/8、AdamW 带历史 8/8 符号与封存推导一致；实际写入口径有 11 到 14 个
  程序参照未建立，记为未建立，而不是被抑制。
- 尚未运行：一个真实场景的输出、梯度、实际写入逐层表；更新层的等价性报告。

**RQ5 实用性。** 设计：（1）外部接入：未参与开发的人从冻结清单领取或自选新组合，只按指南写绑定，记录耗时、求助、核心
改动、自动完成率与失败原因。（2）诊断收益：在已有深案例上比较「只有直接差分」与「加上差的拆分与定位」。（3）已有普查
整理成统一报告。（4）发现的问题视情况提交上游，状态如实记录。（5）确需支持训练主张时做独立配对训练，结果按事先声明的
目标报告。
- 已完成且有报告：AdamW8bit 从状态误差到 8 对独立 run 的训练改善闭合；B016、B012 深案例；bf16 参数下 AdamW 的问题被
  无提示地定位到二阶矩的写出（B005，提交 9d44d70）；真实问题 B012–B018 的登记，其中 B017、B018 在 main 上仍在（各条的
  发现方式如实标注：B018 不是工具检出）；benchmark 修复前后 38 个单位。
- 尚未运行：外部接入试验；诊断收益的对照；普查整理；问题提交。

## 7 有效性威胁

**内部有效性。** 盲测的出题方与工具开发方同属一个团队。缓解：答案在评测前封存并记录哈希（揭盲版与原始包中的封存成员
逐字节相同）；判定规则在开包前冻结；答案由不使用工具代码的独立实现复算。出题方自己的答案也会出错，两轮共九条勘误，
揭盲前声明的与揭盲后发现的分开记录（`blind_records/errata.md`），没有一条改变工具的判定。揭盲后 v1、v2 只作回归集。

**构造有效性。** 平均作用检出不等于训练受损：训练后果只由独立 run 的实验支持。δ 的依据在确认数据之前写入声明，并报告
结论对 δ 取值的敏感性。外部语料的「正确」标签相对其规格与容差协议，不是零均值标签，不直接用作平均作用的阴性。

**外部有效性。** 参照的分解只覆盖锁定的 Triton 版本（3.6.0，另验证 3.5.1）与 sm_86 架构；语料以 Triton kernel 为主，
CUDA kernel 只能在黑箱模式下测总差。外部语料由其他团队构造，用来抵消盲测语料只出自一方的偏差。

**统计结论有效性。** 多重比较用 Holm；同一条训练的不同 checkpoint 按 run 聚类，独立 run 只有一两条时只做条件推断；
高维方向学习的功效不足会让「未确认」被误读为「没有作用」，因此每个结论都报告事先声明效应结构下的敏感性，不报观察后的
功效。

## 8 不做的事与论文图表
