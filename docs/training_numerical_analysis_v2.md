# 实际参数写入修正与本轮验收

本页记录实际参数写入修正及选定机制实验，不改讲稿。机制实验检查具体差异如何
形成 bias，以及是否造成 loss 分叉；能量判断不能代替这条证据链。但这不是
2026-09-05 新计划的全部：框架还要扩大实现接入与自动测量，等价判断也是正式输出。
这些工作见[覆盖执行说明](numerical_coverage_execution.md)，不因本页实验完成而自动完成。

2026-09-07 起，整体完成标准统一按[主线四目标](current_mainline.md)理解：机制与
工具、真实 Triton、统计理论、强训练后果。本页保留的 Q-only 判断和小幅 loss
分叉是已测结果，不替代总体统计保证或足够有说服力的训练后果，旧协议不回写。

## 已实现

- 实际执行 AdamW 后读取参数差异，旧的额外舍入函数保留为历史版本。
- 同一 `analyze_artifact` 处理新采集与高维合成验证；不读取缓存 verdict 或缓存区间。
- 原坐标能量与内积决定固定集合 RMS 和加权缩放；状态由声明 ID 选择。
- Q-only 固定集合政策沿用 1% RMS 范围，方向只作诊断。它不是旧三投影政策，
  也不是随机总体或全训练等价性保证。小投影不再用于排除未观察的方向。
- 新入口自动执行已有案例 runner、保留日志与失败、复算结果，拒绝覆盖已有文件。
- Phi 已在 FP32 master 的真实 AdamW 重放下完成 32 状态测量，确认集合 RMS 约 5.47%。
  这与旧 BF16 参数表示不同；不能用新结果宣称旧 BF16 零值已被同协议推翻。
- Liger 的 32 状态实际写入复采也已完成：确认集合 RMS 为 0.653724%，
  加权缩放为 −0.046111%。它在声明的 1% 总 RMS 范围内，但差异不为零，
  方向摘要也不为零；这个有限集合的能量判断不等于“没有 bias”或“未来 loss 相同”。
  此测量使用 Qwen 状态，不能与下面小型 GPT-2 的训练结果拼成同条件因果证明。
- 两个 DeepSeek 以及原 Llama softmax backward 已完成同入口复采。固定确认集合的
  实际写入 RMS 分别约为 53.04%、46.04%、13.71%，加权缩放分别约为
  −14.07%、−10.60%、−0.94%。这些数字分别属于各自模型和参数范围，
  不能把 RMS 超范围直接叫作数学上已证明的 bias，更不能据此推断 loss 后果。
- Llama 的原实现来源绑定已恢复，未换成其他案例。Gemma 的真实执行采集已完成，
  3721 个名义实数 F+B 单元及 140 个 backward 重算节点的公式检查通过。
  GELU 的十进制公式关系与二进制常量误差分别记录，前者通过不代表后者为零。
  原案例的内部输出现已恢复：历史 runner 只开放指定参数的梯度，误将全部参数
  开放会改变编译计算和保存的中间结果。恢复原训练参数范围后，实际 kernel 的
  完整语法结构与原记录一致，32 个状态测量通过。目标是 FP32 行平方和缓冲区，
  不是仅凭 `buf31` 名称猜测的最终 normalization 输出。
  确认集合 RMS 7.678779%，加权缩放 −0.294828%；前者超过本版 1% 范围，
  但不能由此称它为新的 bias 或 loss 案例。此前拒绝测量的记录全部保留。
- 新模型 Granite 的 MoE expert 输出累加也已完成 32 状态确认。两种实现均为
  FP32，参考只反转 expert 的累加次序，使用同一统计代码且不调整阈值。
  实际更新差异非零，确认集合 RMS 为 0.002281%，在声明范围内。这是新家族的
  非零小差异对照，不是新增有害 bias，也没有测其长程 loss。常规实现作为被测
  对象而非仅作参考，运行源码、替换位置和 exact-repeat 检查均保留。
- WikiText 与真实 tokenizer 的全参数训练开发检查已跑通。共同 FP32 评估路径下，
  参考重复的参数、optimizer state 和 loss 完全一致；64 步原实现减参考的 loss
  差异约为 −0.000717。它只支持这次短程分叉，不支持持久性或训练质量收益。
  四组不同初始化的 1024 步配对开发实验均已完成：最终 loss 差为
  +0.000708、+0.000566、+0.000800、+0.000259，平均 +0.000583。
  参考设置在这四组中 loss 均略低；这还不是总体或工程收益保证。
  独立的新初始化确认另外冻结，不使用这四组重新作确认。
- 新的 16 组初始化配对确认已全部完成，每组训练 1024 步：15 组原实现的最终
  共同验证 loss 更高，平均差 +0.00069609。预声明单侧符号检验 p=0.00025940，
  支持在这套固定数据顺序、四层模型和评估设置下，参考实现更经常取得较低 loss。
  代码、输入、有限 loss 和 checkpoint 摘要核验全部通过。
  这是小幅且可重复的训练后果，不是工程收益幅度、完整 LLM 泛化或持久 bias 的证明。
  [冻结计划与结果](../results/property/training_numerical_analysis_v2/language_training_confirmation_iid/summary.json)
- 同一套语言训练的末期机制检查已补齐：32 个真实 checkpoint 全部仍有直接更新
  差异，RMS 约为正常更新的 0.0910%–0.1025%；每个状态的前后两半输入均同向。
  一个真实状态的 128 个分块乘积及输入梯度相同，`dW` 舍入差异可精确重构。
  这是末期固定状态与源码恒等式证据，不是全程持续 bias 或 loss 的充分归因。
  [同设置机制检查](liger_language_mechanism_followup.md)

## 实际训练延续与结论边界

Liger 首次缺包，复用本地包后又遇到非默认设备 Triton 指针问题；修正设备映射后的
复采已完成，原失败和中断记录仍保留。原六项复采均已有效测量；
Gemma 使用恢复的原训练参数范围和完整运行源码校验，并非放宽绑定条件。
全部 16 组、32 条真实语言训练轨迹已从 1024 步继续到 4096 步，保持参数、
AdamW 历史和配对输入。四个事前指定的直接测量窗口均完整保存：
1025–1056、2017–2048、3041–3072、4065–4096。

32/32 条轨迹的后期窗口平均差异与第一个窗口同向；30/32 条轨迹在每个窗口内
前后半均值也同向。例外是第 13 组的两条轨迹，在 3041–3072 窗口内部未保持
前后半同向，未删除该组。最后窗口的直接更新差异 RMS 为正常更新的
0.1502%–0.1786%。这支持已测后期窗口仍有直接方向结构，不证明所有未测步骤同向。

16/16 组最终都有 loss 分叉，但只有 2 组原实现 loss 更高，平均差为 −0.00132849，
与 1024 步的平均正差相反。因此同一设置已连接舍入来源、后期直接方向和 loss
分叉，却不支持持续质量恶化；也没有证明工程上足够大的收益或方向分量独自解释
全部 loss 差异。延续在早期确认结果之后开展，不作为新的独立前瞻检验。
已见 Llama/Gemma 案例的恢复不能重新命名为“新实现的未见确认”；
新实现确认另由 Granite 的 FP32 expert 累加承担。

保留的方向诊断区间是固定窗口的描述量；其中逐状态缩放比例的经验区间，
不是原坐标加权缩放估计的置信区间。它们不参与本版 Q-only 等价判断。

总体证书不在已完成保证中：16 独立单位的偏斜分布边界测试错误通过率为 9.9%，
重尾场景更高。结果原样保存，暂不启用总体证书，不按已见案例调阈值。
后续样本量检查在有限方差 `t8_energy` 的边界场景中，16 单位错误通过率仍为
16.6%（2000 次），1024 单位为 7.5%；见
[样本量检查](../results/property/numerical_coverage_v1/population_sample_sizes.json)。
不能仅靠增加到某个固定样本数就宣布校准通过。
本轮完成的是固定集合分析及声明设置的机制与训练验证，不是把该失败改名成通过。

## 自动执行

使用仓库现有 Python 环境并设置 `PYTHONPATH=src:.`：

```bash
python scripts/run_training_numerical_v2.py freeze
python scripts/run_training_numerical_v2.py capture --case phi --device cuda:0
python scripts/run_training_numerical_v2.py report
```

完整计划审计使用 `python scripts/audit_training_numerical_analysis_completion.py`。
它会重新读取当前测量、失败和训练确认，而不是接受历史完成标签。
训练确认的输入与输出完整性另外由
`python scripts/verify_liger_language_confirmation.py` 检查；已保存的核验结果不覆盖。
全部有效报告由 `scripts/verify_training_numerical_reports_v2.py` 重新从原坐标数据
计算；延续由 `scripts/summarize_liger_temporal_extension.py` 核验完整步数、窗口、
配对输入、有限 loss 与 checkpoint 摘要。
最终表格由 `scripts/build_training_numerical_final_report.py` 自动生成，不手抄判定。

协议只冻结一次，现有记录不覆盖。多 GPU 应通过 `CUDA_VISIBLE_DEVICES` 映射到逻辑
`cuda:0`，否则与旧编译图中的设备常量不同。重试另外保存，不关闭实际执行身份校验。
结果在 `results/property/training_numerical_analysis_v2/`；旧 v1 结果不删除。

历史有限清单曾记录 **COMPLETE_BOUNDED_MAINLINE**。这只表示选定实验执行和复算
完成，不是整份新计划完成；当前审计已将这两项分开，旧结果文件保留历史标签。
执行完成与科学观察分别记录；阴性也可以是有效结果，完成标签不代替 bias 证明。
