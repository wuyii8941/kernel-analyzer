# 外部接入试验协议（计划 WP4）

目的：证明"别人能用"。由一位**没有参与工具开发**的使用者，在新环境中接入一组新组合，只写绑定，不写专属参照、
不改检测核心，完成模式 A；模式 B 另记写规格的工作量。

## 冻结与准备

1. 工具冻结在一个标签（`tool-v3.0`），试验期间核心不改；试验中发现的问题记下来，试验结束后再修，修完的版本单列。
2. 使用者拿到：仓库标签、`docs/binding_guide.md`、`examples/bindings/`，不拿到开发者的个别指导（遇到问题只能查文档；
   求助次数与内容照记）。
3. 组合由使用者在下列库里自选，开发者事先不看、不试：SGLang 的 Triton kernel、FBGEMM 的 Triton GEMM / jagged、
   xformers 的 Triton 算子、flash-attention 的 Triton 实现、unsloth 的 kernel；每个库 1–3 个，共 5–10 个组合。

## 每个组合记录

| 项 | 怎么记 |
|---|---|
| 接入耗时 | 从开始写绑定到第一次得到报告（分钟），另记模式 B 写规格的耗时 |
| 绑定行数 | 不含空行与注释 |
| 是否需要修改核心 | 是 / 否；是则记下哪个文件、为什么（这一项直接计入"不能复用"的证据） |
| 自动完成比例 | 报告里参照建立的比例（`reference_classes.complete_fraction`），program 中止的原因 |
| 超时与失败 | 超时、报错、无法捕获的次数与原因 |
| 分析成本 | 参照求值与统计的耗时（报告的 `seconds`） |
| 求助 | 次数与内容 |

## 判定

- 模式 A 成功：不改核心，得到所有输出的报告（参照未建立的输出如实列出，不算成功也不删除）。
- 需要改核心的尝试照实计入，不事后改写成"已支持"。
- 结果写进 `docs/reuse_trial_<日期>.md`，原始报告入库。
