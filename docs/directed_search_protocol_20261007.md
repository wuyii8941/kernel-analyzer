# 定向搜索协议（阶段 C，`docs/next_phase_plan_20261006.md` 第 2.4 节，2026-10-07，运行前写定）

在作用不经过 Adam 抑制的位置上，用阶段 B 冻结的尺子（δ_γ = δ_b = 0.05，相对每步更新范数）给候选实现排序；超过尺子的做深案例，
低于尺子的报告上界。本文在任何阶段 C 的测量之前提交；改动只追加到第 8 节。

## 2. 测量：影子状态单步（C1–C8）与普通单步（C10）

- **影子状态。** 对照配置正常训练（种子 0 与 1，2,000 步）；每个候选的优化器另持一份状态，在每一步用与对照**相同的梯度**更新
  （参数每步重置为对照的 θ_t，bf16 参数的候选取 bf16(θ_t)），所以状态里会积累候选自己格式的漂移，而参数轨迹不分岔。在第
  100、120、…、1980 步（每 20 步，共 95 个单位）记录 u_t = (θ_X⁺ − θ_X) − (θ_R⁺ − θ_R)，同一 θ_t、同一梯度；开发单位为序号
  ≡ 0 (mod 3) 的 32 个，其余 63 个为确认单位。C8 的对照与候选共享动量（动量不依赖 Newton–Schulz），差别只在正交化。
- **普通单步（C10）。** 用纯 bf16 参照 P 的种子 0 状态（第 250、500、1000、1500 步），与阶段 B 相同的 96 个单位。
- **C9（EMA）。** 对照训练中同时维护 fp32 与 bf16 两份 EMA，单位同上：u_t = ΔEMA_bf16 − ΔEMA_fp32（相对 ΔEMA_fp32 的范数）；
  训练层面的结果是结束时两份 EMA 权重各自的验证 loss（同一次训练内配对，种子 0–3）。
- 作用量与阶段 B 相同：γ̂、b̂（95% 区间，确认单位）、规则 R1、R2、R3、R5，ρ 相对 A1–A3（阶段 B 的单步值）。

## 3. 分类（事先写定）

- **超过尺子**：|γ̂| 或 |b̂| 的 95% 区间整体在 δ（0.05）之上；
- **在尺子之内**：两者的区间上界都在 δ 之下，报告上界与 δ 之比；
- **判不了**：其余情形。
- 两颗种子的影子测量分别分类；结论取两者一致的类别，不一致记为判不了。

## 9. 深案例预注册（2026-10-07，在任何深案例测量之前提交）

**C4 torchao AdamW4bit。** 源码（torchao 0.16）：二阶矩 v 用无符号 16 级线性码表且不含 0（`linspace(0, 1, 17)[1:]`），按 128 个
元素一块以块内最大值归一；每步用 v = lerp(dequant(v_prev), g², 1 − β₂) 更新并重新量化存回，所以小于块内最大值约 1/32 的 v 每步
被抬到 max/16，√v 偏大、更新变小。一阶矩 m 用有符号动态码表。
1. 机制归因（影子状态，种子 0，同第 2 节）：C4a 只量化 v（m 为 fp32）；C4b 只量化 m（v 为 fp32）。预测：|γ̂(C4a)| 接近 |γ̂(C4)|
   （≥ 其 70%），|γ̂(C4b)| < |γ̂(C4)| 的 30%。
2. 预注册干预：块大小 128 → 32（C4c，可部署的参数）。预测：|γ̂(C4c)| < |γ̂(C4)|；不预测是否落到 δ 之内。
3. 独立配对训练：以 AdamW4bit 为真实优化器训练种子 0–3，与 R′ 同种子配对。
4. 上游检索：torchao 的 issue / PR（AdamW4bit、4-bit optimizer、second moment、zero point）与当前 main 的码表。

**C9 权重 EMA 存为 bf16。** 机制假设：EMA 每步的增量 (1 − β)(θ − e)（β = 0.999）小于 e 在 bf16 中半个 ulp（约 2⁻⁹·|e|），就近舍入
后丢失，EMA 冻结在初始化附近。
1. 真实接口复现：纯 bf16 模型（P）上用 `torch.optim.swa_utils.AveragedModel(model, multi_avg_fn=get_ema_multi_avg_fn(0.999))`
   每步更新，结束时评估平均模型的验证 loss；对照为同一次训练中 fp32 的 EMA 缓冲（配对）。预测：bf16 的平均模型 loss 比 fp32 EMA
   高出远大于 σ_seed（0.0145）。
2. 预注册干预：EMA 缓冲保持 fp32（参数为 bf16 时把增量算在 fp32 中）。预测：与 fp32 EMA 参照的差在 σ_seed 之内。
3. 训练层面的结果：同一次训练内两份 EMA 的验证 loss 配对，种子 0–3。
4. 上游检索：PyTorch issue（AveragedModel / get_ema_multi_avg_fn 与 bf16）、文档是否有说明；常用库（timm、diffusers）的 EMA 是否
   默认保持 fp32。
