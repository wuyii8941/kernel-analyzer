## 1. 我们要回答什么

**能否建立一个以 Triton 为重点、机制和工具共同组成的框架，用有明确条件的数学
推导与统计检验，解释不同实现为何形成系统性训练更新，并通过局部修改验证具有
实际意义的训练后果？**

数学目标相同的实现仍可能产生不同 update。我们区分总差异、平均方向、相对缩放
和波动，但不让指标表或等价标签取代“成因为什么成立、修改能预测什么、训练是否
受到实际影响”这三个问题。

起点是 [Qiu 与 Yao 的 FlashAttention 分析](https://arxiv.org/abs/2510.04212)：
从具体舍入行为和 backward 公式出发，分析偏差怎样进入权重更新，再用训练与
针对性修改检查机制。我们沿用这条研究逻辑，不把其中一个 attention 机制当成
所有算子的通用成因，也不把训练崩溃设成每个案例的必要条件。

```text
声明实现与参考 → 数学成因 → local / gradient / 实际参数写入
→ 能量与方向分析 → 声明范围内的判断 → 局部修改与训练验证
```

我们已经有多种机制推导、测量、干预和训练结果。不为了某个分数过线而改成功标准。
现有汇总在补接 99 个此前已完成的 SiLU/normalization 结果后，共有 520 个有效位置；
这次增加是清单修正，不是新增实验或新增问题。它足以说明已有适配器不是单案例脚本，
但不能证明全部已观测 kernel 已支持。全部保存位置继续进入统一支持清单；清单用于
去重、发现空缺和保留失败原因，不再以把有效位置从 520 扩到更大数字为默认实验。
当前主任务是完成随机训练状态的统计含义，并对少数重要问题闭合机制—训练链；只有
主要算子族存在明确方法空缺时才补必要覆盖。位置总数不是成功指标，新家族能否复用
同一流程才是覆盖指标。
对未知实现可以先进行有效分析；不要求每个实现预先拥有一个非零 bias 定理。
只有要声称具体偏差成因时，才必须完成相应数学条件和干预验证。
覆盖进度见[统一执行入口](numerical_coverage_execution.md)。

2026-09-11，统一入口新增了两个已审核的专用参考适配器：RMS 归一化和状态递推。
家族优先清单自动选择各一个代表位置，自动冻结计划、运行三阶段采集、检查实际参数写入并
复算结果。`family_first_campaigns_v5/summary_final.json` 中两个位置均为有效测量，观察到的
固定状态集合 update 差异均为逐位零，因此它们是有效阴性，不是新的 bias 阳性；其余家族没有
被改选或伪装成阴性。这个结果证明新算子族可以复用同一测量和审计入口，但不增加 bias 数量，
也不替代后续的机制—训练后果验证。

同一入口随后生成了家族级“未测前沿”清单。它按静态家族身份合并位置，排除已有测量或
主线证据的族，并把此前 AOT 图哈希不一致、端口身份不一致和编译失败的族标为“先修参考
绑定，不要重跑”。在修复两个 runtime release 后，数据搬运/布局族和逐元素族各完成了
32 状态有效测量；confirmation 固定集合 update RMS 分别约为 41.53% 和 39.78%，对齐缩放分别约为
−8.62% 和 −7.91%。它们是新的家族级固定集合证据，但尚无总体或训练质量结论。当前清单中
剩余两个族仍需修复参考绑定，另一个族尚无可用参考适配器。`FUSED_MIXED` 的新 Mamba 尝试只完成
9/32 个状态，确认 AOT/`torch.compile` 采集会走不可接受的 sequential fallback，因此仍保持运行路径阻塞，
不进入有效覆盖或 bias 计数；详情见[未测算子族前沿](unmeasured_triton_family_frontier.md)。

### 算子族优先与去重（2026-09-08 用户校准）

后续覆盖面向全部已观测 kernel 建立清单，但按不同算子族选择执行顺序，不以位置数作为
默认进度，也不以增加根因机制数量为目标。
已有 source/response 两类机制语言在条件成立时保留，不强行给新算子发明机制。
搜索顺序按尚未完成有效测量的算子族优先，而不是按预测 bias 最大的位置优先。
优先补新族的真实执行、参考与三阶段接入；已有族的模型/shape 扩展用于确认覆盖，
不替代新族搜索。完成测量后的阴性结果也计入有效覆盖，但不计入 bias 案例。
逐通道一维卷积作为新的具体接入单列；历史 Gemma 视觉卷积已经属于卷积族，
不能把 Mamba 接入称为仓库首次发现卷积族。
同一问题换模型、shape、checkpoint、前后向阶段或递推分段，均不新增算子族；
不同算子族可以具有相同偏差根因。原始实验与协议不合并或删除。

早期汇总目录归纳为 10 族：矩阵乘法/线性层、normalization、softmax、cross-entropy/
fused loss、SiLU/门控、softplus、状态递推/scan、rotary/RoPE、独立求和/平方和归约、
索引梯度累加。该目录不是全仓库的穷尽分类，也不是 10 族都已确认 bias 或训练后果。
历史记录补查又发现该目录遗漏了 GELU 和卷积；后续真实测量接入 embedding、
Top-k/sort、optimizer parameter/moment update、fused causal attention 和逐通道偏置，
因此旧机器目录有 17 个展示分类。这不表示新增了 17 个 bias。新的全部位置清单根据
精确语义端点与结构记录覆盖实际出现的 18 个计算组，并保留融合输出的分类边界；两套
数字的定义不同，不能互换。Gemma GELU 的旧 formation 和视觉卷积的旧 gradient
测量须保留原统计版本，不能直接升级为新协议的完整三阶段覆盖。
嵌入在其他算子中的归约只作子计算，不以其名字重复计作新问题。

`scripts/summarize_operator_families.py` 对已审核参考标签作统一汇总，未知标签保留，
记录测量状态而不从家族名称推断阳性。不同来源的覆盖清单尚未全部汇合，某份汇总中
计数为零不等于仓库没有该族实验。当前 v11 已通过
`scripts/merge_family_execution_measurements.py` 将三份完整执行清单的 99 个位置按
release 和 task ID 接回，不以模型名模糊匹配。每族分别核对参考接入、有效三阶段测量、bias
证据和 loss 后果；“已测”和“已发现问题”不可共用一个数量。

最新 optimizer-update 接入由人工审核 TorchAO 8-bit AdamW 与标准 AdamW 的比较
语义，冻结后自动复用 32 个真实 Mamba loss gradient，执行两遍完全一致的 transition、
保存 Torch 编译生成的 Triton 源码并调用统一分析。gradient 输入逐坐标相同；确认集合
的一阶 moment、二阶 moment 和实际参数写入相对 RMS 差分别约 3.62%、0.551% 和
5.45%。参数写入超过声明的 1% 固定集合范围。它证明新家族可以复用同一分析入口，
[完整记录](optimizer_update_family_audit.md)

在此基础上，分块大小机制实验事前预测并确认：block size 从 64 增至 256、1024 时，
moment 与参数写入 RMS 差异严格增大。随后冻结的 8 条非重叠 WikiText 数据流各训练
1024 步；默认 256-block AdamW8bit 相对 FP32 AdamW 的最终评估 loss 差为 8/8
正，平均 `+0.02718`，95% 区间 `[+0.01217,+0.04220]`，超过预声明的
`+0.01` 实际幅度门槛。未出现崩溃；64-block 是否稳定改善训练 loss 未确认。
这是当前最明确的“数值机制 → 实际参数写入 → 有实际幅度的训练后果”链条，但范围
仍限于一个 Mamba checkpoint、八条数据流和声明 optimizer 设置。

为补足固定集合与随机状态总体的区分，后续协议从冻结的 8192 个 token 块经验分布中
独立有放回抽取 32 条长度 8 的 gradient history；每个统计单位重新建立 candidate 与
reference optimizer state。32/32 个单位的最终参数写入 RMS 差异均超过预声明 1%，
超范围比例的一侧 95% 下界为 91.06%，高于合同允许的 5%。这给出声明 history 总体的
精确有限样本不等价结论；它不证明平均 $Q$、递推训练状态或跨 checkpoint 总体。

基于 component 分解提出的第二轮修改也已完成独立训练确认：保留 FP32 一阶 moment
虽然把固定 gradient 上的写入 RMS 从 5.45% 降到 3.21%，但在另外 8 条新数据流上，
`default − modified` 的最终评估 loss 均值为 `−0.01070`，95% 区间
`[−0.02708,+0.00567]`，修改改善为 `NOT_CONFIRMED`；修改版相对 FP32 AdamW
的次要 loss 差均值反而为 `+0.03513`，区间 `[+0.01040,+0.05987]`。因此单步
update 更接近参考不能替代训练验证；这条修改链保持为阴性结果。

随后针对跨步量化残差提出的补偿修改在另一组 8 条预注册、非重叠数据流上完成确认。
主要比较 `default−compensated` 的均值为 `+0.0248481`，95% 区间
`[+0.0168563,+0.0328399]`，超过 `+0.01` 门槛，独立复算为 `VERIFIED`。因此，
在这个声明协议内，AdamW8bit 已形成一条完整的“递推数学来源 → 实际写入改善 →
评估 loss 改善”链条；补偿版的显存和速度代价、单 checkpoint 范围以及未观察到崩溃
必须同时报告，不能把它写成普遍或生产级优化器改进。

结果后的全模型核验使用 16 条新的独立 gradient history：block64 的全部参数实际写入
RMS 在 16/16 个单位中低于 block256，精确二项单侧 95% 下界为 82.93%。因此修改失败
不能再解释为旧机制只挑中了一个 `x_proj` 参数；现有证据更明确地指向“降低单步全模型
RMS 仍不足以预测递推训练 loss”。逐参数复算显示一个代表单位中 99.84% 的 block256
effect energy 来自 embedding 和最后一层 mixer output projection，后续机制分析应
围绕这些训练位置与 trajectory response，而不是继续枚举 optimizer 变体。

同一轮还正式接入 fused causal attention：在 Qwen 第一层只将 PyTorch SDPA 的
Flash backend 替换为 math backend，其余 27 层共同使用 math；两边都用无 padding
文本和同一个 `is_causal=True` 语义。确认集合的 local、q-projection gradient 和实际
参数写入相对 RMS 差约为 0.172%、11.47% 和 36.91%。这提供了一个幅度明显、不是
把 softmax 位置重新计数的新算子族，并展示小 local 差异如何在 backward/AdamW 中
放大。它是普通 CUDA Flash-SDPA candidate，不冒充 Triton；单步 loss 差正负均有，
尚不是训练质量结果。[完整记录](fused_attention_family_audit.md)

新的 Ministral fused RoPE / position scaling 计算也通过源码、实际 Triton 执行、
相同输入参考和目标参数绑定进入统一三阶段流程。高位置与低位置确认集合的实际参数
写入 RMS 分别约为 10.88% 和 8.35%，所以 position scaling 不是已证明的唯一来源。
在严格匹配的 cold、warm、warm 参数但清空 moments 三种设置中，写入 RMS 分别约
为 8.67%、0.45% 和 10.02%；warm 与清空 moments 的 gradient 统计完全相同。
这支持固定集合内的 optimizer-state 抑制，不是总体推断或 loss 结果，也不是事前
冻结的机制预测。[完整记录](fused_rotary_position_scaling_audit.md)

### 四个共同目标与完成标准（2026-09-07 校准）

| 用户目标 | 本篇必须争取的证据 | 不能充当完成证据 |
|---|---|---|
| 框架，机制和工具都有 | 在原仓库上自动接入、测量、复算；不同家族使用统一方法；代表机制有成立条件、修改预测及新数据验证 | 每例手写一套分数，或只有批量测量没有偏差解释 |
| 包含 Triton | 主要机制与局部修改对应真实手写/编译生成 Triton；常规 candidate 用同一方法，混合位置如实归因 | 库名含 Triton、源码扫描数或静态参数映射数 |
| 统计学理论完备 | 实际输出的偏差/等价结论有明确对象、抽样条件、误差控制和完整生产路径验证；适用范围一致 | 只有公式、加上 bootstrap、仿真跑完，或关闭总体输出后称理论完成 |
| 训练后果足够有说服力 | 首选可复现且可由针对性修改缓解的训练崩溃；否则是有实际幅度的 loss/perplexity、稳定性或固定质量下成本变化 | 单步大 update、参数距离大、微小 loss 不同、仅显著但幅度很小 |

这里的“自动”不要求程序自行发明修改或决定长训练方案。候选发现、实现与参考绑定、
共同状态恢复、三阶段采集、统一分析和报告复算应尽可能自动；根据诊断选择合法修改、
决定是否进入训练验证以及制定训练设置，可以由研究者完成。框架必须记录选择依据，
在查看确认结果前冻结修改预测和训练指标，并自动执行已审核的配置。这个人工参与是
设计边界，不再列作“必须消除的自动化缺口”。

这四点是一个研究方案，不是“四个关键词的组合首创”。截至本次文献核查，未找到
完整建立“跨实现统一偏差检验 → 机制预测 → 修改后的训练后果”这一联系的近邻工作；
这是有范围的创新性判断，不是对全部公开或未公开工作的不存在证明。
[逐篇比较与主张](novelty_positioning.md)

**当前仍未完成四目标整体。** 自动测量与 Triton 家族接入已有进展，并已获得一项
预声明幅度的 optimizer 训练结果；主要缺口是随机训练状态总体的统计结论，以及把
AdamW8bit、fused RoPE 等少数重要案例推进为更完整的机制—训练链。全部已观测 kernel
必须进入可追踪清单，但不要求逐位置运行完整训练分析；尚不能支持的家族保留具体原因。
后续资源原则为约 40% 总体统计、40% 两三条深机制/训练链、20% 必要的新家族覆盖。
一项训练确认也不能由自身补齐这些缺口。
单项运行是否完成、科学预测是否成立、论文目标是否达到分别记录，具体见
[完整验收范围](new_mainline_execution_status.md)。

总体统计不再以寻找一种无条件万能区间为目标。有限样本下，无总体能量上界时，不可能
对所有非负重尾分布从有限观测统一签发平均 $Q$ 等价；证明和反例见
[总体推断合同](population_inference_contract.md)。当前生产路径支持固定集合原坐标 $Q$、
有事前能量上界时的总体平均 $Q$，以及无需幅度上界但只控制超界状态比例的精确二项
判断。理论边界已经明确。AdamW8bit 已完成一项真实独立 history 总体的超范围比例
判断；平均 $Q$ 的真实总体证书仍因缺少观察前可用且有检出能力的能量上界而未完成。

## 2. “数学上可解释”不是给分数换一个名字

对被测实现和声明参考实现，先写出具体运算差异怎样到达目标 gradient/update。
再说明在什么输入、训练状态或舍入条件下，差异有非零平均分量或稳定的相对缩放。

一条公式可以精确说明误差如何传播，但还需要检查保证不抵消的条件。
反过来，测得方向显著也不能代替成因推导。“实际 backward 实现了正确的导数”
与“实现差异形成了 bias”是两个不同的证明问题。

当前已有的成因语言归纳为两项：

- **正负误差或它们与训练状态的配对不平衡**：例如分块累加、舍入、截断、缩放选择
  或前后向保存状态差异。求和顺序只是其中一种。
- **正负误差得到的响应不对称**：即使输入严格为 +e 和 −e，backward 或 AdamW
  产生的额外更新仍不互为相反数。

两项可在选定误差位置上作精确分解，但这个分解本身不证明某个案例非零。
低秩描述偏差怎样集中，不是必要条件；后续训练反馈解释分离怎样延续，不是第三个
原始成因。具体条件和公式保留在[成因推导](effective_antithetic_symmetry.md)中。

## 3. 三阶段测量检查推导，而不是代替推导

```text
算子输出差异 → 真实参数 gradient 差异 → 目标 optimizer update 差异
```

每层同时记录差异大小、共同方向、相对正常计算的缩放和去掉缩放后的剩余方向。
它们回答推导中的作用是否出现、在哪一步改变，以及幅度有多大。

“前一层没检出，后一层检出”是定位线索，不自动证明该层是唯一根因；还应看效应量、
测量能力和干预。Qwen 的 cold-start 短测与 warm-state 长测不同，说明结论依赖
声明状态，不能把“被 AdamW 抵消”写成永久属性。

有限步方向分数、置信区间、工程阈值和 update 等价检查各有明确作用。
等价判断是正式输出之一，但不是对任意未来训练的通用安全证书。

## 4. 选定案例要争取强训练后果，单项分析不强求阳性

loss 分叉能证明一对轨迹不再相同，但不自动证明质量下降；参数距离也不能替代验证
loss。对最有信息量的案例，使用独立配对训练检查局部修改是否带来质量、训练成本
或稳定性的可重复变化。论文希望解释可复现的训练崩溃；没有崩溃时，也要争取实际
幅度足够的训练后果，而不满足于统计显著但极小的差异。

在新确认结果揭示前，声明主要训练指标、评估时点、最小有意义幅度及其理由，
用独立配对运行同时检查幅度与不确定性。低成本/高速度主张还需在质量相当的条件下
测量。不能从当前小差异反推一个刚好通过的幅度标准，也不设所有 LLM 共用的常数。
若有限确认计划未取得这种证据，保留负结果，标明第四目标未达成并收窄相应主张；
不把“不强求每例崩溃”偷换成“整篇不再需要有说服力的训练结果”。

需要对齐模型、实现差异、参数范围、optimizer、初始状态和数据顺序。配对训练从
相同起点出发，随后允许两边的参数和 moments 自然分开。loss 在同一个评估输入上
比较；不能拿两边不同 batch 的 loss 差当实现后果。

应分别记录：

1. 当前仍有目标实现直接造成的 bias；
2. 直接作用减弱，但此前差异通过训练反馈继续影响更新；
3. 只观察到 loss 不同，尚没有与之对应的 bias 证据。

前两类都可能有研究价值；第三类不能仅凭分叉升级为成因案例。已经建立成因、
后续直接作用不再持续的结果仍保留，不能一律删除为“失败”。

“持久”另注明经过了哪些训练阶段、哪些后期窗口检查。它不由 32 或 4096 这个数字
定义。loss 差异的正负也不是 bias 有无的判据。

## 5. 现有证据怎样组成主线

完整来源和比较限制见[案例地图](case_evidence_map.md)，不再用一张旧审计表代替
全仓库当前状态。

| 研究问题 | 已有代表证据 | 不应跳过的边界 |
|---|---|---|
| 数值源怎样打破抵消？ | Liger 分块累加推导、累加精度修改；同 FP32 不同顺序的补充预测实验 | 不同模型和顺序实验不能拼成一次同协议验证 |
| backward 怎样改变偏差？ | Phi、Qwen 的实际 lm-head backward；Phi 同 AdamW 随机舍入干预 | SGD、cold-start、warm-state 分开；局部无偏不保证 optimizer 无偏 |
| 对称误差为何仍留下更新？ | saved-P、SiLU 的严格正负重放与 AdamW 响应分解 | 人工正负响应与自然实现差是两种实验 |
| bias 是否只是一种固定方向？ | Liger 剩余方向，Phi/v-proj/Mamba 的相对 update 缩放 | 不同几何不是自动新增几个独立成因 |
| optimizer 状态是否影响它？ | 两个 DeepSeek 位置的 cold、warm、重置 moments 对照 | 测到缩放不等于已证明每个新位置的具体底层成因 |
| 实现差异是否进入 loss？ | 历史配对长测；新 Liger 小模型全参数训练到 10000 步 | 单参数实验、全参数实验、单轨迹和多条数据流分开 |

### 最新 Liger 后果

高压力设置第一条数据流延续自同一 4096 步 checkpoint，保持 AdamW 历史，
续跑学习率为 1e-4。4 层小型 GPT-2、字符级数据、全参数训练：

| 量 | 4096 步 | 10000 步 |
|---|---:|---:|
| 参数相对 L2 距离 | 19.69% | 23.50% |
| 被测实现 − 参考实现验证 loss | +0.02778 | −0.02325 |

最后 128 步 training-loss 比约 1.00048，未观察到声明的训练崩溃。
**loss 分叉存在，但不是持续朝更差方向发展。** 这条延续没有逐步重新拆直接作用
和反馈，不能从参数距离增大推断后期直接 bias 的强度。
[设置、数据与解释](liger_single_boundary_collapse_experiment.md)

### 实际参数写入与公式 update 必须分开

v1 将 update 先舍入到 BF16 再加到参数上。审计发现它可能与实际 AdamW 写入不同，
因此不能继续把该表中的零值或非零值当成目标 optimizer 的实际写入证明。
历史 JSON 和推导不删除；[旧表](training_numerical_analysis_v1.md)保留历史含义。

v2 从声明的参数与 moments 开始，真实执行一次 `torch.optim.AdamW.step()`，
读取前后参数变化。当前确认协议采用从存储参数初始化的 FP32 master，明确不声称
恢复了过去未保存的 master 权重。Phi 的固定确认集合写入 RMS 约 5.47%；这是新
参数表示下的结果，不是对原 BF16 协议的同条件复现。方向、成因与 loss 仍分别判断。
其他案例的复采、执行失败和未完成项目见[修正记录](training_numerical_analysis_v2.md)。

### 新增的配对训练验证

另行冻结的真实 tokenizer / WikiText 实验已完成 16 组新初始化配对训练，每组
1024 步。共同 FP32 验证 loss 中，15 组原实现高于参考实现，平均差 +0.00069609；
预声明单侧符号检验 p=0.00025940。它支持该四层模型、固定数据与训练设置下的
小幅可重复 loss 差异，不是工程收益幅度或持久 bias 的单独证明。
[新确认结果](../results/property/training_numerical_analysis_v2/language_training_confirmation_iid/summary.json)

后续恢复这些训练的真实末期参数和 moments：32 个 checkpoint 均仍有直接更新
差异，且两半输入的平均差异同向。另在一个相同设置的真实状态上，由 128 个

## 6. 研究范围与实现身份

研究具体训练算子与边界明确的计算区域，重点是 Triton，也允许 ATen/CUDA、
非融合表达和混合路径。三个问题必须分开：做什么数学计算、实际执行什么代码、
哪个实现被选作比较参考。

参考不是绝对真值，提高精度也不自动证明全部语义正确。只有在声明目标上改善并有
验证的变体才称为修复。数学结论应明确是相对哪个参考、在哪些条件下成立。

特别是，Liger 库使用 Triton 不代表其每个误差位置都在 Triton 内。当前安装源码的
dW 累加在常规矩阵乘结果之后；历史运行的具体执行身份仍以当次证据为准。

## 7. 保留的工具与历史结果

- 首轮 1,562 个输出位置是覆盖数，不是完整 bias → loss 案例数。
- 历史六个完整 F+B/参考/参数/32 步记录、统一 AdamW 三个主案例、
  五例统一测量、16 项冻结验证集和 4096 步逐行审计，是不同集合。
- 三阶段测量 v2、等价检查 v2、长程标签各有协议，不共享一个“v2”含义。
- 阴性、未决、非零但不持续的记录全部保留；它们限定成因与后果的范围。
- 大向量随机摘要不是原向量能量的严格上界。已有摘要结果保留其原测量含义；
  不把旧标签改写成数学保证。
- 新的整理和重新分析不回填为旧实验的事前预测。loss 方向放大检查不是未来训练
  外推，人工注入也不是自然实现已经发生的后果。
- 新采集把 AdamW 公式计算出的 update 与参数存储格式中的实际写入分开；旧结果只按
  其原端点解释，不通过改名升级为实际写入证据。

## 8. 文档与后续工作的边界

论文围绕本页四目标组织：框架与机制、真实 Triton、结论所需的统计理论、强训练
后果共同构成目标。loss 与成本不必对每条记录都测，但必须为选定机制争取有说服力
的训练验证。理论条件、测量和训练后果不能跨配置拼接。

后续优先修复统计有效性与参考归因，按有限计划补未参与开发的家族/状态，优先分析
自然 warm 训练中有可靠作用且能提出修改预测的机制。扩大覆盖仍是框架任务，不能
单靠更多同族位置代替机制和训练结果；也不为得到崩溃而无约束改变模型或学习率。
