# Bias-formation property tournament

This is the next experimental layer after the frozen T1--T4 and SEUP
evidence.  It does **not** assume that source--transport alignment is the only
mechanism.  The question is narrower and falsifiable:

> At which transition does a local endpoint difference first stop being
> centred and become a directional training bias?

The unit remains one exact forward invocation plus its actual backward.  The
four recorded transitions are:

```text
local endpoint residual
  -> parameter-gradient residual
  -> effective optimizer-update residual
  -> paired trajectory drift
```

## Frozen tournament

The protocol and roster are generated by:

```bash
python scripts/build_bias_property_roster.py
```

The current roster contains eight project cases and one external Flash
Attention control.  The external control can validate the measurement chain,
but cannot count as a project discovery.  Every case has 16 calibration and 16
disjoint evaluation slots.  Calibration is open-loop and freezes any declared
projection; evaluation is a new closed-loop paired trajectory.

The six candidates are deliberately hypotheses rather than labels:

| ID | Candidate | Formation question |
|---|---|---|
| P1 | Conditional source asymmetry | Is the local event conditional mean already directional? |
| P2 | Source--transport alignment | Does pairing a centred residual with the real cotangent/Jacobian create direction? |
| P3 | Forward--backward numerical consistency | Do saved/reconstructed/scaled representations disagree across F+B? |
| P4 | Nonlinear rectification | Does a sign-symmetric perturbation become directional through a nonlinear region? |
| P5 | Optimizer rectification | Does a centred gradient residual become directional after moments/preconditioning? |
| P6 | Semantic-orbit centering | Do mathematically equivalent schedules have a systematic update orbit? |

SEUP is not a competing formation property.  It is a persistence/consequence
measurement after an effective update has already become directional.  Existing
T1--T4 and SEUP verdicts are immutable and cannot be used as predictors,
calibration gates, or roster-selection criteria.

## Bias transition certificate

`src/kernel_analyzer/bias.py` and `scripts/run_bias_trace.py` implement the
candidate-blind data layer.  A normalized trace row has one declared scalar
projection and norm per transition.  Full tensors can remain in `/data1/tzh`;
the repository stores only compact projections, block summaries, digests and
certificates.

The certificate reports, separately for calibration and evaluation:

- signed mean, variance, skew and mean-to-norm ratio;
- signed persistence (`abs(sum) / sum(abs)`);
- `CENTERED`, `BIASED`, `NONFINITE` or `UNRESOLVED` status;
- the first non-centred transition;
- whether temporal persistence is present under the frozen engineering gate.

Missing layers, malformed values and non-finite values fail closed.  No value
is imputed as zero.  Continuous metrics are retained even when a categorical
status is unresolved.

## Promotion rule

A candidate can become a cross-mechanism property only after all five tests
pass: non-circular calibration, replication across distinct mechanisms,
positive/negative discrimination, a matched causal intervention, and an
improvement over tolerance/norm baselines.  Otherwise it remains a
case-specific mechanism, a counterexample, or unresolved.  The tournament may
therefore end with multiple mechanisms or with no single headline property.

The formation result directory is `results/property/bias_formation_v1/`.
Only its protocol, roster, compact property matrix and atlas should be kept in
Git; full vectors and replay tensors remain local.

The Flash-style anchor is used as a methodological reference: that work
attributes failure to biased low-precision rounding interacting with similar
low-rank attention representations, and validates the explanation with a
minimal repair ([Qiu and Yao, 2025/2026](https://arxiv.org/abs/2510.04212)).
Related work motivates testing forward/backward scaling contracts and
optimizer dynamics, but does not determine this project's labels:
[transposition-invariant FP4 scaling](https://arxiv.org/abs/2607.24953) and
[stochastic rounding with Adam](https://arxiv.org/abs/2502.20566).
