## 1. 选这两组共同阻塞的理由

上一轮结构验收暴露的两类问题，正是 rc3 要求「先行」的两件事（CODEX_TASK 第 3、4 条）：

1. **按写法识别 combine。** 5 个 T1 程序的 Welford 变体全部以「unrecognized reduction combiner」被拒，其中 3 个在实数上与 Welford 等价。
2. **执行有效性缺失。** T5 的 4 个程序在同一 program 内写后读、中间没有屏障，被当成 K − G 的数值作用；跨 program 的读后写只抓到一半。

## 2. 目标签名与做法

| 项 | 目标签名 | 做法 | 状态 |
| --- | --- | --- | --- |
| A | `tt.reduce`，任意 combine 区域（单值或多值） | 沿 TTGIR 布局给出的 lowering 次序逐步解释区域，得到顺序特定的目标（02 §6.2）；Welford 闭式保留为快速路径 | 已实现，测试通过 |
| B | `tt.load` / `tt.store` / `tt.atomic_rmw` 的执行效应；`gpu.barrier` | 跨 program 读后写与写后读；同一 program 内写后读的线程级判定（TTGIR 布局，同线程有序，异线程竞争，映射未知则未建立）；屏障分阶段 | 已实现，测试通过 |
| C | 重复启动（02 §8.7） | 每个输入至少启动两次并逐位比较。不一致时：已接纳的原子程序按输入内平均；已判竞争的不进入统计；原因不明的只诊断，记执行有效性未建立 | 登记后实现 |

## 3. 预算

- 实现：A、B 已用约半天；C 估计半天。
- 回归实验（§4）：主轮种子（开发 0–31、确认 32–95），模式 B，32 个常规程序，16 个进程。
  C 项里重复启动只重捕获 K、不重算参照，预计 T7 的耗时降到上一轮的 1/8 左右，总墙钟约 1 h。超过 2 h 先报告。

## 4. 回归实验的预计结果（运行前写定）

v1.1 的 33 个程序从此只作开发集与回归集，这里的结果不是盲测成绩。

| 程序 | 4.0 预计 | 依据 |
| --- | --- | --- |
| prog_17、prog_20（带保护的 Welford 变体） | 参照完整 | 通用区域沿 lowering 树求值，权重精确，保护分支可判定 |
| prog_32（去掉 δ² 项） | 参照完整 | 同上；它不是 Welford 等价写法，由通用求值处理 |
| prog_08（δ² 用内联 `mul.rz`） | 参照完整 | `mul.rz` 已在内联算术表中登记（数值差异模式下即实数乘法） |
| prog_29（无保护的比值） | 均值与方差未建立：实数下的 0/0 | BLOCK = 2048 而 D = 1536，被 mask 的 512 个元素权重为 0。若某个线程持有的 8 个元素全被 mask，线程内合并就出现 0/0。这不是覆盖缺口，是实数语义无定义 |
| prog_01、13、22、23（T5） | 执行竞争；输出未建立；不进入数值统计 | 标量由线程 0 写，所有线程读，中间无屏障 |
| prog_11、18、19、27（T7） | 参照完整；两次启动不逐位相同；按原子执行随机性在输入内平均 | float atomic_add 的次序；返回值未使用，可交换 |
| 其余 19 个常规程序 | 参照与 v3.1 逐位相同，判断不变 | 这次改动不触及它们的路径 |
| prog_26（边界项） | 不运行 | 环境权限检查；同类模式已由 CPU 合成用例覆盖 |

安全标准（04 W4）：被标记为竞争或不一致的任务上，数值判定为 0。
