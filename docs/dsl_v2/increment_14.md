# DSL v2 第十四个增量：登记（2026-10-09）

分支 `dsl-v2`，工具 4.0（开发中）。对应 rc3 正式版 02 §5.3、§10（集合目标 L_E）与 04 W4（原子与调度相关的集合参照）。
本登记写于实现之前。

## 1. 选这组的理由

官方主线的广泛捕获（`results/dsl_v2/main_capture/inc6_combined.jsonl`）中，最大的未完整类是
「set-valued integer atomic return value (L_E) is not representable as a point」：244 次启动（`test_atomic_rmw` 的整数类型为主）。
增量 4 已经把浮点原子返回值作为集合目标（各交错下返回值的包围）；整数返回值至今只接受点值。Gluon 的 `test_core` 中
local atomic 的整数返回值是集合的 12 次启动也属此类。rc3 §5.3：「若 G_set 有限且可包围，可先形成所有允许残差的区间」；§10：
集合参照给出对所有允许选择都成立的残差上下界。整数集合用包住它的整数区间表示，是 §10 允许的形式。

## 2. 做法

| 项 | 内容 |
| --- | --- |
| A | 返回值集合（`_atomic_old` 整数分支）：各交错返回的是初值与其他更新的某个子集的组合。add：[v + Σ负贡献, v + Σ正贡献]，越出该宽度的有符号范围（表示里会回绕）则未建立；max / min：[v, max(v, 其他)] / [min(v, 其他), v]；umax、umin、exch：返回值必是初值或某个贡献之一，取这些候选的包围；and / or / xor：逐个贡献求可达值集合的闭包（超过 4096 个值则未建立），取其包围。原有的点值判定保持在前 |
| B | 值的表示：整数值带上界 `hi` 即为集合（区间 [lo, hi]，元素宽度的有符号表示）。只有不改变值的操作可以原样传递：`tt.store` 与 `amdg.buffer_store` 的被存值、`ttg.convert_layout`、`amdg.in_thread_transpose`、`tt.splat`、`tt.broadcast`、`tt.expand_dims`、`tt.reshape`、`tt.trans`。其他任何操作（算术、比较、选择、地址、循环边界、原子操作的操作数、共享存储、调用等）收到集合时，相应 lane 记未建立并写明原因，不当作点值 |
| C | 存入全局缓冲：求值器内部这些元素仍是「未建立」（之后的读、原子操作、竞争检查都不会把集合当点值用）；另记一条集合记录（下界、上界、写入的 program）。启动结束时只有满足下列全部条件的记录成立：该元素仍是这次写入的结果（之后没有别的写：值、写入者、状态都未变）；写入的 program 没有中止、没有卷入执行竞争、没有两遍求值不一致；目标缓冲没有被经未建立地址的 store 污染；没有走 CAS 双序重算；未决的 `scf.if` 两支给出的记录一致。上一次启动留下的集合，在这次启动没有被写、启动没有中止、且求值了全部 program 时才保留 |
| D | 报告：成立的集合元素在 `KernelReference` 中单列（类别 `set_target`，区间 [iset_lo, iset_hi]）；主线捕获与两层对照插件把它算作已建立的集合目标；`compare()` 对整数输出报告实际值落在集合内外的个数 |
| E | 未纳入：check / measure 对整数输出的统计不变（它们现在只把点值算作已建立）；整数集合不进入后续启动的 load（读到的仍是未建立） |

## 3. 评价设计（实现前写定）

- **复跑**：官方主线下跑官方 `test_core` 中 `atomic` 相关测试（main_capture_plugin），与增量 6 的同名测试比较每次启动的状态。
  另跑官方 Gluon `test_core` 中 local atomic 相关测试。
- **独立核对**：逐签名测试中，用独立的小模拟器枚举少量 program 的全部执行顺序，得到每个 program 实际可能返回的值，核对它们都落在
  参照给出的区间内；回绕、闭包上限、各类误用（集合作地址、作循环边界、参与算术、存入后被覆盖、未决分支只有一支写入、跨启动后被覆盖）
  逐一构造。
- 逐签名测试三类齐全，违反 0；回归不变。

## 4. 预期

- 复跑中，原来唯一的未建立原因是「整数原子返回值是集合」的启动，全部变为「完整（集合目标）」；只有包围越出整数宽度时仍记未建立（写明原因）。
  原来完整的启动状态不变。
- Gluon local atomic 中整数返回值是集合的启动同样变为「完整（集合目标）」。
- 独立模拟器枚举的所有执行中，实际返回值全部落在参照区间内（违反 0）；各类误用全部不给出点值或集合声明。
