# DSL v2 第四个增量：登记（2026-10-09）

分支 `dsl-v2`，工具 4.0（开发中）。对应 rc3 正式版 04 的 W4（内存、并发和运行时），依据 02 §5.3、§6.3、§6.9、§10。
本登记写于实现之前。

## 1. 选这组的理由

用官方主线 `e50b186e` 跑官方单元测试并捕获启动，再用增量 3 的求值器求值，不完整的启动几乎都来自原子操作：

- 260 个启动只得到部分参照，原因都是「原子返回值依赖未声明的次序」。全部来自 `test_atomic_rmw`：5 个 program 对同一地址做原子操作，各自把返回的旧值写到 `Old`；
- 80 个启动中止，原因是「i32 访问 f32 缓冲（位重解释）」或 i64 访问 f64。Triton 前端把浮点 `atomic_max/min`
  降成整数视图上的一对操作：非负值用 `max`/`min`，负值用 `umin`/`umax`。

审查同一段代码时还发现一个可靠性缺口：同一次启动里，不同种类的原子操作（例如 add 和 max）落在同一地址时，现在按 program
求值顺序折叠，只给出其中一种次序的结果。rc3 §6.3 要求原子的最终折叠有相应的代数律。这个缺口顺带修掉。

## 2. 目标签名与做法

| 项 | 签名 | 做法 |
| --- | --- | --- |
| A1 | `tt.atomic_rmw`，返回值被使用，地址无竞争 | 按一次启动做两遍求值。第一遍记录每个地址收到的全部原子贡献（program、lane、种类、值区间）。第二遍从启动前的内存重来：某次原子访问若是该地址在本次启动里唯一的原子访问，且没有其他非原子写，返回值就是启动前的值。这是点值（L_Q/L_C） |
| A2 | 同上，地址有竞争 | rc3 §5.3/§10 的集合目标（L_E）：返回值取「启动前的值 ⊕ 其他贡献的任意子集」的凸包。fadd：init + [Σmin(0,l_j), Σmax(0,h_j)]，外向舍入；max/min：[init, max(init, max h_j)] 或其镜像。结果标 `set:` 原因，单独计数，不算可收紧的点参照。整数结果只能表示点，所以有竞争时记未建立，原因写「集合值整数结果无法用点表示」；凸包超出 float64 有限范围时记未建立（例如 max 的中性值 −inf） |
| A3 | 两遍一致性 | 第二遍的原子事件表必须和第一遍一致（地址、贡献、种类）。有差异，或某地址有贡献依赖于第一遍未建立的返回值，相应返回值记未建立 |
| B1 | 整数指针访问同宽浮点缓冲的原子操作 | 位视图：被访问地址的值必须是可精确表示的点（与 `tt.bitcast` 同一条「位确定」政策）才取位，否则记未建立。整数运算结果按位写回浮点缓冲 |
| B2 | 同一地址上混合种类的原子操作 | 最终值只有在混合种类有联合次序律时才折叠。登记两条可检查的证书：{max 且贡献 ≥ 0, umin 且贡献 < 0} 等价于按浮点键取最大；{min 且贡献 ≥ 0, umax 且贡献 < 0} 等价于按浮点键取最小（纯整数陈述，与 NaN 无关）。其他混合记未建立，原因写明 |
| C | `xchg` | 无竞争时为点；有竞争时，浮点的最终值和返回值都取全部候选值的凸包（L_E）；整数记未建立 |

不在本增量内：CAS 的有限交错枚举与协议摘要（自旋锁、轮询）；整数集合结果的区间表示。

## 3. 预算

实现约半天；捕获复跑（只跑 `test_atomic_rmw` 一组）约 15 分钟；逐签名测试约 1 h。

## 4. 预期（实现前写定）

- `test_atomic_rmw` 的 260 个部分参照启动里：
  - fadd 类（float16、bfloat16、float32、float64）的 `Old` 由未建立变为集合完整（L_E）；
  - 中性值为 ±inf 的 max/min 仍未建立（凸包非有限）；
  - 整数 add/max/min 的 `Old` 仍未建立（整数集合）。
- 80 个中止启动变为可求值：`Z` 完整（证书 B2 成立），`Old` 未建立（整数位视图上的集合）。
- 单地址无竞争的返回值（逐签名测试构造）为点值完整。
- 包含性违反预计为 0。混合种类不满足证书的构造（逐签名测试构造）报告未建立。
- 回归：已有全部测试不变。
