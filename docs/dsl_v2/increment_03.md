# DSL v2 第三个增量：登记（2026-10-09）

分支 `dsl-v2`，工具 4.0（开发中）。依据 rc3 正式版 04 的 W3（主线经典前端）、W4（原子 / CAS）、W5（块缩放格式）。
本登记写于实现之前。

## 1. 选这几组的理由

- 用官方主线 `e50b186e`（3.9.0）跑官方教程和单元测试，转储出 473 个唯一 TTIR。旧解析器全部能解析，439 个的每个操作名都有规则。
  挡住其余 34 个的只有 4 个名字：
  - `llvm.intr.assume`：32 个 kernel；
  - `ttg.barrier`、`tt.atomic_cas`、`tt.dot_scaled`：各 1 个。
- 名字之外，主线的产物能否真正求值还没有证据：捕获模块是按 3.6.0 的运行时写的。

## 2. 目标签名与做法

| 项 | 签名 | 做法 |
| --- | --- | --- |
| A1 | `llvm.intr.assume` | rc3 02 §12：编译假设不是可随意擦除的提示。沿参照路径逐样本检查条件：成立则无作用；不成立就判这次执行的参照未建立，原因记「假设被违反」；判定不了也记未建立 |
| A2 | `ttg.barrier` | 与 `gpu.barrier` 相同，开始新的访存阶段（按地址空间属性；本增量把所有地址空间都当作受序） |
| A3 | 捕获模块兼容主线运行时 | 在官方环境里用 `TritonLaunchRecorder` 捕获官方教程的真实启动，再用 4.0 求值器求值；结果分完整、部分、中止三类，中止的按原因列出 |
| B | `tt.atomic_cas` | 本增量只做到「如实报告」：CAS 的结果依赖交错次序，记执行有效性 / 参照未建立，并写明「CAS 交错关系尚未建模」，不静默。有限交错枚举与协议摘要留到下一增量 |
| C | `tt.dot_scaled` | MX 块缩放格式精确解码（fp8 e4m3 / e5m2、fp4 e2m1 打包、e8m0 缩放），按实数做精确点积；未知格式或布局记未建立 |

## 3. 预算

A 约半天，B 约 1 h，C 约半天。

## 4. 预期（实现前写定）

- **A1、A2**：官方测试转储的唯一 TTIR 中，操作名全部有规则的比例从 439/473 升到至少 471/473；剩下的是 CAS 和 dot_scaled 各一个。
- **A3**：
  - 教程里的 vector-add、softmax、layer-norm：参照完整；
  - matmul 类：默认 tf32 的 dot 在数值差异模式下可以求值，参照完整，dot 精度记为属性；
  - fused-attention、persistent-matmul：若用到 tensor descriptor 或 TMA，在 sm_86 上走回退路径，参照预计完整；否则按原因记录。
  - 若捕获模块因运行时 API 差异无法工作，先修捕获，再给出比例。
- **B**：含 CAS 的 kernel 全部报告为未建立，原因写明。
- **C**：用 4 条逐签名测试核对包含性（正例、边界、违反前提，fp8 与 fp4 各覆盖）。包含性违反预计为 0。
