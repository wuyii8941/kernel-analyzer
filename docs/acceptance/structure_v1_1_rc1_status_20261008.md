## 3. 参照完整率（主轮，模式 B）

- **程序级「全部必要输出已建立」**：27/33（全部 33 项），27/32（32 个常规项的条件比例）。
  输出级为 27/38。TTIR 覆盖完整的程序为 27/32。
- **5 个 T1 程序未建立**（prog_08、17、20、29、32，共 10 个输出），原因是语义缺失：`tt.reduce: unrecognized reduction combiner`。
  冻结的 Welford 匹配器只认 Inductor `welford_combine` 那一种数据流，即 `r = select(W==0, 0, w_b/W)`，
  `M2 = M2_a + M2_b + δ·δ·w_a·r`。包里的写法有五种：
  - prog_17、prog_20：把 W = 0 的保护放在输出上，并用 `safe` 作除数；
  - prog_29：写成 `w_a·w_b/W`，而不是 `w_a·(w_b/W)`；
  - prog_08：δ² 用内联 `mul.rz`；
  - prog_32：去掉了 δ² 项。

  前三种在实数上与 Welford 合并等价，却被拒绝。工具没有猜测接受它们，这符合设计，但确实是一个通用性缺口。
  修正属于语义变化，要出新版本，不在冻结验收里做。
- **边界项 prog_26**：没有运行，因为隔离运行未获批准。它计入 33 项分母，记为未建立；没有算作正确拒绝。
- **调用级完整**：一律未建立。工具自己把 27 个输出都分到调用级（上游只有声明的输入和全零缓冲），
  但协议 §1 不允许仅凭内容相同或全零升级到调用级。
- **分辨率**：
  - 22/27 个已建立输出，每个元素的包围宽度都不超过 1/8 ulp；
  - 4 个 T2 程序（prog_15、24、25、28）有 0.03% 的元素超出，最大 668 ulp；
  - prog_30 有 0.13% 的元素超出，最大宽度按中点 ulp 计为 4.6e32；
  - 这 5 个都记为「包围太宽」。

## 6. 不能据此说的

- 这不是盲评分数，没有检出率，也没有误报率。
- 「非零」是对某个投影的平均作用的判断，不是逐元素的契约违反。
- 「未确认」不等于没有 bias。
- F 的区间排除 0 只是样本差异证据。
- 把 G 与 f 不相交的元素判定为规格反例还是程序语义差异，本轮不做。
- T7 的运行时调度分布是声明的假设。
- 复现轮与主轮共用开发块，不是完全独立的重复。

## 7. 待决

1. **出题方重新封存答案之后才能计分。** 计分脚本要按 v1.1 的标签格式写，并以本运行的作业文件为输入。
2. **Welford 匹配器的通用性缺口（§3）。** 一种做法是对合并区域做代数等价归一化，例如有理函数恒等判定，而不是按字面匹配数据流。
   这属于语义变化，要出新版本，只能在揭盲之后做，并用回归集重验。
3. **prog_26 的隔离运行**需要批准，并要有独立子进程、超时和静态依赖证据。
4. **等价判断。** 要做的话，需要事先声明 δ 及其依据。
5. **定位。** 本轮的定位预算为 0，非零项的核内定位没有做，要单独立项。
