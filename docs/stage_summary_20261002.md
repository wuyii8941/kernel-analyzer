# kernel-analyzer 阶段性总结与系统 prompt

2026年10月2日 · @wuyii

本文供后续会话作为系统 prompt 使用：它写定了研究问题、已确认的方法、已被纠正的说法，以及下一步的实验操作。凡与本文冲突的旧结论，以本文为准；凡本文标为「未验证」的内容，不得在报告中当作已成立。

## 1 研究问题与估计目标

研究对象是训练中数值实现差异的系统性作用，不是误差大小。工具的输入是一个 Triton kernel（或其他实现）在真实训练中的执行，输出是：这个实现相对参照，在声明的训练分布上，是否对参数写入产生非零的平均作用。

### 五个问题的主线（讲稿 [bias_chain_final.md](bias_chain_final.md)）

1. 为什么不同：实现 K 与参照 K_R 在同一输入上为何给出不同的数。
2. 怎样进入更新：局部差 e 怎样变成梯度差 δg，再变成参数写入差 u。
3. 换一批状态是否成立：u 沿预先固定的方向投影后，平均是否非零。
4. 沿训练怎样累积：逐步的平均作用如何在独立训练历史上加总。
5. 对训练质量的影响：配对训练的 loss 差与失败次数。

五步是证据链，不是必然发生链：前一步成立不保证后一步成立，阴性与边界案例因此也是结果。

### 估计目标

一次比较的输入是 (s, b)：s 是完整的训练状态（参数、两侧 optimizer 状态、步数、随机状态），b 是本步数据。记 θ⁺ 为一步更新后的参数，候选实现 K 与参照 K_R 各走一步：

$$u(s,b)=\theta^{+}_{K}(s,b)-\theta^{+}_{K_R}(s,b)$$

预先固定一个只依赖状态与本步数据、不依赖结果的单位方向规则 w(s)。投影 a = ⟨u, w(s)⟩。估计目标是

$$\mu=\mathbb{E}_{(s,b)\sim\Pi}\big[\langle u(s,b),\,w(s,b)\rangle\big]$$

Π 是声明的训练分布：从哪些 checkpoint 抽状态、每个状态重抽多少个 batch。两种规则对应两种分别报告的命题：常向量规则 w = ν̂ 检验平均方向作用；参照更新方向规则 w = D r_s / ‖D r_s‖（r_s 为参照更新，D 为事前选定的坐标集）检验对齐效应，两者可以并存也可以一个为零一个非零。w 不参与训练，只是测量尺子。

判定分四类，只答存在性，不做「无偏差」声明：检出平均作用（区间不含 0，在声明的 Π、α 与事前比较集合下）、未确认（区间含 0，证据不足）、证明为零（仅穷举有限输入库或解析证明，须标测量点与范围）、无法有效判断。

## 2 误差记账：两级恒等式与逐节点分解

记账回答「差从哪里来」，它是声明模型下的恒等式，不是机制分类，也不是检测完备性的证明。

### 顶层：两项

设 K 为实际执行，K_R 为按程序声明的计算在实数算术下求得的参照（第 4 节），f 为任务规格（这个 kernel 替换掉的那段计算）。加减同一项：

$$K - f = (K - K_R) + (K_R - f)$$

第一项是数值保真度：程序算的数与它声明的数学之差。第二项是语义：程序声明的数学与任务要的数学之差。没有 f 时取 f := K_R 的声明语义，报告写明「任务语义未检验」，此时第二项为零是定义，不是正确性证据。

### 节点层：四项

把一次 kernel 执行看成有向无环图。每个节点 n 有实际执行 K_n、精确语义 g_n（指令在实数上的定义）、规格 f_n（可缺）；每条输入边有指定生产者（这个输入应当是哪个节点的输出，来自训练计算图）。记 x̂_n 为实际读到的输入，x̄_n 为指定生产者的实际输出，x*_n 为全部按规格精确计算时应得的输入，y*_n = f_n(x*_n)。在 ŷ_n − y*_n 中间依次加减 g_n(x̂_n)、g_n(x̄_n)、g_n(x*_n)：

$$\hat y_n-y^*_n=\underbrace{K_n(\hat x_n)-g_n(\hat x_n)}_{①}+\underbrace{g_n(\hat x_n)-g_n(\bar x_n)}_{②}+\underbrace{g_n(\bar x_n)-g_n(x^*_n)}_{③}+\underbrace{g_n(x^*_n)-f_n(x^*_n)}_{④}$$

① 节点自身的计算误差（舍入、求和顺序、近似指令、硬件行为、并发次序，不管什么机制）；② 输入来源不一致（读到的不是指定生产者的输出：保存值、重算、别的副本、读错数据）；③ 上游误差传进来，只是传播；④ 节点的算法与规格之差。

**定理（记账）**：若每个节点的 ①、②、④ 都为零，则每个节点的实际输出等于理想输出。证明按拓扑顺序归纳：第一个节点只读外部输入，③ 为零；若前 n−1 个节点都相等，则节点 n 的指定生产者输出等于理想输入，③ 为零；再由 ①②④ 为零得 ŷ_n = y*_n。

定理说了什么、没说什么：它说明任何非零总差至少来自某个节点的 ①、② 或 ④，所以「来源只有三类」是算术事实，不依赖我们列了哪些机制。它没有说明工具能把各项算出来、能把差异分配到单条指令、能在有限样本里发现所有问题。它也不保证可加性：各节点单独改动的作用存在交互时不能相加，需要联合比较。

### 测量各项时的三条注意

1. ② 要用参照求值算：g_n(x̂_n) − g_n(x̄_n)。用原生执行两次相减得到的是 ② 加上 ① 随输入的变化，不是纯 ②。
2. ① 需要 K_n 的实际输出可观测。被后端融合（乘加合成 fma）、消去或重组的节点没有独立的实际值，只能在能建立对应关系的区域边界上测。
3. 第 1 步讲稿中的三项恒等式 K(x) − f(x) = 舍入误差 + 输入误差 + 近似误差 是这个分解在单个算子上的写法：舍入对应 ①，输入对应 ②，近似对应 ④。两种写法同一回事，讲稿用算子级，工具用节点级。

## 3 检测为什么不依赖误差来源清单

对一个陌生 kernel，不需要事先知道 bias 来源有多少种。需要穷尽的不是来源，而是编译产物里的指令：来源是开放的，谁也列不全；指令是有限的，可以逐条核对。把「排查来源」换成「覆盖指令」，保证才有可能成立。

### 检测测的是总量

第 2 节的两项恒等式只有两个位置。任何来源，不管有没有被命名，要么改变了实际算出的值（落在 K − K_R），要么改变了程序声明的函数（落在 K_R − f），没有第三个地方。两项都是直接测总量，不是把列出来的来源加起来，所以一个从未听说的机制只要改变了结果，就已经被测到。

对 bias 同样：用 K_R（舍回存储格式）替换 K 做受控重放得到 u，检验 μ 的区间。任何会产生平均作用的来源都必须经过 u，否则它对训练没有作用。

### 定位也不需要命名机制

参照是逐节点组合出来的，每个节点都有自己的局部残差 ①。它把该节点与声明语义的全部差异都包含在内，哪个节点出了事由各节点的 ① 直接给出。DeepSeek-V3 报告 H800 上 FP8 矩阵乘的累加只保留约 14 位：工具不需要事先知道这一点，dot 节点的 ① 会呈现为与最近舍入不符的同号差异，被定位、被测出均值；它是什么机制，事后归因。

归因用覆盖表文档第 9 节那张开放的后端选择表（fma 合并、除法下降、ex2.approx、FTZ、inputPrecision、求和树、split-K、原子次序……）把已定位的 ① 对应到一个可操作的设置和对照值。归因不出来，就报告「节点 n 存在未归因的局部差异，平均作用为某某」，这仍是合格的检出结果。

### 对一个陌生 kernel 的处理顺序

1. 覆盖检查：逐条指令映射，标出不支持的区域。
2. 绑定核对：操作数与捕获一致；IR、编译配置、最终产物三者对应。
3. 构造 K_R，输出区间。
4. 总量检测：K − K_R 的局部与组合差异；受控重放得到 u，做端点保守检验。
5. 定位：按各节点或区域的 ①。
6. 归因：对得上已知设置的给出对照值；对不上的报告未归因。
7. 语义层：有 f 时测 K_R − f；没有则写明未检验。

### 检测合格由什么判定

不是来源清单是否完整，而是三份能写进报告的东西：覆盖报告（哪些指令已映射、哪些区域未核实、每个输出属于三类中的哪一类）、参照区间宽度（参照自身误差是否足以下结论）、统计功效（样本量、置信区间、抽样可能漏掉稀有输入）。

## 4 参照 K_R 的构造：组合求值器

K_R 不是把 K 用更高精度再跑一遍，而是由我们自己的求值器按程序声明的语义算出来。它与 K 只共享声明语义和操作数，不共享 GPU 执行路径，所以 K 执行层面的未知机制没有渠道进入 K_R。这是为什么「提高 tl.dot 的精度重编译」不能当参照：那样会换掉硬件指令路径，参照继承了被测对象的未知。

### 泛化来自组合

不为每个陌生算子手写 reference，而是为少量基本运算定义参照求值，再按实际计算结构组合。一个融合 kernel 的名字工具不认识，也不知道它会出现哪种误差，但只要组成它的运算与执行条件受支持，就能生成参照。内部参照运算是有限集合：实数加减乘除与初等函数、指定格式与模式的舍入、精确积和、带明确 NaN 规则的最值、参照内存的读写、位级重解释、未定义值。覆盖表（第 5 节）是「IR 指令 + 属性 → 内部参照运算」的映射。

### 参照语义是预先声明的模式

缺省为数值差异模式：所有转换取恒等，名称带舍入后缀的函数（add_rn）和 PTX 指令（add.rn.f32）同样取实数运算。同一次 FP32 加法写成 a + b 或 add_rn(a, b)，参照都是实数和，否则换写法就能让一次舍入从研究对象里消失：a = 2²⁴，b = 1，K = 2²⁴；实数和参照给差 −1，含舍入的参照给差 0，后者研究的是硬件是否遵守规范，是另一个问题。另一种模式是舍入核验模式：g 取声明的舍入函数。配方声明为有意量化的转换节点可在任一模式下单独声明取舍入函数。

### 点输入与区间输入

局部参照在节点实际读到的输入上算，输入是精确点：浮点数的加减乘除、fma、积和是二进制有理数，精确有理数或 Kulisch 长累加器给出宽度 0；初等函数用 MPFR 向上向下各算一次得包围，无理数结果（√2、e）永远是区间。组合参照从相同外部输入逐节点传递参照值，从第二个节点起输入就是区间，必须按区间算术传播：e 的区间经一次加法后是 [2ℓ, 2h]，不会因为加法「精确」就清零；非单调函数（sin、x²）要处理区间内部的极值，不能只代两个端点。组合参照成立的条件是每个节点满足包含性：

$$\{\, g_n(x) : x \in I_n \,\} \subseteq \mathrm{Eval}_n(I_n)$$

**定理（包围）**：若每个基本运算的区间求值包含其实数结果，按拓扑顺序归纳，每个节点的参照区间都包含声明计算的真值。这是区间算术的包含性质（Moore 1966）。它保证的是工具实际输出的参照可信，比「误差只有几类」更直接有用。

### 组合参照的三条规则

缺一条，只能得到条件局部参照。

1. **参照内存**。组合参照维护自己的内存状态：外部输入从捕获值初始化；区域内 store 写参照值；之后的 load 按地址、别名、mask、先后次序读参照值。若 load 直接读捕获的实际值，上游差异在此被抹掉：t = 2²⁴ + 1 经 store、load 后与 2²⁴ 相减，组合参照应得 1，读捕获值得 0。atomic 返回旧值并更新内存，(v_old, M′) = AtomicAdd(M, p, a)；只有返回值未用、贡献不依赖中间结果、初始值与参与集合明确时才能折成一次精确和。
2. **路径**。条件用参照值判定。参照与实际路径不同时，要么分析可能分支取并集，要么报告该输出降为条件局部参照；不能沿实际路径继续并称之为组合参照。s = 2²⁴ + 1 在 FP32 下得 2²⁴，分支 s > 2²⁴ 实际为假、参照为真，沿实际路径的参照给出 K − K_R = 0，真实差是 −1。
3. **可观测性**。TTIR 解释器算出的中间值不一定在 GPU 上出现过（fma 合并后舍入过的 p 不存在），插桩去取它会改变被测对象。「可生成参照」和「可观测实际值」分开记；被融合的节点在区域边界上比较。

### 三类输出

每个目标输出归入：完整组合参照（三条规则与包含性都满足，区间包围真值）、条件局部参照（某处固定了实际值、实际路径或位级结果，此后的分析仍有效，但不计入完整覆盖率）、参照未建立（未识别语义、不可结合的归约区域、次序缺失、区间过宽）。参照未建立的样本从该位置统计中剔除并报告剔除比例，剩余样本的结论只对参照成功的那部分成立。

### 参照误差进入统计

样本 i 的真实残差满足 l_i ≤ a_i ≤ h_i，平均与期望保持不等式：

$$\mathbb{E}[l] \le \mathbb{E}[a] \le \mathbb{E}[h]$$

对 E[l] 的置信下界大于 0 即确认正向作用，对 E[h] 的置信上界小于 0 即确认负向作用，否则不下结论。这是保守检验：参照越粗越难下结论，但参照误差不会制造假的偏差。前提是上下界包住同一个声明目标量；路径切换、实际值回填或模式变化后不能混成同一种残差。

### 参照求值不等于可执行干预

解释器里算出的高精度值送回 GPU 路径时，要核验插桩、类型和读取位置只改变了预期因素。参照区间控制的是计算参照的不确定性，总体统计区间控制的是有限抽样的不确定性，两者分开报告。

## 5 覆盖表与版本依赖

细表在另一份文档：Triton 编译产物指令覆盖表：K_R 的构造依据（修订版本 20，十一节）。这里只记它的结论和使用规则。

### 覆盖分三层，只对第一层承诺 100%

| 层 | 含义 | 承诺 |
|---|---|---|
| 指令处理覆盖 | 编译产物中每条指令及其属性都被某条规则接收或明确拒绝，没有静默跳过 | 对锁定版本可做到 100%，由枚举测试保证 |
| 参照求值覆盖 | 被标为支持的指令确有正确的点值与区间求值方法 | 由反例测试验收，规则写全六项后才成立 |
| 整段参照覆盖 | 目标输出的数据、控制、内存依赖都被可靠处理，参照中途没有换成实际值 | 对具体程序由实现报告，不能从清单推出 |

### 覆盖表的内容

检查层是 TTIR（tt、arith、math、scf、cf 五个方言）。九个类别 A–I：非数值、精确、精确但不连续、初等实函数、求和、其他归约、转换与声明舍入、位级、外部状态、语义未声明、复合。每条表项写六项：声明语义与输入前提、点输入求值、区间输入传播、执行效果（读写内存、返回旧值、影响控制流）、实际执行绑定（值能否观测）、条件不满足时的输出类别。2026-10-02 读取的来源：tt 文档 53 条与同日源码 50 条不一致（文档多 approx_divf、atomic_load、atomic_store；两者都无 tt.cat），arith 56 条，math 46 条，scf 12 条，libdevice 接口约 190 个按族映射，内联汇编按 PTX 助记符逐条映射。表外指令即覆盖失败。

### 版本依赖的处理规则

1. 锁定版本：Triton 提交、它绑定的 LLVM/MLIR、目标后端与架构、提取 IR 的阶段，一起写进报告。未经适配的新版本不继承旧版本的支持承诺。
2. 语义与名字分开：内部参照运算的定义不随 MLIR 名字变化；版本更新只改映射。
3. 五种变化各有处理：新增操作（枚举测试失败，拒绝）；新增属性、类型或默认值（枚举测试扩展到属性与默认值；描述文本哈希只触发复核，不作保证）；定义不变而下降实现改变（K 变 G 不变，重新测量，重做执行核对）；提取 TTIR 之前的优化改变（记录提取阶段，比较版本时单独报告 G 的变化）；节点被融合或重组（在能建立对应的区域边界比较）。
4. 比较两个版本的恒等式：
   $$\mathbb{E}[K_2 - G_2] - \mathbb{E}[K_1 - G_1] = \mathbb{E}[K_2 - K_1] - \mathbb{E}[G_2 - G_1]$$
   右边第二项非零时，观察到的「bias 变小」有一部分来自比较标准变了；两版共享同一声明目标才能直接比较。
5. 跨层核对的正确关系：TTIR 与 PTX 各自的参照解释的是不同表达式，不要求区间相交。
   $$K - G_{\mathrm{TTIR}} = (K - G_{\mathrm{PTX}}) + (G_{\mathrm{PTX}} - G_{\mathrm{TTIR}})$$
   exp 的例子：Triton 把 f32 的 exp(x) 下降为 ex2.approx(c·x)，c = RN₃₂(log₂e) = 1.4426950216293335，c/log₂e − 1 ≈ −1.335×10⁻⁸；x = 1 时 e = 2.718281828459045 而 2^c = 2.718281792170640，两个参照本来就不同。第二项是编译器采用的允许近似；第一项还含 RN₃₂(cx) 与 ex2.approx 自身的误差。−1.335×10⁻⁸·x 只是常数一项的一阶表达，不预测整个 kernel 误差的符号，更不预测训练分布上的均值。首版 PTX 只用于核对具体下降与归因，不另建全量参照解释器。
6. 执行对应：从实际那次编译保存 IR、编译配置、最终产物三者的对应。重新编译 TTIR 比对哈希只是辅助——相同支持「同一机器程序」，不证明参照解释正确；不同不自动否定。Python 源码不是意图，只有另行声明的 f 才能把前端差异解释为对规格的偏离。

### 这一节能保证什么

工具针对明确版本的 IR，把操作、属性和执行条件映射到独立定义的参照语义；新版本需要重新验证映射与执行对应；覆盖检查、语义测试和跨层核验能发现并约束兼容性问题，但不保证所有未知错误都在生成参照之前被发现。

## 6 实验设计与统计

方法骨架是常规的：因子分类处理、配对比较、推断范围、用注入做校准。统计部分不自己发明。创新只在因子是什么（kernel 内部的单个数值实现选择，由中间表示自动找出）和结果是什么（它对实际参数写入的带符号平均作用及训练后果）。

### 决定一次 kernel 执行结果的全部因素

实际执行的指令流（源码、编译期常量、autotune 配置、元素类型、编译器版本与选项、目标硬件）；读到的内存内容；启动配置；并发执行的先后；硬件单元的实际行为。确定性机器的输出是程序和输入的函数，GPU 上的非确定性只来自并发交错，所以任何改变输出的东西至少改变其中一项。被测对象是「源码 + 配置 + 硬件」下的执行，不是源码：autotune 换 BLOCK_K 或 split-K 就换了求和树。

### 每个因素的处理与标准术语

| 处理 | 适用因素 | 标准术语 | 结论的适用范围 |
|---|---|---|---|
| 固定 | 编译产物、启动配置、硬件 | 保持恒定 / 区组 | 只对固定的那个水平成立 |
| 逐一列举 | autotune 配置、硬件型号 | 固定效应因子，因子设计；水平太多时覆盖数组 | 只对测过的水平成立，不能取平均后外推 |
| 抽样 | 输入、并发顺序、训练状态 | 随机化 / 随机效应 / 噪声因子 | 推广到被抽样的总体 |
| 同一输入上比较原实现与变体 | — | 公共随机数下的配对比较 | — |

每次检测报告中五项因素各自标明处理方式，缺一项即无法判断。这是实验设计里推断范围的要求，不是新规则。

### 单个位置的检验（第 3 步）

抽样单位是「固定 checkpoint 重抽 batch」：状态 s 来自声明的 checkpoint 集合，每个状态重抽 n_b 个 batch，投影 a = ⟨u, w(s)⟩，μ(s) = E_b[a]。主文用 t 区间 ā ± t_{α/2} σ̂/√n；同报非零比例与正负比例作诊断（稀疏分布时 t 近似不可靠要能看出来）。参照误差按第 4 节用端点保守检验叠加。方向规则 w 事前固定：固定方向用开发批平均更新差归一化后冻结，再另采确认批（Liger 实验：32 次开发、64 次确认）。判定四类见第 1 节。

### 跨步累积（第 4 步）

在参照轨迹上（影子式，由参照更新推进）定义 Z_j(T) = Σ_t a_{j,t}，j 为独立训练历史。由塔性质 E[Z_j(T)] = Σ_t E[μ_t]；波动部分为鞅差，Chebyshev 给出界（讲稿 §4）。Z_j(T) 是逐步 u 的累加，不等于两条各自演化轨迹的终点参数差 Δθ_j，这是第 4 步与第 5 步的分界。

### 训练后果（第 5 步）

配对 run：同配置只差一个实现，Δℓ_j 为 loss 差，以种子间 loss 差为刻度；配对 t 区间的条件要陈述（配对差独立、近似正态或 n 够大）；只纳入双方完成的配对，结论条件于双方完成；另报训练失败次数/总 run 数，非有限值或崩溃的 run 不进 loss 差平均。

### 多重性

对事前确定的比较集合用 Holm（控族错误率，允许任意依赖）；BH 需独立或正依赖，不互换。来源定位、确定性重构、数学恒等式不套用校正。多重性只在汇总时算，不进理论主线。

### 与 Liger、AdamW8bit 的接法

现有 check_bias 已实现第 3 步。第 4 节的自动参照接在它前面：K_R 替代手工 reference，受控重放得到 u，统计不变。先验证自动 K_R 与手工参照在 Liger 位置一致（第 11 节步 4），再谈陌生 kernel。

## 7 LLM 训练中的坐标与传播

一个陌生 kernel 在训练里的位置，用低精度训练实践已经通用的坐标来指认，不自己发明。

### 坐标：层 × GEMM 角色 × 张量角色，加五类非 GEMM 位置

一个线性层在一个训练步里有三个 GEMM：前向 fprop（y = xW）、输入梯度 dgrad（∂L/∂x = (∂L/∂y)Wᵀ）、权重梯度 wgrad（∂L/∂W = xᵀ(∂L/∂y)）；每个 GEMM 的操作数有张量角色 activation / weight / gradient。GEMM 以外：注意力内部、norm 与激活函数、保存给反向用的值、optimizer 的状态与写回、跨 micro-batch 与跨设备的梯度归约。Transformer Engine 的精度调试工具（层 × fprop/dgrad/wgrad × activation/gradient/weight 的 YAML 配置）、torchao 的 FP8 配置（每个张量角色单独的转换方式、每个 GEMM 单独的累加方式）、NVFP4 预训练配方（敏感层保留高精度；权重梯度 GEMM 的输入做随机 Hadamard 变换；权重 2D 块缩放保证前向与反向一致；梯度用随机舍入）、DeepSeek-V3（嵌入层、输出头、MoE 门控、归一化、注意力保持原精度；每 128 个元素把部分和提升到 FP32，因为 H800 的 FP8 GEMM 累加只保留约 14 位）都在这套坐标上描述数值选择。

属性名也通用：格式、缩放粒度、累加精度、舍入方式、变换、矩阵乘算法（JAX 的 DotAlgorithm 用一个名字指定操作数精度、累加类型、分解次数）、是否近似。

### 一条检测的写法

```yaml
- 位置: {layers: "blocks.*.mlp.fc2", gemm: wgrad, tensor: gradient}
  属性: rounding            # 当前值从编译产物读出
  对照: {rounding: stochastic}
  保持: [format, scaling, accumulation, 同层其他 GEMM]
  测量: {点: update, 方向: 前半样本定方向、后半样本确认}
  总体: {checkpoints: [...], 每个 checkpoint 抽 64 个 batch}
```

位置与属性沿用现有坐标；对照与保持是我们补的（TE 的调试功能能关闭 FP8 或做伪量化，但不声明其他什么保持不变，也不核实两侧编译产物只差这一处）；测量与总体是我们补的（TE 只记录张量统计量，配方靠 loss 曲线评价）。

### 陌生 kernel 怎样落进坐标

1. 定坐标：从捕获的训练计算图看它扮演什么角色——哪一层、前向还是反向、哪个 GEMM、还是保存值、optimizer 写回、梯度归约。名字可以完全陌生。
2. 读属性：从编译产物读 tl.dot 的 inputPrecision、累加类型、转换位置与目标格式、PTX 的舍入后缀；读不出的标为未知并探针。
3. 生成检测：对每个属性查受支持的对照值，自动写出上面的条目；没有对照值的只列出。

### 角色决定传播公式（讲稿第 2 步）

| 误差位置 | 进入 u 的方式 | 可用的公式 |
|---|---|---|
| wgrad 上的误差 | 直接成为梯度差，再经 optimizer | δg = e；u 由 optimizer 响应给出 |
| dgrad 上的误差 | 沿反向图传播；两侧保存量与分支相同时精确线性 | δg = J_{s,b} e，另有浮点重放残差 ξ |
| fprop 的误差与保存值误差 | 既影响前向又影响反向读到的值 | 一阶加余项；双线性情形精确线性（matmul 权重梯度 δ(dW) = eᵀdY，固定同一份 dY）；softmax 反向对 p 二次：B_i(p+e, dp) − B_i(p, dp) = e_i(dp_i − ⟨p, dp⟩) − p_i⟨e, dp⟩ − e_i⟨e, dp⟩ |
| optimizer 状态上的误差 | 不经梯度，直接进入写入差，非线性 | u = Step_C(θ, g_C, z_C) − Step_R(θ, g_R, z_R)；AdamW 的归一化更新 m̂/(√v̂+ε) 展开为分母均值漂移、分子分母协方差、Jensen 三项，只在 warm、小扰动、v 不由当步梯度主导时成立 |

两条已确认的推论：算子输出误差正负抵消不代表传到梯度后仍抵消（e = ±1、J = 2 / 1 时 Je 平均 +0.5，协方差项 Cov_b(J, e | s) 非零）；一阶矩差的递推 m_{C,t} − m_{R,t} = β₁(m_{C,t−1} − m_{R,t−1}) + (ρ^m_{C,t} − ρ^m_{R,t}) 把残差（第 1 步）、状态差（第 2 步）与历史（第 4 步）接起来。

### 训练层的坐标是另一层

保存值来自哪次前向、反向读哪一份、optimizer 状态编码、梯度累加与 all-reduce 的精度与次序，由训练程序的计算图决定，靠捕获得到，单个 kernel 的 DSL 描述不了。工具因此有两层输入：kernel 的编译产物，和它在训练图中的位置。

## 8 一致性检查：前向是反向的参照

输入来源不一致（第 2 节的 ②）里最重要的一类是前向与反向不一致：反向读到的保存值、重算值或转置后另行量化的权重，与前向实际用的不是同一份。这类问题不需要外部实现作参照，前向本身就是反向的参照。

### 伴随关系

设前向是 f，反向 kernel 记作 B：它接收上游梯度 v，输出对输入 x 的梯度。若反向与前向一致，应当有 B(x, v) = J(x)ᵀv，J(x) 是 f 在 x 处的雅可比。两边与任意方向 u 作内积：

$$\langle B(x,v),\,u\rangle=\langle J(x)^{\top}v,\,u\rangle=\langle v,\,J(x)\,u\rangle$$

右边只用到前向的方向导数。这是数值计算里检验正向程序与伴随程序是否匹配的点积检验：通过不能证明代码正确，不通过说明两者不一致。用于非线性算子时把算子换成它在当前点的线性化。

### 方向导数必须精确算，不能用有限差分

中心差分有截断误差，而且符号固定。取 f(x) = x³、反向完全正确 B(x, 1) = 3x²：

$$\frac{f(x+h)-f(x-h)}{2h}=3x^{2}+h^{2}$$

检查残差恒为 −h²，所有样本同号，均值稳定为负，但反向没有任何问题。所以 J(x)u 由参照解释器做前向自动微分得到（在声明的表达式上，带区间），没有截断误差；有限差分只作交叉检查。x = 0 处前向自动微分给出导数区间 [0, 0]，残差为 0，不误报。

### 残差均值怎样进入判定

取 v 为训练中真实的上游梯度，u 为事前固定的方向，残差 a = ⟨B(x, v), u⟩ − ⟨v, J(x)u⟩。a 的区间端点按第 4 节的端点保守检验做均值判定。a 本身是 ② 的局部量，它对参数写入的作用仍要经受控重放到 u 上测，不能把 a 的均值直接称为训练作用。

### 带量化的前向

FP8、FP4 训练的前向含量化节点，其导数几乎处处为零，训练实际用的是另行声明的替代梯度（如直通估计）。此时验证的是声明的求导规则，不是「去掉量化后的导数」；工具不得擅自把前向改成去量化版本。

### 三种不同的 saved-P 比较

仓库里对 saved-P 实际做过三种比较，报告中不得混称：算术实现对照（两种实现算同一个 P）；同一次前向概率的一致性干预（反向读前向算出的 P 而不是重算或保存的 P，即本节的 ②）；重归一化（强制行和为 1，这是修复，不是参照）。一致性关系（行和为 1）只用于核验，不能唯一决定 P，输入误差的符号由 g(x̃) − g(x) 的分布决定。

## 9 与相关工作的边界

不新的部分：比较实现、量化数值偏差、操纵归约顺序、随机舍入探针、追踪训练中权重发散（Golden 等 2024「Is Flash Attention Stable?」已做 matched 微基准与 block 顺序交换）、从真实训练采集张量并替换输入（TTrace）、按子系统二分定位（Inductor accuracy minifier）。可能新的部分：在 kernel 内部逐个实现选择检验带符号的平均作用而不是容差；按基本运算语义组合生成参照而不是手写 reference；persistence 与 diffusion 的跨步相关区分。「从测方差转向测均值」是最站得住的概念差异。

| 工作 | 它做什么 | 与我们的区别 |
|---|---|---|
| TTrace（2025） | 给候选与可信参照，采集真实训练张量，找超出容差的不一致 | 容差判断幅度；我们自动生成局部对照，估带符号平均作用，非零不直接当 bug |
| FLiT（HPDC 2019） | 用多种编译器与选项构建同一程序，与基准编译比较，二分到函数；4,376 次受控注入，约 15 次运行内定位，精确率召回率 100% | 比较幅度得分；二分依赖「变化由单个函数独立引起」的假设，我们直接测交互；因子是编译器开关，我们的因子是 kernel 内的单个选择。它的注入式评价是我们「已知阳性召回」该有的样子 |
| Herbgrind / Herbie | 局部误差：单个运算在精确输入上自己产生的误差；实数影子执行加影响跟踪 | 我们的 ① 在实际读到的输入上算，这样恒等式才严格成立；两者用途不同，不比谁诊断更强 |
| 白盒性能影响建模（ConfigCrusher、Comprex，ICSE 2021） | 静态分析找出配置选项在代码中起作用的位置，再对这些区域插桩测量，估计选项与交互的影响 | 结构相同（从中间表示找出实现选择，再生成变体测量），被研究的结果从运行时间换成参数更新的平均作用 |
| Transformer Engine 精度调试工具 | YAML 按层 × GEMM × 张量角色关闭 FP8、伪量化、记录张量统计 | 坐标直接借用；它不声明保持什么不变、不核实两侧产物只差一处、只记统计量不估作用 |
| torchao FP8 配置、NVFP4 与 DeepSeek-V3 配方 | 每个张量角色与 GEMM 单独设格式、缩放、累加、舍入 | 属性名直接借用；它们靠 loss 曲线评价，我们给每个位置一个估计目标 |
| JAX DotAlgorithm、StableHLO 版本化规格 | 用一个名字精确指定点积的操作数精度、累加类型、分解次数；用版本化规格维护语义 | 前者是「g 由属性决定」的现成例子；后者是版本依赖的组织方式，其兼容承诺不转移到 TTIR |
| Verificarlo / Monte Carlo Arithmetic | LLVM 级随机舍入全程序分析，测方差与有效位数 | 回答相容性，不回答跨状态带符号平均偏差；同一状态重复随机舍入不等于抽不同状态；随机舍入须发生在与确定性 kernel 相同的舍入位置 |
| 实验设计（Box–Hunter–Hunter、Montgomery）、稳健参数设计、仿真的公共随机数、不确定性量化的偶然/认知区分 | 因子固定/区组/随机化、控制因子与噪声因子、配对比较、有分布可抽样与无分布只能列举 | 我们的统计骨架全部来自这里，不另造 |
| Qiu & Yao（Flash Attention 分析） | 单一数据序列上根因 → 进入梯度 → 跨状态同向 → 累积 → 后果由干预闭合 | 五环形状来自它。不同处：筛查对事后诊断；覆盖更多算子与 optimizer 位置；加总体推断；FA 也分析了前向输出经 δ = rowsum(dO∘O) 的作用，不涉及的只有 optimizer |

写作要求：凡沿用 FA 的环节标注来自 FA；凡与 FA 不同处说明为何合理；某些方向的机制解释弱于 FA 处如实标注。不声称「首次」。

| 错误或过强的说法 | 为什么错 | 替代表述 |
|---|---|---|
| 指令分类完备就能保证找全实现选择 | 分类是指令到语义的映射，不是实现选择的清单；一条归约指令同时涉及来源、组织、精度、同步 | 分类只用于读出属性；完备性靠总量测量与逐节点残差 |
| 高精度替身与只去掉某次舍入严格一致（双重舍入定理） | 定理只对加减乘除开方在中间精度足够时成立，不适用于任意中间量与下游程序 | 参照由求值器按声明语义算，不用重编译替身 |
| 改随机舍入就消掉传播均值的前两项；正负重放就测完非线性项 | 随机舍入只保证特定局部舍入的条件无偏，能否传到下游要额外条件 | 写明替换为哪种具体舍入方案及其已证明性质，不写「消除 bias」 |
| 单处归因需要先构造全部精确的 K₀ 和裂项求和 | 以真实实现为起点只改一处即可，交互只影响可加性 | 单处比较从真实实现出发；需要时做联合比较 |
| 中心差分残差的均值就是一致性偏差 | f = x³ 时残差恒为 −h²，截断误差符号固定 | 方向导数用前向自动微分精确算；有限差分只作交叉检查 |
| 各来源的局部作用投影取均值就是它的平均作用 | 局部均值不等于对参数写入的作用，中间隔着依赖状态的传播 | 作用一律在 u 上测，受控重放后估 μ |
| 名称带舍入后缀的函数（add_rn）默认让 g 含舍入 | 改写法就能让一次舍入从研究对象消失（2²⁴ + 1 例） | 参照语义是预先声明的模式，不由写法推定 |
| 求和、sqrt 的参照「宽度 0」「正确舍入可得单点」 | 只对精确点输入成立；组合参照的输入是区间；√2 不可精确表示 | 分点输入与区间输入两列；无理数结果永远是区间 |
| 组合参照沿实际路径走、只标记分支翻转 | 2²⁴ + 1 后接 s > 2²⁴ 的分支，沿实际路径得差 0，真实差 −1 | 路径条件参照与组合语义参照分别命名，翻转后不得冒充后者 |
| 内存一律以捕获值为准 | 先 store 再 load 的链上，load 读捕获值会抹掉上游差异 | 组合参照维护自己的参照内存 |
| atomic_rmw 浮点加法的 g 是全部贡献的精确和 | 该操作返回旧值并更新内存 | (v_old, M′) 建模；仅在返回值未用等条件下折成求和 |
| 后端选择的作用都落在某个 TTIR 节点的 ① | fma 合并后不存在舍入过的中间值 | 落在节点或能建立对应关系的区域 |
| 「同名指令语义变化是唯一真正的风险」；查表 + 哈希 + 随机校准 + 跨层比较保证更新前一定先失败 | 还有新增属性/默认值、定义不变而下降改变、提取前优化改变、融合重组；描述文本哈希不含类型约束与下降实现；随机输入看不到 NaN 差异 | 第 5 节的五种变化与缩小后的保证陈述 |
| TTIR 与 PTX 的参照区间应当相交 | 两层解释的是不同表达式（e^x 与 2^(cx)），本就不同 | K − G_TTIR = (K − G_PTX) + (G_PTX − G_TTIR) |
| 把 Gluon、CUDA、PTX 换成另一张指令表即可 | 布局、线程、异步与内存对应各不相同 | 基础运算可复用，其余分别处理 |
| 二进制哈希相同证明 TTIR 是忠实声明 | 多份 IR 可编译成同一二进制；不同也可能只是配置不同 | 保存实际编译的 IR、配置、产物对应；重编译只作辅助 |
| 全部 53 条 tt 指令已归类 | 同日文档 53 条、源码 50 条，两者都无 tt.cat | 总数由锁定版本的注册表生成 |
| log1p 在 x ≤ 0 无定义 | 定义域是 x > −1 | 已更正 |
| PTX 内联汇编的谓词只影响解析 | @p 决定指令是否执行 | 谓词按 select 建模，跳转按控制流处理 |
| 没有规格时静默取 f := g | 把「未检验」写成了「正确」 | 报告写明「任务语义未检验」 |
| 「指令全覆盖」等于「数值参照全覆盖」等于「所有 bias 都能检出」 | 三个命题不同：指令处理覆盖可 100%；参照覆盖由实现报告；bias 检出还涉及总体与统计功效 | 第 5 节的三层覆盖 |

讲稿阶段此前已纠正、这里只列不展开的：对照「三种角色」表述已废；参照由误差项决定；判定不做「无偏差」声明；主文统计用 t 区间而非经验 Bernstein；投影统计量 w 为单位方向、不除以 ‖w‖；对齐投影投的是差 u 不是候选更新；FA 覆盖前向输出路径、不涉及的只有 optimizer；精度与顺序共同决定符号。

## 11 下一步实验操作

可以开工，从求值器开始，按每一步能单独证伪的顺序搭。步 1、2 不需要 GPU。首版目标：固定一个 Triton 版本，对包含基本算术、cast、归约、部分初等函数及明确读写关系的计算自动生成参照；换一种组合不增加算子专属 reference。

### 开工前定下的四件事

1. 锁定版本：实际环境的 Triton 提交、绑定的 LLVM、目标 GPU 架构、编译选项，写进仓库。
2. 缺省模式：数值差异模式；舍入核验模式作开关。
3. 首批 kernel：仓库里已有手工参照的位置——Liger FP32 归约顺序、Liger fused CE 的 dW 累加、AdamW8bit 的 moment 更新。它们是步 4 的对照，也决定 libdevice 映射只需覆盖实际出现的符号。
4. 捕获方式：包一层 kernel 启动函数复制操作数，或用 Triton 运行时钩子；先在一个 kernel 上试通逐位复现。

### 六步

| 步 | 做什么 | 输入 | 输出 | 完成标准 |
|---|---|---|---|---|
| 1 | 参照求值器：内部参照运算、点输入精确有理数与 MPFR 区间、区间传播、参照内存、分支并集、前向自动微分 | 无（纯 CPU）；gmpy2 提供 MPFR 与有理数，python-flint 的 Arb 做复杂函数 | 一个库，含三种执行：局部参照、组合参照、导数参照 | 下表 8 项反例测试全部通过 |
| 2 | TTIR 解析与映射：遍历指令（含区域与 call），查表，判操作数来源（bitcast 下游归 F），出覆盖报告 | 锁定版本编译首批 kernel 得到的 asm['ttir'] | 覆盖报告：每个输出归三类之一；未映射清单 | 枚举测试通过；首批 kernel 的报告能分出三类 |
| 3 | 绑定：捕获一次真实调用的操作数、输出、编译产物、配置 | GPU；首批 kernel 之一 | 捕获包 + IR/配置/产物对应记录 | 同一输入重放两次逐位相同；对应记录完整 |
| 4 | 自动参照对照手工参照 | 步 1–3 | Liger 归约顺序位置上的 K_R 区间与局部残差 | 自动 K_R 与手工参照在区间内一致。不一致则回步 1、2 改规则，不进步 5 |
| 5 | 接回统计：受控重放得 u；端点保守检验得 μ 区间 | check_bias 的第 3 步 | 一个真实位置的有效单步统计实例 | 重新得到 Liger 或 AdamW8bit 的已知结果，方向与区间与原结论一致 |
| 6 | 负对照与泛化 | 步 1–5 | 三种结构的报告 | 见下 |

### 步 1 的反例测试

| 测试 | 要阻止的错误结论 |
|---|---|
| 2²⁴ + 1 分别写成普通加法与 add_rn | 换写法让舍入从研究对象消失 |
| sqrt(2)；exp 之后接求和 | 正确舍入或精确累加被报告成零宽度真值 |
| 2²⁴ + 1 之后接 s > 2²⁴ 的分支 | 路径条件参照被报告成完整组合参照 |
| 先 store 再 load 的数值链 | load 回填捕获值后丢失上游差异 |
| atomic_add 的返回值被后续使用 | 全部贡献的和被当成每次 atomic 的输出 |
| p = a × b、y = p + c 在开关 enable_fp_fusion 下 | 捕获不存在的中间值，或插桩改变原计算 |
| log1p(−0.5)、isnan(NaN)、maxnumf(NaN, 1)、无 other 的 masked load | 合法值被误拒绝，或未定义值被误接收 |
| f = x³ 的伴随检查 | 中心差分误报，前向自动微分不误报 |

### 步 6 的三种结构

| 结构 | 验证的能力 | 负对照 |
|---|---|---|
| 归约与类型转换 | 自动构造参照，正确解释精度与组织选择造成的差异 | 故意漏一项：无规格时检不出且报告写明；提供源计算作规格后检出 |
| exp → sum → divide（一个此前没有专属参照的融合计算） | 参照不确定性跨节点正确传播；换组合不写新 reference | 同一表达式换一种组合写法，参照自动生成 |
| 计算 → 保存 → 读取 → 继续计算 | 参照不在 load 处丢失上游差异 | 有意把一次 load 固定为捕获值，报告须降为条件局部参照 |

验收不只看运行成功，还看：参照区间是否足够窄（宽到无法分辨实际误差的区间数学上可靠但没有诊断价值）、真实张量规模下高精度与区间计算的成本、换组合后是否真的无需重写 reference。

### 每份结果报告的必填项

版本锁定信息；五项因素各自的处理方式（固定/列举/抽样）；覆盖报告与三类输出；参照区间宽度；参照未建立样本的剔除比例；统计：Π、n_b、n_h、α、事前比较集合、区间与四类判定；对 f 的说明（有规格或「任务语义未检验」）。

### 暂不做

PTX 参照解释器、Gluon 与 CUDA 支持、autotune 配置逐一列举、libdevice 全量映射、跨步累计与完整训练的新实验（复用已有）。

### 分水岭

步 4。自动 K_R 在 Liger 位置上与手工参照不一致，问题在步 1 或 2 的规则，回去改表；一致之后，再谈陌生 kernel。下一轮最有价值的交付是：一个没有专属 reference 的陌生组合，工具自动生成有依据的参照，说明自身误差范围，并在真实执行中得到可核验的数值差异。

### 写作与讨论的规则

只用 LLM 训练与统计学的标准术语，不自造名词。公式一条一条往下推，结论必须出现在它依赖的公式之后。符号在首次需要它的那一步引入并说明用途；能砍的符号砍掉或内联展开。不加防御性表述。凡沿用 FA 的环节标注来自 FA。事实核对由 Claude 自己完成，不留给用户。
