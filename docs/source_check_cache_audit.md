# 重复源码检查的开销

本检查针对覆盖采集器的 CPU 工作，不是 kernel 性能或训练质量实验。
`run_row_reduction_capture.py` 在每次创建观察器时重新读取并检查执行源码。
新工具 `source_check_cache.py` 仅复用相同完整源码文本和符号的纯检查结果，
不缓存运行绑定，不以文件名、mtime 或旧文件哈希替代当前源码读取。

一次本机测量使用 Mamba seq64 的 backward segment0 源码，以及
`triton_poi_fused__unsafe_view_add_bmm_exp_mul_neg_select_softplus_transpose_unsqueeze_69`：

- 直接完整检查：2.19765 秒。
- 缓存首次检查：1.89858 秒。
- 五次重新读取文件并命中缓存：0.00776、0.00668、0.00638、0.00644、0.00650 秒。
- 六次缓存返回内容均与直接完整检查所得 contract 相等。

这是一次时间测量，不是端到端吞吐估计；并发 CPU 工作与系统缓存会影响
耗时。已有测试还检查内容变化、符号变化、失败不复用旧成功、返回值修改
隔离和容量限制。当前缓存默认最多保留两个源码/符号组合。

尚未在训练采集器中启用。后续应显式声明新配置并冻结缓存代码，验证
测量结果一致及端到端耗时；不修改正在运行实验，不将本项优化当作
新增 bias 案例或实际训练收益。
