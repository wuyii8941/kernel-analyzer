# 审查工具：阶段状态与下一步（2026-10-13）

本文是审查入口（`reference_eval/audit.py`）这一阶段的结论汇总：能做什么、证据在哪、讨论中定下的判断、仍不足的地方与下一步。
证据的原始记录在各实验目录，本文只汇总并给出出处。

## 1 现在能做什么

一次调用审查入口，对这次启动自动完成下面各项：

```python
audit(lambda: kernel[grid](...), spec=..., reference=..., names=..., programs=None | "all" | [...])
```

- 事前预测（kernel 不运行，可选）；
- 逐位核对：仿真器在 CPU 上按锁定的下降规则重算，与设备输出逐位比较；
- 精确参照 G（声明程序的精确值），实测偏差 K − G，显著性（统计显著且超过输出格式的单位舍入）；
- 给了参照程序时（通常是 kernel 替换掉的 torch 运算，float64）：逐元素比较 G − S，报告一致 / 不一致 / 无法判断、超出的元素数与
  所在 program；参照程序无定义的元素与 kernel 的非有限输出分开计数；
- 常用容差检查分三类：会通过（偏差被漏掉）、因为偏差而报错、去掉系统分量也通不过（随机误差已超出）；
- 归因：每个舍入位点逐个设为精确、各仿真一次，得到贡献，对到源码行与机制；
- 改法：按机制给出改法与代价，以及「只改一处」「全部都改」的模型内效果（后者一次同时仿真算得）；
- 各 program 偏差的范围（差别超出随机误差时提示抽样不一定代表整个 kernel）；
- 做不到的部分写「无法判断」与原因。

报告先给作者摘要，技术细节在附录。

## 3 讨论中定下的判断

- **事前预测**：对「审查自己的 kernel」不是必需的。偏差大小来自实测，工具理解是否正确由逐位核对证明，归因与改法效果用的是
  逐位核对过的仿真器。预测保留为可选的自检与研究用途（组合研究的结论不受影响）。审查默认是否关闭预测待定。
- **预测器性能**：剖析显示约一半时间花在精确 dot 的严格区间包围（DotK），预测只需要点值。可用「快速路径加可证明的回退」
  （便宜区间里没有任何 ≤ 25 位有效数字的数时直接用，否则回退）去掉，结果与精确算法的舍入决定相同。预测既为可选，此项降为低优先级。
- **归因的成本**：每个位点一次完整仿真（flash attention 6 个 program 约 4–7 分钟），一次审查可以接受；问题在于不可复用。
- **文献方向**（凭记忆，未逐条核实）：
  - 反向 / 切向一遍得到全部位点贡献（Linnainmaa 1976、Langlois 的 CENA、ADAPT、CHEF-FP）适合本工具；
  - 随机舍入 / 蒙特卡罗算术会抹掉要测的偏差，不适用；
  - 静态误差界（Fluctuat、FPTaylor、Daisy、PRECiSA）给不出偏差；
  - 概率误差分析（Higham–Mary 等）可作理论层的闭式摘要。
- **规格分两层**：DSL 定义 G（代码字面上算什么），规格库定义 f（本来应该算什么）。精度审查只用 G；规格库只影响语义判断。
  规格内容按官方文档或原论文推导；审阅方负责裁决歧义与保证独立性，不是内容的来源。
- **单个原语**（原语表）：加减乘、fma、转换都正确舍入。默认写法里的偏差来源是：
  - fp32 的 `tl.dot` 默认 tf32，操作数被截断；
  - 近似数学函数（`tl.sqrt`、`tl.exp`、f32 除法等）有零点几 ulp 的偏差；
  - 次正规数默认冲零；
  - 一个真错误：浮点取模，B024。

  实践中更大的偏差来自组合（循环里的低精度累加、窄化）。

## 4 不足

1. **参照有隐含前提**：
   - 规格（[5_specification](../../5_specification/README.md)，v2.4）31 个角色中只有 3 个有审阅过的合同，且尚未启用；
     有一批条目按记忆书写、原文未核对（见其 `docs/status.md` 第 2 节）；
   - 审查的参照程序由调用方给出（通常是被替换的 torch 运算）。参照程序无定义的元素已单独计数、不再误报；
     但「不一致」是 kernel 错还是约定不同（例如全部被忽略时返回 0 还是 NaN），仍要人判断；
   - G 绑定 Triton 3.6.0 / sm_86 的下降行为，逐位相同只是测过输入上的证据。
2. **归因结果可用，但计算不可复用、成本高、只限精度**：
   - 每次从头逐位点重算，灵敏度不保存；
   - 改法效果只算「位点精确」，不算真实改写；
   - 只审查调用里的第一个 kernel；
   - inf / NaN 源头、执行有效性（竞争、未定义值）不进报告；
   - 语义错误定位不到行。
3. **验证主要是执行方自证**：审阅方的独立核验（M03、M04）与新盲测（W7）未做；事前预测在真实 kernel 上只检验过两例。
4. **范围窄**：只有 Triton 3.6.0 / sm_86 做过真机验证。

## 5 下一步：主攻不足 1 与 2

验收阈值在实现前登记，结果按成立 / 不成立 / 无法判断报告。

**不足 1（参照的前提）**

1. 核实规格库中「文档待抓取核对」的条目：
   - 涉及 CosineAnnealingLR、HF warmup + cosine、GradScaler、checkpoint 重算、`torch.var` 的 correction、`torch.matmul` 的广播、
     Embedding 的 padding_idx / max_norm；
   - 抓 PyTorch 2.10 文档原文，逐条附 URL、版本与原文片段；
   - 与规格不符的交审阅方，执行方不改规格语义。
2. 审查与参照程序的比较（2026-10-15 完成简化版）：
   - 参照程序就是 kernel 替换掉的 torch 运算，在 kernel 实际收到的输入上以 float64 计算；规格库不再是审查的前提；
   - 逐元素判断、参照无定义、kernel 非有限输出、报告写明参照程序，已实现并在 flash attention 上按登记验收；
   - 下一步：在没测过的算子库上批量使用，没有 torch 对应的 kernel 列表交用户定义参照程序。
3. 前提清单进报告：
   - 本次结论依赖的下降规则中哪些来自实测；
   - 未证明前提（scan 结合、CAS 串行化）；
   - 分析策略的默认（显式转换按舍入位点处理）；
   - 逐位核对只覆盖本次输入。

**不足 2（归因）**

1. 一遍得到全部贡献：
   - 在仿真的同一遍里取每个位点实际发生的舍入误差，经每个位点一个切向通道传到输出；
   - 逐处关灯降为对前几个位点的核对与退路；
   - 验收：flash attention 6 例与测试 kernel 上，逐位点贡献与现有结果一致，贡献之和与实测之差在 3 倍标准误内，记录用时；
   - l_bf16 在 N = 8192 时偏差 +15%，处在非线性区，一阶方法会偏：用它检验余项检查能否发现并回退到逐处关灯。
2. 可复用：按 TTGIR、输入与 program 的哈希缓存；保存灵敏度，换一种舍入规则的效果由「灵敏度 × 误差变化」直接给出。
3. 改法效果按真实改写计算（截断改就近、窄类型改宽），不只是「位点精确」。
4. 扩到精度以外：inf / NaN 源头、执行有效性进报告；语义错误的定位依赖规格提供中间观察点（不足 1 第 2 项之后）。
5. 批量入口：抓取一次运行里的全部 Triton 启动，去重后逐个审查，输出汇总表。
