# 规格生成方法（定稿，2026-10-15）

## 两个参照，各自回答一个问题

- G_π：由 DSL 按明确声明的策略 π 从程序提升得到的参照。策略决定哪些浮点运算解释为实数运算，以及哪些量化、位语义、允许结果集合和状态效应保留，不能无条件把全部构造换成实数。它回答「执行有没有偏离该策略下程序声明的计算」，覆盖舍入、累加精度、归约次序等。G_π 是声明参照，不是设备的逐位模型；设备的逐位模型（例如张量核）只用来验证执行模型。此处沿用 [合同实施口径第 1 节](CONTRACT_PROTOCOL.md)，具体查询必须说明采用的策略。
- f：这个程序所承担的任务要求，即独立规格。它回答「程序声明的计算是不是任务要的计算」，覆盖公式、归一化、掩码、状态语义、分布式归约的参与者与权重等。

关系检查、独立复算、误读检查是验证规格的手段，不是第三种真值。

## 用于语义判断的三个条件

Specification 的可信性是相对于具体语义合同及其声明范围的条件性保证。合同来源决定正确性目标；参照求值器及其验证决定答案的可靠性；与被审程序的绑定决定该答案能否用于此次裁决。

1. **语义有依据**：当前任务明确采用相应来源与 profile，公式、默认参数、布局、前态和后态都有依据。论文中的一个子计算不能代表完整算法；合法的另一种约定不能自动判错。
2. **参照可信**：参照兑现全部输入、输出和状态要求。严格包围必须包含合同允许的正确结果；高精度点值加经验余量不能作为严格包围。例子相容与实现通过独立核验分别记录。
3. **对应关系成立**：当前计算区域的输入、参数、前态、输出、后态及 profile 与合同完整对应。名称、计算图片段和运算支持清单只帮助寻找对应，形状相同和少量数值相近不能独自证明对应。

三项不能互相代替。没有完成绑定时，不作 Gπ − f 的语义错误结论；K − Gπ 可以在其自身前提成立时独立分析。
任务尚未选择唯一合法 profile 时，可以保留有依据的允许结果集合；只能在排除所有允许结果时判矛盾，不能逐输入选择最接近被测输出的 profile，再称整个程序符合某个固定任务。

输出范围也属于任务声明。合同的 `profiles.<name>.outputs` 可以预先列出该接口承诺的非空输出集合；未声明时要求合同全部输出，每个选中字段沿用原保证。检查器和运行时使用同一声明，查询不能临时删字段。选择仅输出 attention 值的接口不意味着可忽略另一个接口承诺的 LSE 或状态；实际计算区域的全部写回仍须独立对应。

## f 的生成：三个对象

来源原文 → 审定的数学合同 → 可执行参照

1. 来源原文：版本钉死的标准、文档、任务定义，逐条引用。参考代码可以用，但要标明身份：是任务明确指定的定义，还是仅供交叉核验的另一份实现。知名框架的实现不会因此自动成为数学真值。
2. 数学合同（contracts/*.yaml）：输入与前态、输出与后态、采用的公式或转移规则、合法域、前提条件、允许多解之处、每条输出的保证标签。原文没有规定的行为，只能记为未规定、允许集合或由任务负责人选定的约定；不得为了让某个实现通过而事后补读法。
3. 可执行参照：顶层合同通过 `adapters/<ID>.py` 进入对应的 `kernel_spec` 实现；部分适配器通过明确的依赖入口复用 `specification_v2/algorithm_specs` 的数值实现。统一运行时入口是 `kernel_spec.registry`，不自动回退到历史草案。参照负责兑现合同并复用共同数值部件。

保证标签分四种：exact（精确值）、rigorous_enclosure（严格包围）、allowed_set（允许集合）、declared_approximation（声明近似），不统称「精确答案」。

## 规格的验证

- 例子：审阅人按条款手算，不从代码取值，标明检验哪些条款。
- 误读：每条典型误读必须被至少一个例子拒绝。它检查判据能否抓住误读，不负责证明条款来自正确意图。
- 独立复算、另一种算法、关系检查、与同一定义的实现比对：作为额外证据按条款编号登记。
- 每次比较分别记录相容、矛盾、未建立。区间相交不证明相等。开发样例与参照的相容性检查，不能代替完整候选输出的正确性判定：对于单值任务，若候选坐标位于严格包围之外，可拒绝该候选；若仅包含于非零宽度包围，等式仍未建立。只有精确值、单点包围或独立等式证明才能确认该坐标。必须汇总全部输出和状态，不能因一个坐标未建立就漏掉其他坐标的矛盾。允许集合的联合约束必须另行检查，不从逐坐标包围推导集合成员资格。
- 工具只在已成立的条款上下结论，其余报告「未建立」。

## 检查单位

由问题决定：一个运算、一段归约、一组通信、一次状态转移，或一次完整更新。合同写明该单位的输入、状态和观察量。分片、累积等价只在合同写明的前提下成立（同一组有效贡献、同样权重、没有依赖批统计量的运算）。

## 从陌生算子出发扩充（2026-10-19）

扩充从真实调用及其任务资料出发。先固定一批外部实现及调用范围，检查接口、调用上下文、官方文档或论文，再确定缺少的是任务定义、参照求值能力，还是输入、输出与状态的对应。新增合同必须回答其中一个实际缺口；不以合同数量作为进展指标。

允许采用两条参照路线，分别报告其依据和结论：

- **标准实现对比**：有依据表明两者承担同一任务时，使用明确版本、参数和执行配置的 PyTorch 或其他参考实现作比较。直接运行得到的是该实现的设备结果，能支持相对它的一致性或差异结论，仍有共同错误及参照自身数值误差的局限。若任务明确要求复现某份程序，则须另行说明要求的是其数学计算、特定舍入规则还是逐位结果，不能混用。
- **独立数学规格**：从当前任务采用的标准、论文、公开语义或明确任务声明确定公式和状态转移，独立求出精确值或有依据的严格包围。公开实现运行结果可以交叉核对，但不代替数学参照；来源、求值器和调用对应仍须通过前述三项条件。

同一调用可以同时具备两种参照。二者冲突时，核查任务选择、绑定和两侧实现，不按多数表决或更接近被测结果的一侧确定答案。两种路线都缺少任务依据时，保留未建立；在自身前提满足时仍可分析 K−Gπ。

已知 PyTorch 任务经编译生成的 Triton 用于验证求值和绑定能力；从外部取得的陌生 Triton 还用于检验能否根据独立资料确定其任务。两类样本分别报告，不能合并宣称陌生算子覆盖率。用于补规格的样本属于开发材料；首次遇见的适用性需在另一批事先固定的实现上评估，保留拒绝、部分、超预算和未知结果。

下一批优先选择实际使用广泛、能取得任务依据且暴露新缺口的通用计算，不以某个库或容易通过的算子为扩充目标。每批重点记录：有多少调用确定了任务、采用哪条参照路线、多少完成完整对应并实际求值，以及未完成的原因。已有规格足够时优先复用，不新增同义合同。

## 不再追求的目标

为每个角色找唯一刻画、证明优于所有同行、自动推导任意程序的意图、按 kernel 库列分母。specification_v2/THEORY.md 保留作记录：定理 1–3 是记账恒等式和标准结论；定理 4 的「五类互斥」、定理 5 第 2 条、定理 6 的「可见集合包含」撤回（反例见 evidence/theory_checks/checks.py）。

## 对外表述

我们依据版本化的标准、文档和任务定义建立独立可执行规格，通过来源审阅、独立计算、性质检查与误读检查验证其实现，并明确标注适用范围和未决项。
