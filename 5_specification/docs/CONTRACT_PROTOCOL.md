审阅日期：2026-10-15。对象是上传的 kernel_spec_package_2026-10-15，而不是仓库全部运行能力。

## 1. 不再变更的方法

保留“版本化来源 → 审定数学合同 → 可执行参照”。继续复用现有 DSL 和规格数值模块。
本轮只贯通 CE、ADAMW、RANKMEAN 三个试点，不要求补齐全部角色、求唯一刻画或合并全部数值库。
Gπ 与 f 分开；Gπ 由声明策略 π 决定，可能保留特定量化、位语义、合法结果集合和状态效应，不是无条件把所有构造换成实数。
未绑定独立 f 不阻塞模式 A；历史性质检查可以继续作为已标注的部分证据，不能冒充完整算法参照。

## 3. 来源与读法

- `SOURCES.json` 给出本次实际查阅的官方 PyTorch 2.10 页面和 HF 原文。条款中的公式为数学转录或推导，不伪称逐字引文。
- 旧 CE main/2.16 与 AdamW stable 页不作为这三个试点的锁定版本。采用 2.10 是明确版本决定，不覆盖其他版本。
- 本次通过 web 读取了版本化正文，但容器无法获取原始 HTML，未伪造网页 SHA。Codex 首次实施时保留原文快照/位置和哈希；快照若与本次合同冲突则暂停受影响条款并提交差异，不自动改答案。
- RANKMEAN 的全局有效 token 等权是任务选择，HF 博文是支持例子，不是约束一切分布式训练的标准。
- CE 加权 label smoothing 的 R_A 需要明确绑定；R_B 是有标签的诊断读法，不可把每次运行更接近的读法临时当真值。
- 未迁移的文档、旧 THEORY、旧 CHECK_REPORT、旧哈希清单均为历史材料，不参与自动启用。

## 4. 输入、输出与保证

1. 值输入按实际接收的精确有理值解释，字符串 `1/10` 与浮点接收的 `0.1` 不得暗中互换。
2. 输入验证先于参照执行。不能 `int(3.9)` 后当合法计数；不能通过 `zip` 丢弃多余状态或输出。
3. CE 必须返回完整 loss 与指定上游方向的 VJP。`none` 的梯度必须声明上游向量，不得把一个向量函数的“梯度”不加说明地当标量梯度。
4. ADAMW 必须读取显式前态，返回 theta/m/v/t，不能只比较最终 theta 后认证整个状态转换。
5. 必须递归检查完整结构、形状、元素个数与有限性。不允许只检查公共键或有限子集。
6. `exact` 是精确值；`rigorous_enclosure` 是有依据的包围；`allowed_set` 是多个有定义的合法答案；`declared_approximation` 是明确近似。保证随每个输出传递。
7. 数学无定义不是 `allowed_set`。缺少允许集合的语义，不能解释成“任何输出都可以作为参照”。

## 5. 结果与异常

建议结果类别：`value`、`domain_undefined`、`invalid_input`、`unsupported`、`not_established`、`implementation_error`。
- `domain_undefined`：合法参数组合下，本合同所选有限实数目标无定义，例如平均分母为零。单列，不用它证明设备必须返回 NaN 或零。
- `invalid_input`：违反合同内明确形状/类型/范围条件。
- `unsupported`：API 合法但当前 profile 未覆盖，不能报告为上游实现错误。
- `not_established`：预算或可计算证据不足。
- `implementation_error`：参照/适配器异常、结果结构失配、输入验证失灵、损坏区间。不能靠匹配异常文字转成数学结局。
以上不是 bias 的正负结论；非零检验和可接受性仍用原统计层各自的明确合同。

## 6. 样例与条款验证

- 每个 expected 必须带完整预期结果/类型，不只一个浮点数。
- 有理数保持 Fraction 或等价精确表示，不转换成 mpf 后贴 `exact` 标签。
- 精确关系或退化为同一个精确点可作精确一致证据。
- 已证明包围不相交可作矛盾见证；两个区间相交只作相容或分辨率不足，不能证明等式。
- 高精度点值复算单列 `numerical_crosscheck`。任意 `1e-50` 宽限或 `1e-30` 宽度不得隐含写入“严格成立”。
- 不要求所有例子都有符号证明，但必须区分数学依据和实现回归；不能把样例计数用于生成普遍保证。
- 负例、边界、合法替代实现与等价变异都要保留。某误读在普通对照上恰好相等不是测试失败。
- 变异检出必须连到指定输出/状态与见证；异常崩溃不是杀死语义误读的替代证据。等价、域外、无效变异与未决单列。
- 新包列出的 20 条为变异实施要求，不声称这些新增变异已经执行或全部被拒绝。

## 7. 运行与准入

只有同时满足：内容已审阅、来源/profile 固定、任务选择已绑定、输入域验证、参照实现证据绑定、完整输出可观察、无未隔离冲突，才允许对该 query 使用相应规格。
证据文件不能单独宣布条款正确；但其中可信的矛盾必须阻止受影响条款继续认证。
调用者的任务选择不能被工具默默代替。CE.R_A 和 RM.TASK 可以由显式参数在每次任务初始化时绑定，不必等待“所有用途统一批准”。
检查器发现结构错误、矛盾、适用的读法失败或必跑测试失败必须非零退出。未建立/待实施独立返回，例如代码 2；可选依赖缺失只跳过对应旁证，不算通过。

## 8. 验收范围

本轮验收对象是三份 profile 合同、适配器和测试入口。不是 31 个角色的全域认证，不是 kernel bias 预测或 GPU 校验。
执行方不得把数值模块大合并作为启动这三个试点的前置条件。先统一结果与异常接口；已有后端分别保留保证并做交叉核验。
