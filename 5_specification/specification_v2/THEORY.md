# 规格理论：来源、可见性与相对完备性（v2.4，2026-10-15）

本文回答两个问题：我们的规格（ground truth）在什么意义上比已有做法更合理；它在什么意义上「覆盖」了真实情形，在什么意义上不可能覆盖。每个结论都放在它依赖的公式之后。

## 0 四个对象

对一个输入 x：

- f_task(x)：任务要求的值，由任务的数学定义给出（例如「窗口内按 token 平均的损失」「对相位无关的检索」）。
- f_alg(x)：文档声明的算法在实数上的值（例如 PyTorch 文档里交叉熵的公式、论文里 KV 压缩的聚合公式）。
- G(x)：被审程序的声明语义——DSL 从程序代码自动提升出的实数计算，以严格包围给出。
- K(x)：程序在设备上的实际输出。

## 1 分解恒等式

**推导。**在 K − f_task 中先加减 G，再加减 f_alg：

K − f_task = (K − G) + G − f_task
　　　　　 = (K − G) + (G − f_alg) + f_alg − f_task
　　　　　 = (K − G) + (G − f_alg) + (f_alg − f_task)。

三项分别记为：

- e_num = K − G：执行相对声明的差异（舍入、近似指令、格式转换）；
- e_sem = G − f_alg：程序相对文档算法的差异（写错的分母、掩码、状态读取、常数表示）；
- e_design = f_alg − f_task：算法设计相对任务的差异（有损压缩带来的相位依赖等）。

**定理 1（无重复记账）。**给定 f_task、f_alg、G、K，这三项由上式唯一确定，相加恰好等于总差异，没有重叠也没有遗漏。执行是否合法（竞争、越界）不进入这条恒等式，由接纳判断单独给出。

**这条定理带来什么。**每一项由不同的来源计算：e_num 由 DSL 自动得到；e_sem 需要 f_alg，来自文档；e_design 需要 f_task，来自任务定义或关系。旧的两栏分解（K − G 与 G − f）是本式在 f_alg = f_task 时的特例。KV 压缩的相位敏感，在本式中落在 e_design：kernel 忠实实现了压缩公式（e_num ≈ 0，e_sem = 0），但公式本身对平移不等变。

## 2 包围的可靠性

设程序由局部规则组合而成。若每条局部规则的包围包含该步的真值，并且组合保持控制、内存与定义域的不变量，那么整个程序的包围包含 G 的真值（DSL v2 规范的命题 B；这是抽象解释的标准构造，不是新定理）。由此 K − G 的判断在 DSL 支持的范围内是可靠的：包围不含零，就一定存在执行相对声明的差异。

## 3 关系的可见性

设任务满足关系 f(Tx) = T′f(x)，其中 T 是输入变换，T′ 是输出上的线性变换。记误差 e = K − f。

**推导。**

K(Tx) − T′K(x) = [f(Tx) + e(Tx)] − T′[f(x) + e(x)]
　　　　　　　 = [f(Tx) − T′f(x)] + e(Tx) − T′e(x)
　　　　　　　 = e(Tx) − T′e(x)。

最后一步用到 f(Tx) = T′f(x)。

**定理 2（关系只看见随变换变化的误差）。**对一组变换 𝒯，关系检查看不见的误差恰为

N(𝒯) = { e : 对所有 T ∈ 𝒯 与所有 x，e(Tx) = T′e(x) }。

它是对每个 T 的约束取**交集**，不是把各条关系的盲区并起来。

**例子。**取 softmax 的三条关系：逐行平移不变、类别置换等变、和为一。对任意 β > 0，softmax(βx) 同时满足这三条（符号验证见 derive.py 的同类记录）。所以 e(x) = softmax(βx) − softmax(x) 属于 N(𝒯)：温度写错，这三条关系一条都查不出来。

**补完。**在这个例子里，盲区沿着一个参数 β 展开。取一个锚点：两类输入 x = (0, ln 2)，softmax(βx) 的第二个分量为 p(β) = 2^β/(1 + 2^β)，其导数 2^β ln 2/(1 + 2^β)² 恒为正，所以 p 是 β 的严格单调函数，一个锚点值就唯一确定 β。只有在已经证明盲区是这样一个有限参数族时，才能说「关系加锚点」补完了规格；一般的 N(𝒯) 是无限维的，没有这个结论。

## 4 多实现差分的可见性

设两条实现路径 K₁、K₂，声明语义分别为 G₁、G₂。

**推导。**

K₁ − K₂ = (K₁ − G₁) − (K₂ − G₂) + (G₁ − G₂)，
G₁ − G₂ = (G₁ − f) − (G₂ − f)。

**定理 3（共因错误不可见）。**若两条路径相对 f 的语义错误相同，(G₁ − f) = (G₂ − f) = c(x) ≠ 0，则 G₁ − G₂ = 0：差分看不见 c。推广到任意多条路径，只要参照由实现构成，盲区就是所有参照实现共有的错误。

**由此得到的对比。**以 eager、另一个库或多数表决为参照的做法，盲区包含全部共因错误；B020（include_self=False 的反向在 PyTorch 全部 eager 构建与 Inductor 上一致地错）就是一个实例。我们的 f_alg 由文档独立写出，不经由任何实现，所以它的盲区只是「文档本身的含糊」，而这些含糊在规格中登记为读法。

## 5 统计的可见性

逐元素容差检验判 |e_i| > τ。若所有 |e_i| < τ，无论样本数 n 多大，检出概率都是零。均值检验的判据是 |ē| > z·σ/√n，对任何非零均值 μ，当 n → ∞ 时检出概率趋于一。所以对系统性偏差，均值检验的可见集合严格大于容差检验；对单个元素的大误差，逐元素的 K − G 比较同样能看见（它是精确的，不依赖 τ）。

## 6 相对完备性

**定义。**声明的配置集合 𝒞 由有限个配置组成，每个配置写明（角色，来源与版本，模式，输入域，观察量）。称规格库相对 𝒞 完备，如果对每个 c ∈ 𝒞，库中给出以下两者之一：(a) 在该输入域上的 f_alg，并注明参照类型（点值、允许集合、严格包围或声明近似）；(b) 一组关系及其计算出的盲区 N(𝒯)。

**定理 4（不会静默漏掉）。**若规格库相对 𝒞 完备，且被审 kernel 绑定到某个 c ∈ 𝒞，那么它的任何差异必落入以下五类之一：可见的 e_num；可见的 e_sem；可见的 e_design；落在声明的盲区（N(𝒯) 或共因）；执行不合法。

**证明。**由定理 1，差异分解为三项；由定理 2、定理 3，每一项要么被相应来源看见，要么落在已写出的盲区；执行不合法由接纳判断单独给出。五类互斥且穷尽。

**定理 5（绝对完备不可能）。**没有任何有限的规格库能对所有任务完备。理由有二：
1. 任务意图是外部给定的。一个没有文档、没有被替换的参照、没有任务定义的算子，「正确」没有定义，任何方法都无从判断。
2. 对非线性角色，任何有限的关系集合都有非零盲区（第 3 节的 β 族就是例子），所以仅靠关系不能确定 f。

**所以「覆盖了所有真实情形」只能用经验回答。**在冻结的真实语料上统计：有多大比例的 kernel 能绑定到 𝒞 中某个带 f_alg 的配置；已知 bug 的召回；登记变异族上的检出率。这些是测出来的数，不是定理。

## 7 与已有做法的比较

比较的对象是「在同一配置上，看得见什么、看不见什么」。

| 做法 | 参照来自 | 可见 | 盲区 | 比我们强的地方 |
|---|---|---|---|---|
| eager 加容差（工业实践、KernelBench、RealisticTritonBench） | eager 实现 | 超过 τ 的单元素误差 | 低于 τ 的系统性偏差（定理 5 的统计部分）；与 eager 共有的错误（定理 3） | 简单、无需规格 |
| 多路径差分（EAGLE、DeepREL、TTrace） | 另一条实现路径 | 路径间超过容差的差异 | 共因错误（定理 3）；容差以下的系统性偏差 | API 覆盖面与规模 |
| 蜕变测试（MR-Scout、GenMorph、NOETHER） | 关系 | 随变换变化的误差 | N(𝒯)（定理 2） | 不需要 f |
| 形式等价（Tensor Algebra Equivalence Checker、SymDiff） | 另一份程序 | 声明语义是否相同 | 两份程序共同偏离意图；数值均值 | 在其片段上给出证明 |
| 舍入可解释性（RENDER） | 舍入误差界 | 差异是否超出舍入可解释范围 | 两边共有的语义错误；平均作用 | 逐实例的严格界 |
| 随机算术（noisefloat、Fuzzy PyTorch） | 扰动后的重复执行 | 方差与有效位数 | 系统性均值；任务参照 | 不需要参照 |

**定理 6（可见集合的包含关系）。**在同一配置上，我们的可见集合包含上表前五类做法的可见集合。

**证明。**逐项对照：(1) 容差：逐元素精确的 K − G 比较看见所有超过包围宽度的单元素差异，宽度远小于常用 τ；(2) 多路径差分：路径等价轴（G3）在声明层比较两条路径，且无舍入噪声；(3) 蜕变测试：关系（G2）是规格库的一部分；(4) 形式等价：G 在声明层的差分覆盖其片段上的同一命题（证明强度对直线程序以外不如对方）；(5) 舍入可解释性：e_num 的严格包围给出同一判断。此外我们看见它们都看不见的两类：与所有实现共有的语义错误（f_alg 独立于实现），以及容差以下的系统性均值。

**定理 6 不说的事。**它是「在同一配置上」的包含，不是覆盖面的比较：EAGLE 这类工作覆盖的 API 远多于我们的角色数。它也不说 f_alg 一定符合意图：文档可能错，我们只保证含糊之处被登记。

## 8 我们能对外说的话

> 我们的规格由三个生成器产生——文档给出算法规格，数学给出关系，框架的实现路径给出路径等价——每一项都带来处与证明状态。在声明的配置集合上，任何差异都被唯一地归入数值、语义、设计三项之一，或落在写明的盲区，或判为执行不合法（定理 1、4）。在同一配置上，我们看得见已有做法看得见的一切，还看得见所有实现共有的语义错误与容差以下的系统性偏差（定理 6）。绝对意义上的「覆盖所有真实情形」不可能（定理 5）；真实语料上的覆盖比例是测量值。
