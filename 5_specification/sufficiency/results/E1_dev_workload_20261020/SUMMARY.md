# E1 真实工作负载：开发模型的编译单元（2026-10-19 / 20）

方案：`docs/SUFFICIENCY_PROTOCOL.md` 第 3 节；冻结点 F = 7115198；偏差 D1（bind / merge / dynamic 从主仓库检出重跑，
worktree 的失败产物在 `E1/failed_harness_20261019/`）、D5（开发层口径）。原始数据 `.cache/sufficiency/E1/`（不入库）；
本目录 `analysis.json`、`analysis_units.jsonl`（抽样单元逐个分类）、`dynamic_units.json`（抽样清单，种子 20261019）。

计数单位：模型 × 配置（26 个开发模型 × bf16 / fp32tf32 = 52）；编译单元（一个 Inductor 生成的 Triton kernel 在一个
模型配置中的一次捕获，每个模型配置使用全新 Inductor 缓存）。所有尝试都在分母中。

严格层为 0 的唯一原因是组合合同 GRAPH 仍为 drafted。176 中有 35 个单元的参照用到合同登记之外的操作语义（`aten.pow`

抽样按单元等概率，单元多的模型配置权重大（granite fp32tf32 在样本中占 64 个）。按模型配置看，开发层完整参照在各
模型配置样本中的数目见 `analysis.json` 的 `groups.model`。

### 与旧数字的关系

`corpus/README.md` 记录的 1542 / 25 / 552 / 1（共 2120）是 2026-10-18 对历史 three_way 实例的**静态候选**结果：
1542 个来源唯一且操作受支持，25 个来源唯一但含原地写，552 个多来源，1 个无匹配。那次用的是 three_way 的共享编译缓存
和旧捕获，没有同进程来源，也没有求参照。这次 E1 是不同版本、不同过滤规则：
- 重新捕获，每个模型配置用全新缓存，因此没有多来源；
- 覆盖检查按当前合同登记；
- 并在抽样上实际求了参照。

两组数字不能直接比较或合并。

## 5 结论的写法

- 可以写：「26 个开发模型（47/52 个模型配置捕获成功）的 2221 个编译单元中，75.5% 的源码匹配到操作全有合同的图片段。
  在 400 个随机单元上，允许草案组合合同时 35–44% 得到完整参照，严格只用已准入合同时为 0。逐元素和归约单元多数只差组合
  合同准入；矩阵乘模板和 softmax 几乎没有完整参照，阻断在绑定和预算上。」
- 不能写：「真实工作负载 75% 有 ground truth」。候选覆盖只是名称层面的对应。
