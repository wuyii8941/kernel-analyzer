# PyTorch Inductor `var_mean` 与组合输入 VJP 绑定

调用边界是 PyTorch 2.10.0 的公开 `torch.var_mean`：连续有限 float32 `[16,128]` 输入，固定
`dim=1`、`correction=1`、`keepdim=False`，按公开顺序返回完整 `[16]` 方差和 `[16]` 均值；再用
两个显式 float32 `[16]` upstream 对这两个输出的加权和求完整 `[16,128]` 输入 VJP。三个输入都是
任务前态并保持不变。

任务规格使用已准入的 REDUCE `real` profile。保留的 PyTorch 2.10 文档定义了 corrected variance
并明确返回 `(variance, mean)`；保留的同版本 schema 固定这里使用的 `var_mean.correction` 公开重载。
合同用独立 `Fraction` 循环复算两个前向结果，并从包含两路 upstream 的独立标量目标核对组合梯度：
`upstream_var * 2 * (x-mean)/127 + upstream_mean/128`。ground truth 只依赖收到的 float32 输入和
这份任务定义，不使用 eager 或已编译输出。

`compiled_formula_observed_20261019.json` 确认实际编译生成一个融合 Triton reduction kernel，同时
写出16个方差、16个均值和2,048个输入梯度，输入未改变。该 kernel 的方差除数为127；组合梯度将
方差分支的 `2/127` 生成为 `0.015748031496062992`，进入 float32 运算后为
`0.015748031437397003`，与精确值相差 `-1/17045651456`；均值分支的 `1/128` 则可由 float32
精确表示为 `0.0078125`。编译结果与 eager 的最大差分别约为 `9.54e-7`、`4.47e-8` 和
`1.49e-8`；这组 eager 比较只核对调用边界。

正式报告 `.cache/spec_trial_20261019_var_mean/production_report_20261019.json` 使用8个开发输入和
16个确认输入。方差384个坐标、均值384个坐标、VJP 49,152个坐标的程序参照完整率和分辨率均为1；
没有语义缺失、绑定、特殊值、预算、前提或包围失败，完整公开输出均参与比较，重复执行逐位一致。

方差的 `Gπ-f` 平均绝对差约 `1.92e-16`，没有坐标严格排除零；均值的程序公式与精确任务公式完全
相容。设备到程序的平均绝对差分别约 `1.49e-7` 和 `1.08e-8`，现有规则未确认稳定平均作用。
组合 VJP 的49,152个 `Gπ-f` 坐标全部严格排除零，平均绝对差约 `6.99e-11`、最大约
`1.04e-9`，对齐方向 R2、R3 检出正向平均作用；这来自方差分支中不可精确表示的 `2/127`，均值
分支没有引入同类系数误差。设备到程序的梯度平均绝对差约 `7.32e-10`、最大约 `1.95e-8`，单独看
这一层时现有规则未确认稳定平均作用；完整设备到任务比较仅 R2 检出正向平均作用，Holm 校正后
`p≈0.0447`。这里报告的是相对于声明精确任务的方向和量级，不把通常容差内的实现直接称为错误。

绑定不扩展到其他 shape、dtype、维度、correction、`keepdim=True`、空归约、特殊值、非连续布局、
单独 `var` 或 `mean` 调用、旧 unbiased 重载、out 重载或任意同名 kernel。
