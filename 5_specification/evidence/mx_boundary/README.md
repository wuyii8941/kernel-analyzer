# MX 最小尺度边界：条件性设备反例

任务在运行前选为有限 E2M1、E8M0、`ocp_floor`，块长32。它不是对所有合法 OCP 转换的合规裁决。
`observed.json` 保留 RTX A6000、PyTorch2.10、Triton3.9 下六个输入的全部原始输出，
每个输入有两次不同输出初值的重放。被测 kernel 文件未修改；记录说明了 CUDA 能力查询的兼容转接。

对非零输入 x=2^e，所选尺度为 X=2^max(-127,e-2)，因为 E2M1 最大有限值6的最大二次幂是4。
因此 e=0、-124、-125、-126、-127 的元素应分别为4、4、4、2、1，均可精确表示。
零输入另显式选择 X=2^-127，不能由这个选择推导标准只允许该尺度。

前三个对照（0、1、2^-124）一致。后三个边界案例的尺度一致，但32个元素均为零，
而不是4、2、1。`source_expressions.json` 记录了内部 float32 尺度变零的源码复算。

`verify.py` 不导入参照实现、Torch 或 Triton，从保存字节按 E2M1 编码公式独立解码，
并用上述手算值核对全部尺度、元素和反量化坐标。`independent.json` 保留结果。
这是实验后的独立复核，不伪称盲验或完整输入域证明。脚本成功退出表示证据复核完成，**不表示 kernel 通过**。

复核命令：`python verify.py --out NEW.json`。GPU 复跑入口为 `run.py --out NEW.json`，
需可用的 CUDA、PyTorch 和支持所保留源码的 Triton；两者均拒绝覆盖已有记录。
这些材料没有自动改变合同审核、运行时准入或通用 kernel 绑定状态。
