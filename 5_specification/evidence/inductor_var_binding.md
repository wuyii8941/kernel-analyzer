# PyTorch Inductor corrected variance 与输入 VJP 绑定

调用边界是 PyTorch 2.10.0 的公开 `torch.var`：连续有限 float32 `[16,128]` 输入，固定
`dim=1`、`correction=1`、`keepdim=False`，返回完整 `[16]` 方差；再以显式 float32 `[16]`
upstream 求完整 `[16,128]` 输入 VJP。两个输入都是任务前态并保持不变。

任务规格使用已准入的 REDUCE `real` profile。保留的 PyTorch 2.10 文档将方差定义为平方偏差和除以
`N-correction`；保留的同版本 schema 固定这里使用的 `var.correction` 公开重载。合同用独立
`Fraction` 循环复算均值、平方偏差和完整梯度，并用独立标量目标的精确对称差分核对
`upstream * 2 * (x-mean)/(N-correction)`。ground truth 只依赖收到的 float32 输入和这份任务
定义，不使用 eager 或已编译输出。

`compiled_formula_observed_20261019.json` 确认实际编译生成一个融合 Triton reduction kernel，同时
写出16个方差和2,048个输入梯度，输入未改变。该 kernel 的前向除数是127；反向将 `2/127` 生成为
十进制常量 `0.015748031496062992`，进入 float32 运算后的值为 `0.015748031437397003`，与精确
`2/127` 相差 `-1/17045651456`。编译结果与 eager 的最大差分别约为 `4.77e-7` 和 `1.49e-8`；
这组 eager 比较只核对调用边界。

正式报告 `.cache/spec_trial_20261019_var/production_report_20261019.json` 使用8个开发输入和16个确认
输入。前向384个坐标、VJP 49,152个坐标的程序参照完整率和分辨率均为1；没有语义缺失、绑定、
特殊值、预算、前提或包围失败，完整公开输出均参与比较，重复执行逐位一致。

前向的程序公式与精确任务公式相容，没有坐标的严格区间排除零；设备到程序平均绝对差约
`1.58e-7`，最大约 `6.22e-7`，当前规则未检出稳定平均作用。VJP 的程序公式保留上述 float32
系数选择，49,152个 `Gπ-f` 坐标全部严格排除零；平均绝对差约 `7.55e-11`，最大约 `1.03e-9`，
对齐方向 R2、R3 检出正向平均作用。这里的方向是按参考值对齐后的投影方向。设备到程序的平均绝对差
约 `7.60e-10`，最大约 `1.96e-8`，当前规则未确认稳定平均作用；完整设备到任务比较也未确认，说明
较大的执行误差会遮住更小的程序公式作用。这不是 correction 用错，也不表示公开实现不满足通常数值
容差；它是在本调用和输入分布上，相对精确任务公式可分辨的微小定向差异。

绑定不扩展到其他 shape、dtype、维度、correction、`keepdim=True`、空归约、特殊值、非连续布局、
`var_mean`、标准差、旧 unbiased 重载、out 重载或任意同名 kernel。
